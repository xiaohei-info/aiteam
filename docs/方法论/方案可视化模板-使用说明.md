# 方案可视化模板 · 使用说明

> 状态：**固定模板**。以后做专题方案 / 需求设计时，一律按此模板产出可视化文档。
> 模板文件：`docs/方法论/方案可视化模板.html`
> 配套文档：`docs/v1正式版本/技术设计/专题设计/YYYY-MM-DD-专题名-需求与设计.md`

## 1. 什么时候用

- 跨模块功能、非微小改动、涉及数据结构 / API / 状态流变化的专题方案。
- 需要向用户或团队展示「问题 → 方案 → 界面 → 数据流 → 分工 → 阶段 → 决策」的完整设计。
- 简单改动（几行代码、单文件）不需要，直接写 Markdown 设计文档即可。

## 2. 产出步骤

1. **复制模板**：把 `docs/方法论/方案可视化模板.html` 复制为
   `docs/v1正式版本/技术设计/专题设计/YYYY-MM-DD-专题名-可视化.html`。
2. **同步建 Markdown**：`YYYY-MM-DD-专题名-需求与设计.md`，放同目录，写更详细的
   现状核对、代码引用、接口契约、风险与待确认项。
3. **按节填写**：删掉模板里所有 `填写指南` 注释和 `【】` 占位。
4. **自检**：跑一遍本文 §6 的检查清单。
5. **提交**：HTML 与 Markdown 一起提交；HTML 是示意与沟通稿，Markdown 是权威设计稿。

## 3. 固定目录（9 节，不要增删）

| # | 节 | 必须包含 |
|---|---|---|
| 0 | 总览 | 一句话标题 + 3 个要点卡 + 阅读提示 |
| 1 | 解决什么问题 | 「现状问题 → 本方案怎么解决 → 谁受益」表 + 红色「不能保证的事」 |
| 2 | 实现效果（UI） | 3–6 个标签页，每页一个 mock 窗口，展示关键界面 |
| 3 | 数据流 | 三端 SVG 总图 + 主流程 + 状态与处置矩阵 |
| 4 | 前端要做什么 | 按位置（web/operation、web/manager、clients/desktop、web/shared）列改动 + 阶段 + 量级 |
| 5 | 后端要做什么 | 按位置（server/shared、operation_service、manager_service、agent_service）列改动 + 阶段 + 量级 |
| 6 | 契约与数据变更 | 变更表（内容 / 影响面 / 风险）+ 高风险提示 |
| 7 | 阶段与依赖 | P0 / P1... 阶段表（内容 / 依赖 / 验收） |
| 8 | 待决策 | 已决定标签 + 待决策表（# / 事项 / 建议 / 卡住谁）+ 建议优先拍板 |

> 节内小节可按专题增删（如 3.5 群聊场景），但**编号要连续**，且第 3 节至少要有一张
> 三端总图。

## 4. 填写约定（硬性）

1. **工作量用 S / M / L 粗估**，只表示相对大小，不是排期承诺。
2. **UI 为示意图**，不是最终视觉稿；mock 窗口只表达信息结构与状态。
3. **表格里标「新」的是仓库里目前没有的东西**，便于区分存量与增量。
4. **现状 / 事实必须核对代码**，在 Markdown 里注明文件与行号；不要凭印象写。
5. **「已决定」与「待决策」分开**；每个待决策必须写清「建议」与「卡住谁」。
6. **阶段编号 P0 / P1...**，每阶段写清依赖与**可测试的验收标准**。
7. **项目红线**（写进第 3 节边界）：不向用户机器入站；会话内容不上传；平台模型状态
   单写者；Manager 租户数据经 TenantContext / RLS。
8. **对外口径一致**：第 1 节的「不能保证的事」要写实，不写「应该没问题」。

## 5. 组件库（CSS 类，直接复用）

| 类 | 用途 |
|---|---|
| `.card` `.grid2` `.grid3` | 卡片与两 / 三列 |
| `table` `th` `td` | 表格 |
| `.tag` `.tag.ok/.warn/.bad/.op/.mg/.ag/.gray` | 状态标签（op=运营、mg=企业、ag=用户） |
| `.win > .bar + .body` | mock 窗口；内部用 `.box` `.row` `.input` |
| `.btn` `.btn.pri/.dis/.danger` | 按钮 |
| `.flow > .s + .a` | 流程步骤 |
| `.callout` `.callout.red` `.callout.green` | 提示条 |
| `.sz.S/.M/.L` | 工作量 |
| `svg` | 三端架构图（三横带 + 编号框 + 实线同端 / 虚线跨端） |

新增标签页时：`button[data-p]` 与 `pane#id` 一一对应，脚本无需改动。

## 6. 发布前检查清单

- [ ] 9 个 section 与导航锚点一一对应。
- [ ] 标签页 `data-p` 与 pane `id` 数量、名称一致。
- [ ] HTML `<div>` 开合平衡（mock 窗口 `.cols` 嵌套最易漏 `</div>`）。
- [ ] 每个待决策都有「建议」与「卡住谁」。
- [ ] 每个阶段都有「验收」标准。
- [ ] 现状描述在 Markdown 里有代码位置（文件:行号）。
- [ ] 共享契约变更已标高风险，并写明发布顺序。
- [ ] 「不能保证的事」已写，且与对外口径一致。
- [ ] 浏览器打开 HTML 无报错、标签页可切换。
