### 三、状态持久化与断点续跑 ✅

#### 统一存储接口设计

```python
class StorageBackend(ABC):
    @abstractmethod
    def save_manifest(manifest_content: str, run_id: str) -> str
    
    @abstractmethod
    def load_manifest(run_id: str) -> Optional[str]
    
    @abstractmethod
    def save_state(state: dict, run_id: str)
    
    @abstractmethod
    def load_state(run_id: str) -> Optional[dict]
    
    @abstractmethod
    def append_event(event: dict, run_id: str)
    
    @abstractmethod
    def get_events(run_id: str) -> List[dict]
    
    @abstractmethod
    def list_runs() -> List[str]
```

#### 两种存储实现

| 特性 | LocalFileStorage | MulticaIssueStorage |
|------|------------------|---------------------|
| Manifest | 本地 YAML 文件 | Issue 附件 |
| State | 本地 JSON 文件 | Issue metadata |
| Events | 本地 JSONL 文件 | Issue comments |
| 跨机器续跑 | ❌ 不支持 | ✅ 支持 |
| 开发/测试 | ✅ 推荐 | - |
| 生产使用 | - | ✅ 推荐 |

#### 断点续跑流程

```bash
# 1. 新启动（自动保存状态）
python scripts/run_dag.py manifest.yaml --storage local
# 输出: 🚀 新启动 run dag-20260624-143052-a3f9

# 2. 中断（Ctrl+C）
# 状态已自动保存

# 3. 查看所有 run
python scripts/run_dag.py --list
# 输出:
#   dag-20260624-143052-a3f9
#     进度: 12/15 (80.0%)
#     失败: 0 | 耗时: 2h 34m

# 4. 续跑
python scripts/run_dag.py --resume dag-20260624-143052-a3f9
# 输出: 🔄 续跑 run dag-20260624-143052-a3f9
#        已完成: 12 个节点
#        继续监控中...

# 5. 跨机器续跑（使用 multica 存储）
# 在机器 A
python scripts/run_dag.py manifest.yaml \
    --orchestrator-issue <id> \
    --storage multica

# 在机器 B（无需 manifest 文件）
python scripts/run_dag.py --resume <run-id> \
    --orchestrator-issue <id> \
    --storage multica
```

## 技术亮点

1. **抽象层设计**：`StorageBackend` 支持多种后端，易于扩展（可以添加 S3/Redis 等）
2. **状态机模式**：`EngineState` 封装状态转换逻辑，确保状态一致性
3. **事件驱动报告**：`ProgressReporter` 基于事件自动生成报告，解耦业务逻辑
4. **可序列化状态**：完整的 `to_dict` / `from_dict` 支持，便于持久化
5. **CLI 友好**：`argparse` 提供清晰的命令行接口，易于使用
6. **规则引擎**：失败建议基于确定性规则，不需要模型推理
