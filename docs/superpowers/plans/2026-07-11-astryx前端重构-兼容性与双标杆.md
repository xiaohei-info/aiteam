# Astryx 前端重构：兼容性地基与双标杆页 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不修改后端契约、不破坏现有三端行为的前提下，完成 React 19 + Astryx 0.1.4 技术地基，并交付 Manager 审计页与 Agent 私聊工作台两个可运行、可回归、可视觉验收的标杆纵切面。

**Architecture:** 三端继续独立构建。`web/shared` 只新增 Astryx 主题对象和纯业务共享逻辑，保留现有 `page-shell` 角色过滤与路由激活算法；Manager 与 Agent 在各自端内直接组合 Astryx `Theme/AppShell/SideNav/Table/Chat*`。旧 `@aiteam/shared/ui` 与黑金 token 只在标杆和逐端迁移期间临时存在；三端验收后必须执行零遗留清理，最终主线不包含任何旧视觉源码、导出、依赖、class alias 或兼容层。

**Tech Stack:** React 19.2.7 · React DOM 19.2.7 · TypeScript 5.5 · Vite 5 · Tailwind CSS 4.3 · Astryx 0.1.4 · Stone theme 0.1.4 · StyleX 0.18.3 · Vitest 2 · Testing Library 16.3 · Playwright 1.61 · axe-core Playwright 4.12.

## Global Constraints

- Astryx packages must be pinned exactly to `0.1.4`; do not use `^0.1.4` while Astryx remains beta.
- React and React DOM must be pinned exactly to `19.2.7` across all workspace packages; one workspace may not contain React 18 and React 19 simultaneously.
- Do not change any server endpoint, API envelope, cursor semantics, role enum, auth behavior, route path, or cross-tier boundary.
- Preserve current user-visible behavior and existing test IDs unless a test is explicitly migrated to a stronger accessible role assertion.
- Keep `web/shared/src/page-shell/index.ts` and its tests. Visual shells move to each app; navigation filtering and active-route calculation remain shared.
- Temporary coexistence is allowed only during benchmark and tier migration so every cutover remains reversible. The final delivery is not complete until the old UI stack is deleted completely.
- Do not add compatibility wrappers, deprecated aliases, prop adapters, or dual-render switches that preserve the old UI API. Pages migrate to native Astryx APIs, then the old implementation is deleted.
- Do not delete `@aiteam/shared/ui` or the old design-system during the benchmark phase. After every consumer has migrated and rollback is no longer needed, delete their source, exports, generated CSS, build scripts, tests, dependencies, legacy utility classes, and obsolete active documentation.
- Manager/Operation motion is crisp and sparse. No page transition, no keyboard-triggered animation, and no repeated list stagger.
- Custom UI motion stays below 300ms, avoids `transition: all`, `ease-in`, `scale(0)`, and layout-property animation; movement must support `prefers-reduced-motion`.
- Agent content remains local. The refactor must not add telemetry or upload conversation/timeline/run content.
- Agent production artifact must continue satisfying D15 and must not contain Manager or Operation application modules.

## Scope

This plan delivers only the compatibility foundation and two benchmark vertical slices:

1. React 19 + Astryx compatibility across the workspace.
2. Shared Stone Command theme contract.
3. Manager Astryx shell + `/audit` benchmark.
4. Agent Astryx shell + `/chat` benchmark.
5. Functional, accessibility, visual, motion, build, and artifact gates.

The full three-tier rollout is deliberately split into later plans:

- Manager remaining feature pages.
- Operation shell and pages.
- Agent workspace/group/runs/terminal and remaining pages.
- Mandatory zero-legacy removal of the old shared UI/design-system.

No later rollout starts until this plan's final gate is approved.

```tsx
import { Outlet, useLocation } from "react-router-dom";
import { AppShell as AstryxAppShell } from "@astryxdesign/core/AppShell";
import {
  SideNav,
  SideNavHeading,
  SideNavItem,
  SideNavSection,
} from "@astryxdesign/core/SideNav";
import { buildShellViewModel } from "@aiteam/shared";

// existing managerShellConfig/useSession/useI18n imports stay unchanged

export function AppShell(): React.ReactNode {
  const { session } = useSession();
  const i18n = useI18n();
  const { pathname } = useLocation();
  const vm = buildShellViewModel(managerShellConfig, session, pathname);

  if (vm.requiresLogin) return <Outlet />;

  const sideNav = (
    <SideNav
      header={<SideNavHeading heading={i18n.t(vm.titleKey)} headingHref="/" />}
      collapsible={{ buttonLabel: "收起企业端导航" }}
    >
      <SideNavSection title="主导航" isHeaderHidden>
        {vm.nav.map((item) => (
          <SideNavItem
            key={item.id}
            label={i18n.t(item.labelKey)}
            href={item.path}
            isSelected={item.id === vm.activeItemId}
          />
        ))}
      </SideNavSection>
    </SideNav>
  );

  return (
    <AstryxAppShell
      variant="elevated"
      contentPadding={4}
      sideNav={sideNav}
      mobileNav={{ breakpoint: "md" }}
    >
      <Outlet />
    </AstryxAppShell>
  );
}
```

## Post-Gate Rollout Order

Only after Task 8 returns GO, write and execute separate plans in this order:

1. **Manager rollout:** shell-compatible list/form/detail batches; Audit is the reference implementation.
2. **Operation rollout:** reuse theme/navigation rules, but compose an Operation-local shell and preserve platform roles.
3. **Agent rollout:** workspace/group/runs/terminal; Chat is the reference implementation, and gesture/spring work is isolated here.
4. **Mandatory zero-legacy removal:** execute the exact deletion and verification contract in `Mandatory Final State: Zero Legacy UI`; the project is not complete while any old visual source, export, dependency, class alias, compatibility wrapper, or active guidance remains.
5. **Canonical design update:** revise `08-前端架构.md` to describe shared semantic logic + app-local Astryx composition, then freeze the new baseline.

Each later plan must be independently reviewable and must end with a working tier; no single PR may attempt the entire three-tier rewrite.
