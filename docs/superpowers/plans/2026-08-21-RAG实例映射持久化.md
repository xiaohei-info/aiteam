# RAG workspace → instance 持久化映射

## 目标

在当前静态 startup instance registry 之上，把 Manager 派生的 knowledge workspace 与 instance_id 持久化到 Manager `rag_workspace` 映射表，形成可审计、可检测漂移的生产边界。

## 约束

> 本计划的早期文字保留为历史背景。当前 Stage B 已落地：`instance_id` 是 Manager 持久化路由证据，query/intake 按该 ID 选择 endpoint；URL/key 仍只来自启动 registry，数据库不保存 URL/API key。当前以 canonical D21 与 Stage B 实现为准。

- endpoint/url/key 仍只来自 Manager 启动 registry，不从数据库或客户端读取；数据库只记录 instance_id + derived workspace。
- `rag_workspace` 是路由审计映射，不是 endpoint/secret registry；其持久化 `instance_id` 参与既有 tenant workspace 的稳定选路，不保存 URL/API key。
- Agent/frontend 不能传 workspace 或 instance_id。
- tenant/knowledge_space/workspace/instance_id 不一致时 fail-closed；不自动把 workspace 路由到另一个实例。
- 兼容 legacy 单实例配置和既有 `rag_workspace` 数据；迁移必须幂等。

## 实施

- migration 增加 `rag_workspace.instance_id`，并为 tenant/workspace/instance_id 建索引/约束；
- `PgManagerRagService.get()` 解析 registry 后原子 upsert instance_id，读取旧映射时检测 drift；
- `RagHandle` 返回已经验证的 instance_id；query/ingestion 继续使用同一 immutable binding；
- 增加跨 tenant、unknown registry、mapping drift、legacy bootstrap 和 restart tests；
- 更新 RAG runbook，明确 DB mapping 是审计投影而不是 secret/endpoint registry。

## 验收

- Manager full/RAG tests 通过；
- taiyi migration replay、`rag_workspace.instance_id` 真实写入；
- smoke search/get 通过；
- 修改数据库映射为错误 instance 后 query/ingestion fail-closed；
- Agent env/SSE/SQLite 不出现 instance URL/key。
