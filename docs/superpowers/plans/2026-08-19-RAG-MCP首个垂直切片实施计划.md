# AI Team RAG/MCP 首个垂直切片实施计划

> **历史文档（已由 2026-09-07 Stage A/B 覆盖）**：本文保留 RAG/MCP 首个切片的安全边界与只读约束；当前 Manager 为会话级多租户进程，每个 JWT/TenantContext/request 单一 tenant，每个 tenant 一个共享 LightRAG workspace，workspace 与 endpoint `instance_id` 持久化映射。以 canonical v1 总纲和 Stage B 实现为准。

## 1. 目标

在不恢复 Agent 本地企业知识索引的前提下，打通一条最小只读链路：

```text
Manager enterprise knowledge/document intake
  → Manager-owned MCP facade
  → LightRAG REST /query/data
  → Agent Pi MCP client
  → knowledge_search tool result
  → Pi final answer
```

RAG 仍然由 Manager 持有 LightRAG 和授权真相；Agent 只持有当前会话的 MCP 连接和短期 Agent JWT，不持有 LightRAG service key、workspace 参数或写工具。

## 2. 范围

### 本切片包含

1. Manager LightRAG REST client：`/query/data`、references、workspace header、超时和响应限制。
2. Manager-owned Streamable HTTP MCP facade：只暴露 `knowledge_search`，校验 Agent JWT、`X-AITeam-Employee-ID`、employee snapshot、knowledge binding。
3. Manager FastAPI 挂载 MCP endpoint 和 session-manager lifespan。
4. Agent 受控 MCP client extension：使用固定 `@modelcontextprotocol/sdk`，只连接 Manager MCP endpoint；无 ambient MCP config；只注册 `knowledge_search`。
5. Agent 移除当前 Pi Session 对企业 `SqliteKnowledgeIndex` 的工具注册；保留旧 bundle 投影代码暂不删除，避免把 ingestion cleanup 与 MCP 切片混在一起。
6. manager-enterprise/employee/citation negative tests。
7. taiyi 测试环境配置、文档 intake、LightRAG query/data、Agent Pi tool smoke。

### 本切片不包含

- Manager/LightRAG 存储从 JSON/Nano/NetworkX 迁移到 PostgreSQL/PGVector；
- 多 workspace fan-out；首期只使用 Manager 当前企业共享 workspace。
- `knowledge_get` 独立 citation API；首期 `query/data` 返回 bounded references/chunk context；
- RAG 前端完整页面；
- 旧 knowledge bundle/SQLite 表物理删除；
- RAG API key 下发到 Agent；
- LightRAG 原生写入/删除/图谱管理工具暴露给 Pi。

## 3. Manager 设计

### 3.1 LightRAG client

- 配置来自 `LIGHTRAG_URL`、`LIGHTRAG_API_KEY`、`LIGHTRAG_TIMEOUT_MS`；
- API key 只留 Manager，不进入 MCP response；
- 请求使用 Manager 派生 workspace header；
- `/query/data` 只返回 JSON；
- 限制 query、top_k、chunk_top_k、max_total_tokens 和 response bytes；
- LightRAG 失败、超时、非法 JSON 统一转为 RAG unavailable，不返回原始堆栈。

### 3.2 MCP auth/capability

MCP 请求必须携带：

```text
Authorization: Bearer <Agent JWT>
X-AITeam-Employee-ID: <employee_id>
```

Manager 根据：

```text
JWT tenant/member
+ employee_id
+ SnapshotService/employee lifecycle
+ employee knowledge binding
```

推导唯一 workspace。客户端/模型不能传 workspace、knowledge_space_id 或 LightRAG API key。

### 3.3 MCP tools

首期只暴露：

```text
knowledge_search(query, limit)
```

返回：

```json
{
  "query": "...",
  "items": [
    {
      "citation_id": "...",
      "document_id": "...",
      "knowledge_space_id": "...",
      "title": "...",
      "text": "bounded chunk text",
      "score": 0.0,
      "source": { "type": "file", "display_name": "..." }
    }
  ]
}
```

返回前由 Manager 做 citation ownership/provenance 校验和大小截断；不返回 LightRAG workspace、内部路径、service key 或跨 tenant references。

## 4. Agent 设计

- 新增受控 `RagMcpExtension`，使用 Streamable HTTP MCP client；
- MCP config 在 SessionHost 根据当前 authorization 动态生成；
- MCP endpoint 使用 `AITEAM_RAG_MCP_URL`；
- 每个 session 发送当前 Agent JWT 和 employee header；
- 禁止读取 `.mcp.json`、`~/.config/mcp`、ambient MCP servers；
- 只允许 `knowledge_search`，不注册 `mcp` proxy、document write、graph mutation 等工具；
- session dispose/abort 时关闭 MCP client；
- Manager unavailable 时返回 tool error，不降级到企业本地 SQLite 索引；
- Pi 最终回答由当前 Provider 模型完成，LightRAG 使用 `/query/data` 不二次生成最终答案。

## 5. 验证顺序

1. 本地 FastMCP mount + fake LightRAG client 单元测试；
2. Agent MCP client 与 fake MCP endpoint 测试；
3. Manager cross-tenant/member/employee/binding negative tests；
4. taiyi LightRAG `query/data` workspace/header smoke；
5. taiyi Manager MCP endpoint `tools/list` 只出现 `knowledge_search`；
6. taiyi Agent prompt 触发 knowledge_search 并验证 citation/result；
7. LightRAG key 不出现在 Agent env/Session/SSE/log；
8. Manager/LightRAG offline 和 timeout 降级；
9. 再决定是否实现 multi-space fan-out 和独立 knowledge_get。

## 6. 完成标准

- `tools/list` 仅返回 `knowledge_search`；
- 未授权 employee、跨 tenant、未绑定 knowledge space 均被拒绝；
- Agent 不可指定 workspace；
- LightRAG service key 只在 Manager；
- taiyi 文档 intake 后，Agent Pi query 可以返回真实 citation/chunk；
- 全量 Agent/Manager Python/TypeScript 测试通过；
- RAG 以外的 provider/Hindsight/sandbox 行为不回归。
