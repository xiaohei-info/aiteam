# 登录企业解析缺陷：同一账号跨已删除企业导致登录失败

## 1. 现象

企业「贝拉乔beilaqiao」的负责人用手机号登录桌面端，页面提示「后端服务异常,请稍后重试」。服务端同一时段没有任何 5xx。

## 2. 证据（测试服，2026-11-25 北京时间）

| 时间 | 请求 | 状态 | 说明 |
|---|---|---|---|
| 17:13:54 | `POST /api/auth/resolve-tenant-by-account` | 409 | `tenant_selection_required`，`request_id=req_1f53f5ea24694d70bd244bd8dc3a5774` |
| 17:13:55 | `POST /api/auth/login` | 401 | `invalid credentials` |
| 17:14:54 | `POST /api/auth/login` ×2 | 401 | 分别命中 `571c81b1` 与 `5aac7485` |
| 17:15:08 | `POST /api/auth/login` | 401 | `invalid credentials` |

- `manager.log` 16:45 之后无 5xx；`operation.log` 同期无相关错误。
- 桌面端登录页只有 `status >= 500` 才显示「后端服务异常,请稍后重试」（`clients/desktop/src/pages/Login/index.tsx:46`），说明**本地 Agent 把 Manager 的 4xx 呈现成了 5xx**，或本地请求层报错。该结论未在客户端日志中确认。

## 3. 根因

1. `auth_identity` 里同一手机号存在多条归属：一条在已删除企业，一条在 active 企业。
2. `AuthService.resolve_tenant_by_account`（`server/manager_service/auth_service.py`，约 414 行）只按 `provider + external_id` 查询，**不过滤企业状态**；命中多个 tenant 即抛 `TenantSelectionRequired`（409）。
3. 409 在协议上是「需要指定企业」的正常语义，但登录页与本地 Agent 没有按这个语义处理，最终展示成通用后端错误。

典型数据（脱敏）：

| 手机尾号 | 归属企业 |
|---|---|
| ***8911 | 贝拉乔(deleted)、贝拉乔beilaqiao(active) |
| ***1982 / ***2664 | taiyizhixing-666(deleted)、太乙(deleted)、杭州太乙(active) |
| ***4692 | feifeifei(deleted)、yufei(active) |
| ***4712 | feifeifei(deleted)、redpower(active) |

## 4. 影响面

- 受影响账号：5 个（同一手机号跨多个企业）。
- 涉及非 active 企业的身份行：13 行，分布在 `taiyi1`、`tutorial-demo-corp`、`feifeifei`、`taiyizhixing-666`、`太乙`、`yufei/yufly`、`贝拉乔`。
- 影响功能：登录、企业切换、密码重置。

## 5. 已做的临时处置

测试服已于 2026-11-25 清理 `auth_identity` 中属于非 active 企业的 13 行身份（备份 `/root/auth-identity-backup-20261125.jsonl`，权限 600）。

清理后：`auth_identity` 共 18 行，全部落在 active 企业；歧义手机号 0 个；`app_user`、`tenant_registry` 未改动；三个服务 `/healthz` 均 200。

**这是数据层面的临时处置，代码缺陷仍在，新关闭企业会再次产生同样问题。**

## 6. 修复建议

### 6.1 服务端（必须）

1. `resolve_tenant_by_account` 只解析 active 企业：查询时联 `tenant_registry` 并过滤 `status = 'active'`，非 active 记录不参与判定。
2. 命中多个 active 企业时，返回结构化的候选列表（企业标识 + 展示名），而不是只抛一个 409 让前端猜。
3. 企业关闭 / 删除流程中，同步清理或归档该企业的 `auth_identity` 行（或在解析层排除已关闭企业，两者至少做一项，建议都做）。

### 6.2 登录方式（产品口径）

4. 登录改为**企业标识 + 手机号联合检索**：界面同时提交企业标识与手机号，服务端按 `(tenant, account)` 精确解析，不再先按手机号猜企业。这能同时消除歧义和由此产生的额外探测请求。

### 6.3 错误提示（体验）

5. 桌面端与本地 Agent 补齐错误分级，不要把所有异常收敛成「后端服务异常」：
   - 409 `tenant_selection_required`：提示「该账号属于多个企业，请选择或填写企业标识」。
   - 401：区分「账号不存在」「密码错误」「账号已停用」。
   - 503：沿用现有「企业服务暂不可用」提示。
   - 其余 4xx 透传 `problem.detail`。
6. 本地 Agent 不得把 Manager 的 4xx 映射为 5xx，映射表需补测试。

### 6.4 回归用例

7. 同一手机号在「active + deleted」两个企业各有一条身份时：解析只返回 active 企业。
8. 同一手机号在两个 active 企业时：返回候选列表，前端可选择。
9. 企业删除后：该企业身份不再参与解析。
10. 登录页对 401 / 409 / 503 各有一条提示断言。
