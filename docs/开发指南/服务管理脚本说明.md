# AITeam 服务管理脚本完成总结

## 完成内容

### ✅ 创建了统一的服务管理脚本：`scripts/ctl.sh`

这个脚本提供了统一的入口来管理 AITeam 的所有服务，支持两种环境模式。

### 主要功能

1. **统一命令接口**
   ```bash
   ./scripts/ctl.sh start     # 启动服务
   ./scripts/ctl.sh stop      # 停止服务
   ./scripts/ctl.sh restart   # 重启服务
   ./scripts/ctl.sh status    # 查看状态
   ./scripts/ctl.sh logs      # 查看日志
   ```

2. **支持两种环境**
   - **Local 模式**（默认）：直接运行 Python，适合开发
   - **Docker 模式**：使用 docker-compose，适合测试

3. **灵活的服务控制**
   ```bash
   --server all|manager|operation|agent|postgres  # 控制特定服务
   --env local|docker                             # 选择环境
   --follow                                       # 实时跟踪日志
   ```

4. **统一的配置管理**
   - 所有配置集中在 `.env.dev` 文件
   - Local 和 Docker 使用相同的端口配置
   - 自动生成默认配置文件

## 核心特性

### 1. 统一的端口配置

**问题**：之前 local 模式和 docker 模式使用不同的端口
- Docker: operation(8001), manager(8002), agent(8003)
- Local: operation(8781), manager(8782), agent(8783)

**解决**：现在统一使用 `.env.dev` 中的配置
- operation: 8781
- manager: 8782  
- agent: 8783
- postgres: 5433

无论使用哪种环境，端点都是一致的！

### 2. 自动化环境管理

- ✅ 自动创建必要的目录（`.state/`, `logs/`）
- ✅ 自动管理 PID 文件
- ✅ 自动生成配置文件
- ✅ 自动检查进程状态
- ✅ 自动等待 PostgreSQL 就绪

### 3. 智能的服务依赖

- 启动服务时自动启动 PostgreSQL
- 按正确顺序启动服务（postgres → manager → operation → agent）
- 停止时按相反顺序停止

### 4. 完善的日志管理

```bash
# 查看最近 100 行日志
./scripts/ctl.sh logs --server manager

# 实时跟踪日志
./scripts/ctl.sh logs --server operation --follow

# 日志文件位置
logs/manager.log
logs/operation.log
logs/agent.log
```

./scripts/ctl.sh stop --env docker

## 与旧方式对比

### 旧方式的问题

```bash
# ❌ 需要手动设置一大堆环境变量
env DB_URL=postgresql://... ADMIN_DB_URL=postgresql://... \
    APP_RW_PASSWORD=... SERVICE_TOKEN=... \
    python server/run.py --tier=manager --port=8782 > /tmp/manager.log 2>&1 &

# ❌ 需要记住 PID
ps aux | grep "python server/run.py"

# ❌ 端口不统一
# Local: 8781/8782/8783
# Docker: 8001/8002/8003

# ❌ 日志在 /tmp 目录，容易丢失
tail -f /tmp/manager.log

# ❌ 需要手动管理 postgres
docker-compose up -d postgres

# ❌ 停止服务容易漏
pkill -f "tier=manager"
```

### 新方式的优势

```bash
# ✅ 一行命令启动所有服务
./scripts/ctl.sh start

# ✅ 自动管理 PID
./scripts/ctl.sh status

# ✅ 端口统一配置
# Local 和 Docker 都是 8781/8782/8783

# ✅ 日志统一管理
./scripts/ctl.sh logs --server manager --follow

# ✅ 自动管理 postgres
# 启动服务时自动启动 postgres

# ✅ 安全停止所有服务
./scripts/ctl.sh stop
```

## 配置说明

### `.env.dev` 配置文件

```bash
# 服务端口（local 和 docker 统一使用）
OPERATION_PORT=8781
MANAGER_PORT=8782
AGENT_PORT=8783
POSTGRES_PORT=5433

# 数据库配置
POSTGRES_USER=aiteam
POSTGRES_PASSWORD=aiteam_test
POSTGRES_DB=aiteam_v1

# 服务间认证
SERVICE_TOKEN=dev-service-token-placeholder

# 日志级别
LOG_LEVEL=INFO

# 公开文档（开发环境）
EXPOSE_PUBLIC_DOCS=1
```

**修改配置**：直接编辑 `.env.dev` 文件，然后重启服务即可生效。

## 参考资料

### 借鉴的设计

脚本设计参考了 `app/ctl.sh`（Hermes WebUI）的以下特性：

1. **环境变量管理**：从 `.env` 文件加载配置
2. **PID 文件管理**：自动创建和清理
3. **进程检查**：安全的进程存活检测
4. **日志管理**：统一的日志路径
5. **状态显示**：清晰的服务状态输出

### 扩展的功能

在 Hermes WebUI 的基础上增加了：

1. **多环境支持**：local 和 docker 两种模式
2. **多服务管理**：同时管理 4 个服务
3. **服务选择**：可以只操作特定服务
4. **依赖管理**：自动启动 PostgreSQL
5. **统一端口**：两种环境使用相同端口配置
