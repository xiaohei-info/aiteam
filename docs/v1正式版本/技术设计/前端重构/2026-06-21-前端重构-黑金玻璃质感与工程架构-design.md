# 前端重构设计：黑金玻璃质感 + 同构工程架构

> 状态：已与用户收口（2026-06-21），待评审。
> 范围：**仅前端表现层与前端工程模块**。后端框架、接口、端口、端点、`/api/*` 契约、envelope/错误模型一律不动。
> 关联：本仓 v1 概要设计 08（设计系统/壳）、`web/` 现有工作区、`.github/workflows/web-ci.yml`（既有 CI 闸门）。

---

## 1. 背景与目标

### 1.1 问题
当前 `web/` 三端（operation / manager / agent）前端有两类问题：

**视觉粗糙**
- 无 UI 组件库、无现代 CSS 框架；纯手写 BEM + 巨型 `global.css`（operation/manager 各 191 行，agent `tokens.css` 含数百行页面样式），每个按钮/输入框/卡片逐页重写。
- design token 在 `shared/design-system/tokens.ts` 是 TS 单一来源，却被**手工镜像复制**进 3 个 CSS 文件（注释自承"此处仅镜像注入"），改一处要同步三处。
- 零响应式：固定 `240px 1fr` 栅格、`360px` 登录卡、`calc(100vh)` 布局，窄屏破版。
- 无暗色质感体系、无动效体系。

**工程模块分裂**
- 三端目录结构不一致：operation/manager 用 `{api, auth, features, i18n, pages, shell, styles}`；agent 用 `{app, components, lib, features, pages, styles}`（`lib/` 装 api/auth/i18n）。
- `api/client.ts`、`auth/session.ts`、i18n、shell 配置在三端近重复（"复制三份"屎山前身）。

### 1.2 目标
1. 全新现代化视觉：**macOS 风黑金玻璃质感**，三端统一，带性能降级。
2. 前端工程模块对标后端的清晰度：**分层、单一职责、面向接口、可测试、可扩展**，统一三端骨架，消灭跨端重复。
3. 全程**零后端改动、零接口/端口/端点变更**；保留与后端契约对齐的非视觉资产与测试稳定契约。

### 1.3 非目标（不做）
- 不动后端任何代码、接口、端口、端点、契约、错误模型。
- 不引浅色主题（黑金为深色原生质感；token 架构预留可扩展，日后加不返工）。
- 不做手机端深度适配（仅保证不破版、能用）。
- 不碰架构裁决（D1–D24）、多租户隔离、事件协议/游标/状态枚举、`app/`、`./.hermes/`。
- 不引状态机库/微前端/重型抽象等无真实问题支撑的设计（守最小必要原则）。

## 2. 视觉方向：macOS 风黑金玻璃质感

对标 OpenAI（克制与排版）、Anthropic（暖与品牌人格）、Manus（Agent 双栏工作台）合成而来。

- **质感构成**：半透明毛玻璃面板（透出背景暖金氛围光）+ 交通灯式窗控（Agent 端）+ 金属渐变品牌标/主按钮（带内高光）+ 发丝级金线分隔 + 多层投影做景深。
- **配色**：暖黑底（`#0c0a07` 系）+ 单一金色（`#cda349` 系，作金属材质而非字色）；正文暖白/中性。
- **主题**：黑金深色**单主题**；token 架构预留扩展位。
- **范围**：三端统一。后台（运营/企业）大量表格表单场景，沿用同质感但以可读性/录入效率为先（密度更高、玻璃层更少）。

## 3. 设计系统（design-system 重建）

### 3.1 唯一 token 源（消灭三份镜像）
- `shared/design-system` 重建为**唯一 token 源**，直接产出：① CSS 自定义属性；② Tailwind preset。
- 三端经 Tailwind preset + 注入 CSS vars 消费；**删除各端 `global.css` 中手工镜像的 token**。
- token 覆盖：颜色 / 间距 / 圆角 / 字号 / 层级 / **玻璃材质参数**（模糊度、面板透明度、金属渐变、氛围光、景深投影）。
- 「好品味」取舍：删掉"TS→3 份 CSS 手工同步"这个边界情况，而不是再写脚本去同步它。

### 3.2 Tailwind 接入
- 倾向 **Tailwind v4**（CSS-first、`@tailwindcss/vite` 插件，配 Vite 5 / Node 22）。
- **前置小验证（§10.5）**：先用 30 分钟验证"monorepo 共享 token preset 跨三个 Vite 应用"的接法无坑；若有坑回退 **Tailwind v3 + 共享 JS preset**（成熟稳妥）。验证结论回流本文与实施计划。

## 4. 组件库与壳（shared/ui 新增）

- **Radix 原语**（无样式、带无障碍/键盘交互）+ Tailwind 套黑金皮，组件代码进 `web/shared/ui`，**完全自有可控**，无第三方视觉束缚。
- 基础原语：Button / Input / Textarea / Select / Dialog / Tabs / Toast / Tooltip / DropdownMenu / Table / Badge / Skeleton 等。
- 质感组件：`GlassPanel`（毛玻璃面板，内建 §6 降级）、金属按钮变体。
- 布局组件：`AppShell`（侧栏 + 主区）、`Workspace`（对话 + 执行时间线**双栏工作台**）。
- 组件纯渲染、状态经 props/context 注入，从构造上可测。

## 5. 前端工程架构（对标后端）

### 5.1 分层与依赖方向（单向、无环）

| 后端 | 前端对应 | 职责 |
|---|---|---|
| router | `features/*/components` + `app/routes` | 纯表现 / 路由声明，薄 |
| service | `features/*/hooks` | 应用编排逻辑（可测、不碰 DOM） |
| repository | `features/*/api.ts` ▸ `shared/api-client` | 数据访问，唯一对后端出口 |
| Pydantic schema | `shared/contracts` + 各域 `types.ts` | 类型作边界 |
| DI | 注入式 api-client / providers（context） | 可替身、可测 |
| 统一错误模型 | `shared/api-client/errors`（problem+json→UI 错误）+ ErrorBoundary | 单一错误通道 |

依赖只能 `features → shared(ui/app-kit/contracts/api-client/...)`；**禁止 feature↔feature 横向依赖**，跨域复用一律上提到 `shared`。每个 feature 经 `index.ts` 暴露公共接口，内部可改不破坏消费者。

### 5.2 统一单端骨架（三端一致）
```
web/<end>/src/
  main.tsx                          # 入口
  app/{App,providers,routes}.tsx    # 壳装配 / 全局 provider 组合 / 数据化路由
  features/<domain>/                # 垂直切片，自洽
    components/  hooks/  api.ts  types.ts  index.ts  __tests__/
  config/{nav,messages}.ts          # 仅放本端差异（导航 / 文案）
```

### 5.3 shared 扩成真正地基
```
web/shared/src/
  contracts api-client timeline-client role-state page-shell i18n   # 不动（逻辑资产）
  design-system/   # 重建：唯一 token 源 → CSS vars + Tailwind preset
  ui/              # 新增：Radix + Tailwind 自有组件库
  app-kit/         # 新增：跨端通用 providers / auth-session / query client / ErrorBoundary / Shell 装配
```
三端重复的 api/auth/i18n/shell 装配**上提到 `app-kit`**，各端只留配置差异（单写者、消灭复制）。

### 5.4 服务端状态：TanStack Query
- 引入 **TanStack Query** 统一 loading / error / 缓存 / 重试 / 失效，替代满屏手写 `useEffect + fetch` 样板与边界 if。
- 它是"用数据结构消除特殊情况"的典型；底层仍走既有 `shared/api-client`（Query 只管缓存与状态，不替代 api-client 的契约/错误解码）。

### 5.5 文件粒度纪律
- 单组件 / 单 hook 短小专注，文件过大即拆（大文件 = 职责过多）。
- 组件纯渲染、逻辑进 hooks；展示态不进持久化（守 D6：前端不消费 runtime-native event、展示态不写主状态）。

## 6. 性能与降级（硬约束，一等公民）

- **降级**：`@supports (backdrop-filter: blur())` 探测；不支持 / 低端环境 `GlassPanel` 自动退化为**实色暗面板**，不丢可用性、不破版。
- **性能预算**：
  - 限制同屏毛玻璃层数——仅侧栏 / 面板 / 浮层用 blur；**长列表项（timeline 事件、会话气泡）不用 blur**。
  - `will-change` / 合成层克制使用，避免过度提层导致内存与合成开销。
  - 路由级懒加载（`React.lazy` + Suspense）。
  - 长列表沿用现有游标分页；必要时虚拟化。
- **完成证据**：重构后做一次真实测量（低端 CPU 模拟 + 滚动帧率），纳入完成证据。

## 7. 多端适配

- 桌面优先；窄到平板（~768px）三栏自动折叠为可切换面板；手机保证不破版、能用，不做深度优化。

## 8. 迁移与验证（沿用串行机制）

### 8.1 保留的稳定契约
- 与后端契约对齐的非视觉资产：`contracts / api-client / timeline-client / role-state / page-shell / i18n / auth-session` —— 逻辑层尽量复用，不重写。
- **保留所有 `data-testid`**（`member-row / grant-row / instance-row / quota-row / rollup-row / audit-row / solution-row / template-row / secret-display / ws-conversation / ws-loop` 等）与可访问角色 —— 测试稳定契约。
- 现存仅 **3 处** class 依赖断言（`group.test` 的 `.chat-list__header`、manager/operation 登录页 `.login-page__form`）重构时改为 testid/role。

### 8.2 增量顺序（逐端，按既定闸门）
1. **shared 地基**：design-system 重建（token + Tailwind preset）+ `ui` 组件库 + `app-kit`。（先做 §3.2 Tailwind 小验证）
2. **Agent 端**（旗舰）：验证黑金质感 + 双栏工作台 + 降级 + 统一骨架。
3. **Manager 端**：迁到统一骨架 + 新组件库。
4. **Operation 端**：同上。

每步走既定闸门：**实现 → web-ci（typecheck / test / build 全绿）→ 独立盲审 → 合并到 `feature/v1.0.0`**。每端补视觉验证截图 + 测试绿作为完成证据。每个 issue 粒度足够小、可独立验证、可回滚。

### 8.3 CI
- 既有 `web-ci.yml` 闸门保持绿；Tailwind 构建纳入既有 `build` 步骤；新依赖（Radix / TanStack Query / Tailwind）入 lockfile，CI `--frozen-lockfile` 校验。

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| Tailwind v4 monorepo 共享 token 接法有坑 | 先做 30 分钟小验证；有坑回退 v3 + JS preset |
| 毛玻璃性能 / 低端卡顿 | §6 降级 + 性能预算 + 真实测量 |
| 大重构回归风险 | 保留 testid/role 契约；逐端增量 + 每步 CI/盲审；逻辑层复用不重写 |
| 视觉过度堆砌质感 | 金"少而准"；后台密度优先；性能预算约束 |
| 过度设计 | 守最小必要原则；不引无真实问题支撑的抽象 |

## 10. 完成标准

- 三端统一为同构骨架，`shared` 地基（design-system / ui / app-kit）建立，跨端重复消除。
- 三端呈现 macOS 黑金玻璃质感，带降级，桌面 + 平板适配。
- 后端 / 接口 / 端口 / 端点 / 契约零改动。
- 全部测试绿（testid/role 契约保留）、web-ci 三门全绿、每端视觉验证截图 + 性能测量在案。
