## 5. 通信架构（云侧服务间调用 + Agent 主动访问 + 端内运行事件）

**形态变更（推翻早期"内网三通道 + 业务事件总线"与"全链路单向 pull"假设）**：Operator 与 Manager 同属云侧控制面，可以通过服务身份做受控服务间调用；Agent 是用户本机数据面，只主动访问 Manager，用户机器无入站连接。通信分三层：**云侧控制面服务调用**、**Agent→Manager 主动访问**、**用户端内高频运行事件流**。

### 5.1 跨系统通信（面尽量窄）

| 链路 | 用途 | 形态 | 一致性 |
|---|---|---|---|
| **Operator → Manager**（云侧） | 创建 tenant；同步企业基础信息与负责人 bootstrap；目录发布/下架/可见范围变更通知；平台 Provider/模型/价格版本通知；配额/账单策略同步 | HTTPS / JSON + `shared/service_client` + 服务身份 | 幂等写入，最终一致 |
| **Manager → Operator**（云侧） | 拉取专家模板/方案包；拉取 tenant 可见平台 Provider/模型/价格；幂等解析 tenant Relay access；校验目录版本；上报企业级用量/审计/账单汇总 | HTTPS / JSON + `shared/service_client` + 服务身份 | 幂等写入，最终一致 |
| **Agent → Manager**（用户端主动访问） | 成员登录认证；拉取已授权专家/方案与执行快照；拉取授权能力元数据；上报脱敏计量/审计摘要 | HTTPS / JSON + `shared/service_client` | 本地优先，最终一致 |

跨端约定：
- **用户机器无入站**：Operator 与 Manager 可以云侧互调；Manager/Operator **绝不**向用户机器发起入站连接或推送。Agent 的配置变更靠主动 sync 感知（见 [04 §6 配置投影](04-数据架构与多租户隔离.md)）。
- **传输**：HTTPS/JSON；跨端走公网/企业网，必须 TLS + 服务身份签名（服务间认证即 [03 §9.1 平面③](03-认证与身份设计.md)，流程见 [03 §9.6](03-认证与身份设计.md)）。
- **超时/重试/降级**：所有调用必须设超时；只读调用可幂等重试（request-id 去重）；云侧写调用必须带 `Idempotency-Key`；Manager 短暂不可用时，Agent 已装载配置与已登录 token 在本地继续可用，仅"拉新配置/新登录/上报摘要"受影响。
- **摘要上报**：用户端只上报脱敏计量与审计摘要（见 [04 §6.5](04-数据架构与多租户隔离.md)），失败可本地缓冲后补传；**绝不上传会话内容**。

### 5.2 端内通信（主要在用户端）

| 通道 | 用途 | 形态 |
|---|---|---|
| **本地 Session 调用**（Agent Service ↔ Pi SessionHost） | 创建/打开 participant Session、prompt、mention delivery、abort | 进程内调用 |
| **Pi 事件流**（Pi SessionHost → Agent Service） | `message_update`、tool、settled、compaction 等 Pi 事件 | 进程内订阅 + 本地 SSE；entries 留 Pi Session JSONL |

> **好品味裁决**：高频 Pi `message_update`/tool progress 等事件**始终留在用户端本地**——Pi SessionHost 订阅多个 participant Session，聚合后通过本地 Agent SSE 推给浏览器；**永不跨端**。跨端只看到脱敏的计量/审计摘要，看不到逐 token 流。

### 5.2.1 统一群聊消息投递

用户前端的 `prompt` 和 coordinator Pi custom tool `mention_employee` 共用一个本地 `GroupMessageDeliveryService`：

```text
GroupMessageCommand
  conversation_id / source(human|employee)
  target_employee_ids[] / text/images
  logical_message_id / idempotency_key
```

路由规则：

- 群聊无 `@` → coordinator participant Session；
- `@` 一个 participant → 直接投递该 participant 固定 Session；
- `@` 多个 participant → 并行投递多个固定 Session；
- 非 roster、撤权、非 applied solution 或缺失 snapshot → fail-closed；
- coordinator 的 `mention_employee` 仍使用同一 delivery seam 咨询固定 peer Session，不创建临时 child Run。

所有入口都经 Agent Service 校验 tenant/member/solution roster/snapshot 和单写者；浏览器不得提交 coordinator/roster/能力策略。

### 5.3 调用约定（跨端与端内统一）

- **客户端**：提供 `shared/service_client`，统一 base-url 解析、超时、重试、trace 透传、服务身份签名与错误模型解码；各端不手写 httpx 调用。
- **超时与重试**：所有调用必须设超时；只读幂等重试（request-id 去重），写调用默认不自动重试，由调用方依据 `Idempotency-Key` 决定。
- **降级口径**：快照/授权拉取失败时，run 拒绝并回明确错误，**绝不用陈旧或缺失配置硬跑**；但已成功装载的专家/方案在 Manager 离线期内仍可本地使用。

### 5.4 跨端接口清单（不复用前端 API）

| 调用方 → 被调方 | 接口语义 | 通道 |
|---|---|---|
| Operator → Manager | 创建 tenant；同步企业基础信息；同步负责人 bootstrap；同步目录发布/下架/可见范围；同步配额/账单策略 | 云侧服务间调用 |
| Manager → Operator | 拉取人才市场/行业方案目录、专家模板详情与方案包；拉取 tenant 可见平台 Provider/模型/价格目录；解析 tenant Relay access；校验模板版本；上报企业级计量/审计汇总 | 云侧服务间调用 |
| Agent → Manager | 成员登录认证；拉取已授权专家/方案列表；拉取 EmployeeExecutionSnapshot；拉取授权知识/技能/连接器及平台 provider/model/pricing 投影；经受保护 runtime-config 取得 tenant Relay Token；上报脱敏计量/审计摘要 | 用户端主动访问 |
| Agent Service → Pi SessionHost（端内） | 打开 participant Session、prompt、mention delivery、取消 | 进程内调用 |
| Pi SessionHost → Agent Service（端内） | Pi AgentSessionEvent、participant/source metadata、usage | 本地订阅 + SSE/entries；不跨端 |

### 5.5 服务发现与配置

- Operator 与 Manager 的云侧地址由平台配置/服务发现注入；Manager 地址通过企业成员入户配置、二维码或安装配置串下发给本企业用户端；用户端默认 localhost。
- Pi 运行时配置由用户端 Agent Service 的 `SessionHost`、固定 `ModelRuntime` 和受控 ResourceLoader 装配；**不依赖旧 `app/.env`、不复用 `HERMES_WEBUI_*` 等旧 WebUI loopback 环境变量**。Provider/model credential 仍由 Manager 授权并由 Agent 在 Session 作用域最小注入。

## 6.5.2 三端交互流程清单（设计覆盖面）

> 本节原属 [04 数据架构](04-数据架构与多租户隔离.md) §6.5.2，因其本质是跨端契约面而归入本篇。下列流程是概要设计必须覆盖的三端交互面。详设可拆成接口契约，但不得新增绕过这些边界的隐式链路。

| 编号 | 场景 | 交互链路 | 数据边界 |
|---|---|---|---|
| F01 | 企业开通 | Operator 创建企业账号 → Operator 调 Manager 创建 tenant → Manager 初始化租户数据空间/默认角色/默认知识空间 | Operator 写企业账号；Manager 写 tenant 与企业管理数据 |
| F02 | 负责人 bootstrap | Operator 生成负责人初始/重置凭据 → 同步给 Manager tenant → 负责人登录 Manager 后强制重置 | Manager 成为负责人长期凭据持有端 |
| F03 | 目录发布 | Operator 创建/发布/下架专家模板、行业方案、平台技能以及平台 Provider/模型/价格固定版本 → 通知 Manager 可见范围或由 Manager 拉取目录版本 | Operator 持模板、平台技能、Provider/模型/价格真相；Manager 只缓存 tenant 可见只读投影 |
| F04 | 负责人登录企业后台 | 负责人访问 Manager → Manager 按 tenant 校验凭据 → token 带 `tenant_id`、`roles` | Manager 只能返回本 tenant 数据 |
| F05 | 部门/成员管理 | Manager 租户内 CRUD 部门、成员、角色 | 所有表走 TenantDataSession/RLS |
| F06 | 招募专家 | Manager 点击招募 → 拉 Operator 专家模板、平台模型引用及技能包 → 校验模型发布/tenant 可见 → 幂等解析 tenant Relay access → 安装技能并创建直接可运行 employee，可绑定部门/成员授权 | Provider/model/access 任一步失败则不创建待配置 draft；Manager 不改模板/模型/价格真相 |
| F07 | 应用方案 | Manager 向 Operator 拉固定版本方案包 → 预检专家/Provider/Skill → 在本 tenant 展开 employee 与 solution instance，映射 coordinator employee，由企业管理员选择 member/department grants；知识通过 tenant-scoped employee binding 管理 | 方案实例与授权归 Manager tenant；Operator 方案不携带 tenant knowledge/member/default-grant 数据 |
| F08 | 企业知识/RAG | Manager 上传/导入企业文档 → ManagerRagService 推导 LightRAG workspace → 建索引并绑定专家/方案/部门/成员 | workspace = tenant_id + knowledge_space_id |
| F09 | 用户端入户 | Agent 配置 Manager URL/企业邀请码 → Agent 访问 Manager 登录 → Manager 返回 token、公钥/验签参数、tenant 信息 | Agent 只持本会话 token 与本地投影 |
| F10 | 授权配置同步 | Agent → Manager 拉本成员可见专家/方案/能力及平台 provider/model/pricing 元数据 → Agent 原子写 `loaded_expert_projection`、`loaded_solution_projection` 和 frozen snapshots | Manager 按 tenant + member_grant 裁剪；solution projection 固定 coordinator/ordered roster/config version；目录投影无 secret |
| F11 | 执行快照 | Agent 提交 run 前向 Manager 拉 EmployeeExecutionSnapshot → 冻结 snapshot/provider/model/pricing versions；受保护 runtime-config 另取 tenant Relay Token | 快照只含只读执行配置和非敏感价格；Token no-store、最小注入；不含上游/管理 key |
| F12 | 本地执行 | Agent Service → Pi SessionHost → 固定 participant Pi Sessions；Pi Skill/custom tools/Manager RAG/Hindsight/外部 sandbox 按 snapshot 授权执行 | Conversation 正文与 Pi entries 只落 Agent 本地；群聊一个 Conversation 对应多个固定 participant Session |
| F13 | 用量回流 | Agent 按冻结 pricing version 本地汇总 token/cost/error/run count → 自动异步上报脱敏 summary 到 Manager → Manager 聚合后经服务身份上报 Operator | 失败留 outbox 后重试；不含会话文本、文件内容、工具输入输出明细 |
| F14 | 授权撤销/变更 | Manager 改 member_grant 或 employee version → Agent 下次 sync 失效本地投影；新 run 必须用新快照 | 已冻结 run 不被中途改写 |
| F15 | 模板升级/下架 | Operator 更新/下架模板 → Manager 标记租户实例可升级/不可新增 → Agent sync 感知可见性变化 | 历史实例策略由 Manager 详设决定 |
| F16 | 越权与审计 | Agent 越权拉专家/知识，Manager 返回 403 并记 enterprise_audit；Operator 只看聚合审计 | 审计带 tenant_id，不含会话内容 |
