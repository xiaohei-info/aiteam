> 上位口径：`2026-11-17-方案单人组群与群聊编排-需求与设计.md` §10（能力属于 Agent、不与专家绑定）；`2026-11-18-MCP鉴权与配置导入-需求与设计.md`（MCP 的「自己添加 + 平台目录」双来源）。

## 1. 需求

用户原话：「技能也要跟 MCP 一样，也要能自定义，也能从服务端获取。」

已确认（2026-11-18，用户选择）：

| 项 | 决定 |
|---|---|
| 导入方式 | 三种都要：① 选本机文件夹或 zip；② 粘贴 SKILL.md 内容；③ 填网址导入（如 GitHub） |
| 企业管控 | 一律允许，企业不管；不改企业端 |
| 服务端来源 | 保持现状：平台技能市场 → 企业管理员装进企业技能目录 → 成员在「添加技能」里装（签名校验） |

不变的原则：
- 自定义技能只存在成员本机，只对该成员自己的会话生效，**不上传企业端/运营端**。
- 与 MCP 一样，技能属于成员的 Agent 能力，所有员工都能用，不受专家工具清单限制（`5a4bbdaa` 已让无 `read` 的专家也能读技能）。
- 导入时不执行技能里的任何东西；员工照技能说明跑脚本，仍走现有 bash 工具 + 审批 + 沙箱。

结论：签名缓存 `SkillCache` 的前提是企业签名，自定义技能没有签名，**不能塞进 `SkillCache`**；要一个并列的本机存储，用本机清单（每个文件的 sha256）发现篡改。

## 3. 方案

### 3.1 存储

- 新 `CustomSkillStore`，根目录 `agent-data/capabilities/custom-skills/<tenant_id>/<member_id>/<name>/`，目录 0700。
  - 技能文件原样放在 `files/` 下（保留相对路径）。
  - `manifest.json`：`{ name, description, origin: {kind, label, url?}, files: [{path, size, sha256}], content_hash, imported_at }`。
  - 替换时写到临时目录，全部校验通过后整体改名替换；失败时原版本不动（与 `SkillCache.install` 的「先校验后写」一致）。
- `local_capability` 记一行：`kind=skill`、`ref=<name>`、`source=user_import`（**新**）、`version=content_hash 前 16 位`、`url`=来源说明（网址或「本机文件夹」「本机 zip」「粘贴」）、`source_ref`=网址（若有）。
- 加载：`main.ts` 的个人技能列表按 `source` 分流——`user_import` 交给 `CustomSkillStore.paths()`（逐文件比对 sha256，不符则跳过并在能力页标「文件被改动」），其余仍走签名缓存。resource loader 增加一个 `customSkills` 入参，加载规则同个人技能（失败跳过、同名企业优先）。
- 撤销：沿用 `DELETE /api/agent/capabilities/skill/<name>`，`removePersonalSkill` 同时清掉自定义目录。

### 3.2 导入校验（三种来源共用）

1. 收集文件 → 定位技能根：根目录有 `SKILL.md`；或只有一个顶层文件夹且其中有 `SKILL.md`（zip / GitHub 常见），自动下钻一层。
2. 路径安全：只允许相对路径，拒绝 `..`、绝对路径、软链接、设备文件；跳过 `.git/`、`.DS_Store`、`__MACOSX/`。
3. 规模上限（待决策 #2）：建议 ≤256 个文件、总计 ≤10 MiB、单文件 ≤5 MiB；允许二进制文件（模板、图片）。
4. 解析 `SKILL.md` frontmatter：`name`、`description` 按 Pi 规则校验；不合规时给出具体中文原因（如「name 只能用小写字母、数字和连字符」）。
5. 用 Pi 的 `loadSkillsFromDir` 实际加载一次临时目录，必须恰好得到 1 个技能，保证装上后真能用。
6. 冲突：
   - 与已装**企业技能**同名 → 拒绝（`skill_name_taken`），提示改 `name`（待决策 #5）。
   - 与已装**自定义技能**同名 → `409 skill_exists`，确认后 `replace=true` 覆盖。

### 3.3 三种来源

| 来源 | 桌面端怎么给 | Agent 怎么取 |
|---|---|---|
| 本机文件夹 | Tauri 文件选择（`directory: true`）拿到绝对路径 | Agent 与桌面同机，直接读该目录（`lstat` 逐项，不跟软链接） |
| 本机 zip | Tauri 文件选择（`.zip`）拿到绝对路径 | Agent 读文件并用 `fflate` 解压到内存（**新依赖**，待决策 #4）；解压前先看条目数与解压后总大小，防 zip 炸弹 |
| 粘贴 SKILL.md | 文本框，解析后清空（与 MCP 粘贴框一致） | 单文件技能 |
| 网址 | 输入框 | 只允许 https，≤5 次跳转且全程 https，下载 ≤10 MiB，超时 20 s。支持：① `github.com/<o>/<r>`、`…/tree/<ref>/<子目录>` → 下载 `codeload.github.com` 的 zip 取子目录；② `github.com/…/blob/…/SKILL.md` → 转 raw 取单文件；③ 以 `.md` 结尾的网址 → 单文件；④ 以 `.zip` 结尾的网址 → zip |

网络方向：Agent 主动访问公网下载，不涉及入站，也不经企业端。

### 3.4 接口（新，AGENTS §8 需确认）

`POST /api/agent/capabilities/skills/custom`（operationId `importCustomSkill`）

请求 `CustomSkillImportRequest`：

```json
{ "source": "folder" | "zip" | "text" | "url",
  "path": "/Users/…/my-skill",        // folder / zip
  "skill_md": "---\nname: …",          // text
  "url": "https://github.com/…",       // url
  "preview": true,                      // true：只校验，返回预览，不安装
  "replace": false }
```

响应 200：
- `preview=true` → `{ data: { preview: { name, description, file_count, total_bytes, files: [前 20 个路径], origin_label, existing?: {version} } } }`
- 否则 → `{ data: { capability: LocalCapability } }`

错误（problem+json）：`422 invalid_skill_package`（detail 为具体中文原因）、`409 skill_exists`（可 replace）、`409 skill_name_taken`（与企业技能同名）、`502 skill_download_failed`、`413 skill_too_large`。

`LocalCapability` 视图增加 `source: "user_import"` 取值，以及 `integrity: "ok" | "modified"`（仅自定义技能有）。

### 3.5 桌面端

- 「添加技能」弹窗改成**一次只选一种来源**：顶部一行分段选择（从企业拿 / 文件夹 / zip / 粘贴 / 网址），选中哪一项就只显示那一项的控件，不并列堆叠。
- 「从企业拿」= 现有企业技能列表，行为不变。
- 「文件夹」「zip」「粘贴」「网址」各自一屏：一个入口控件 + 「检查」按钮；检查后统一在预览卡（名称 / 说明 / 文件数 / 来源）点「安装」。切换来源不会把已填内容静默清掉（未安装前保留草稿）。
  - 先调 `preview=true`，展示名称、说明、文件数、来源；同名时显示「已装 xx 版，确认替换」。
  - 点「安装」再调一次（`preview=false`）。
- 「能力」页技能列表每项加来源标签：「企业」/「自定义」；自定义项显示来源（网址可复制）；`integrity=modified` 显示「文件被改动，需重新导入」。
- 空态文案改为：「点右上角『添加技能』，从企业开放的技能里选，或导入你自己的技能。」

### 3.6 边界

- 不向用户机器入站；技能内容不上传企业端/运营端；不改企业端/运营端；不改专家快照。
- 企业不能禁用自定义技能（用户决定）；已导入的技能在撤销前一直可用。
- 对话里员工**不能**自行发起自定义技能导入（待决策 #1）；对话里的 `capability_install` 仍只装企业目录技能。
