# 外部审批平台接入调查报告

> 调查日期：2026-11-23  
> 调查对象：钉钉 OA 审批、氚云流程、飞书原生审批  
> 调查目标：确认桌面端单端接入是否可行，确认三个平台能否通过一套内部流程接入 Agent，并明确平台差异、物料和 PoC。

## 1. 调查结论

三个平台都具备接入我们系统所需的主要业务能力，能够覆盖以下共同链路：

1. 识别或同步审批实例与当前任务。
2. 读取审批表单、当前节点和处理人。
3. 生成 AI 员工的处理建议。
4. 由用户决定直接执行或先人工审核。
5. 以当前用户在第三方平台的身份执行同意、拒绝、评论或转交。
6. 保存本地执行记录并在桌面端恢复后对账。

可以使用一套内部流程协议接入，但不能使用一套完全相同的第三方调用实现。统一协议负责任务、建议、审核、执行、状态和审计，平台适配器负责各自的认证、事件、字段、限流和写操作。

| 平台 | 任务发现 | 任务读取 | 审批写操作 | 桌面端主动接入 | 当前结论 |
|---|---|---|---|---|---|
| 钉钉 OA 审批 | Stream 事件，启动后再对账 | 审批实例详情 | 同意、拒绝、评论、转交等 | 支持 | 可行，优先使用企业内部应用和 Stream |
| 氚云 | OpenAPI 查询或氚云内自定义出站方案 | OpenAPI 和自定义接口 | 需要自定义接口封装工作项管理，或评估氚云连接器 MCP | 支持主动调用，实时事件需额外确认 | 可行，但事件发现和审批执行需要 PoC |
| 飞书原生审批 | WebSocket 长连接事件，启动后再对账 | 审批实例和任务 API | 同意、拒绝、转交、退回、加签等 | 支持，长连接适合桌面端 | 可行，优先使用企业自建应用和长连接 |

## 2. 钉钉 OA 审批

### 2.1 官方能力

钉钉官方 OA 审批方案覆盖审批表单模板、审批实例、审批任务、评论附件和状态事件。企业内部应用可以创建或更新审批模板，发起审批实例，获取实例详情，并对指定任务执行同意或拒绝。审批执行接口的核心字段包括 `processInstanceId`、`taskId`、`actionerUserId`、`result` 和 `remark`。其中 `result` 支持 `agree` 和 `refuse`，接口要求工作流实例写权限。

审批实例变更事件 `bpms_instance_change` 覆盖实例开始、结束、终止和删除。审批任务变更事件 `bpms_task_change` 覆盖任务开始、结束和转交，事件中包含实例 ID、任务 ID、流程编码、业务 ID、处理结果、处理人和事件 ID。

钉钉事件订阅支持 Stream 和 HTTP。官方把 Stream 列为推荐方式。Stream 由客户端主动建立连接，不要求用户机器提供公网回调地址，符合桌面端无入站设计。HTTP 方式要求公网地址、签名 Token 和 AES 加密配置，不适合作为桌面端首选。

钉钉应用访问凭证由应用 Client ID 和 Client Secret 获取，官方方案说明 accessToken 有效期为 2 小时。桌面端需要缓存并在到期前刷新，刷新过程应使用单实例锁，避免并发刷新。

### 2.2 桌面端适配判断

钉钉适配器可以在桌面端内完成。桌面端启动时使用企业内部应用凭据建立 Stream 连接，收到事件后先写入本地事件表，再按实例 ID读取详情。桌面端离线期间无法接收 Stream 事件，因此启动时必须执行增量对账。

审批写操作必须使用当前用户的外部钉钉身份。应用 Client Secret 只能作为连接凭据，不能代表 AI 员工拥有审批权。`actionerUserId` 必须与第三方平台实际允许操作该任务的用户身份一致。官方文档列出了无权限错误，但没有在公开文档中确认应用代用户审批的完整授权边界，需用真实测试企业完成 PoC。

### 2.3 接入物料

- 企业内部应用 Client ID 和 Client Secret。
- OA 审批相关权限，包括实例读写和任务处理所需权限。
- 需要接入的 `processCode`。
- 需要交给 AI 员工处理的节点和节点处理人。
- 当前用户的钉钉 `userId`，以及用户授权或企业内身份映射方案。
- 测试审批模板、测试审批人和可重复执行的测试实例。
- Stream 订阅配置和事件类型清单。

## 3. 氚云流程

### 3.1 官方能力

氚云 OpenAPI 统一使用 `https://www.h3yun.com/OpenApi/Invoke`，请求为 HTTPS POST、JSON、UTF-8，并在请求头提供 `EngineCode` 和 `EngineSecret`。官方文档给出的调用频率是每秒 1–2 次，请求超时时间不超过 60 秒。

公开 OpenAPI 文档覆盖业务对象的创建、批量创建、查询、批量查询、更新和删除，也能取得业务对象关联的 `WorkflowInstanceId`。有流程的表单可以通过 `IsSubmit` 进入流程或停留在发起节点。

氚云后端开发者文档提供 `WorkItemManager`。其中 `GetWorkItem`、`GetWorkItems`、`FinishWorkItem`、`ForwardWorkItem` 和 `Urge` 能够处理具体工作项。`FinishWorkItem` 包含提交人员、工作项 ID、审批结果、审批意见和操作事件类型等参数。

氚云也支持自定义接口。第三方通过 OpenAPI 调用氚云自定义接口，接口在氚云内部运行并调用 `Engine`。这是把「按当前用户校验、取得工作项、完成工作项」封装成受控业务 API 的可行路径。

氚云官方还提供氚云连接器 MCP。连接器包含业务数据读写、待办查看、待办处理、评论、转交、变更和加签等能力，但官方当前列出的支持平台是 WorkBuddy、千问办公和豆包工作。公开文档没有确认任意第三方 MCP 客户端都可以直接接入，不能把该能力直接作为已验证依赖。

### 3.2 事件和任务发现

本次查阅的氚云官方公开文档确认了 Webhook 接收外部系统发来的数据、自动化、流程通知、后端事件和第三方连接等能力，但没有确认一个面向自建桌面客户端、用于推送流程工作项的标准公网事件通道。

因此，氚云适配器第一版应采用启动对账和定时轮询。轮询频率由统一限流器控制，不超过官方给出的 1–2 次/秒调用频率。若客户需要准实时接入，需要在氚云内配置自动化或自定义接口向外部中间服务发送事件。桌面端本身不能接收公网入站回调，所以该方案需要额外的用户侧可访问回调面或改成桌面端定期拉取。

### 3.3 身份与执行边界

`EngineSecret` 是企业级系统集成密钥，不能下发给 Agent Session，也不能进入模型提示词、工具参数或日志。氚云自定义接口应接收短期任务授权或外部用户身份，并在氚云内部校验工作项的参与者、流程实例和允许动作。

如果自定义接口只能使用固定系统用户执行，审计会失去真实操作人的身份，不能满足模式 B 的目标。PoC 必须确认氚云自定义接口能否安全地以当前用户身份完成工作项，或者是否可以通过氚云已有用户授权机制完成等价操作。

### 3.4 接入物料

- 氚云应用地址、应用编码和表单 `SchemaCode`。
- `EngineCode` 和 `EngineSecret`，以及密钥轮换负责人。
- 要接入的流程实例、流程节点编码和业务字段白名单。
- 氚云管理员提供的自定义接口代码和发布权限，或氚云连接器开通状态。
- 测试用户、测试工作项和可重复执行的流程。
- 对工作项查询、完成、拒绝、转交、催办的接口返回样例。
- 氚云版本、套餐和 AI 升级包情况。

## 4. 飞书原生审批

### 4.1 官方能力

飞书原生审批以审批定义 `approval_code` 为模板，以审批实例 `instance_code` 为实例标识，以任务 `task_id` 为节点任务标识。官方 API 支持创建审批实例、获取审批实例详情、查询用户任务、同意、拒绝、转交、退回和加签。

审批实例状态事件覆盖 `PENDING`、`REJECTED`、`APPROVED`、`CANCELED`、`DELETED`、`REVERTED`、`OVERTIME_CLOSE` 和 `OVERTIME_RECOVER` 等状态。审批任务状态事件能够表达待处理、通过、拒绝、转交和当前节点其他任务结束等变化。

飞书支持两种事件接收方式。Webhook 方式要求应用有公网服务地址。长连接方式由飞书 SDK 建立 WebSocket 全双工通道，只需要本地运行环境能够访问公网，不要求公网 IP 或域名，适合桌面端。官方文档说明长连接目前仅支持企业自建应用，事件处理需要在 3 秒内完成，否则会触发重推，连接为集群模式而不是广播模式。

审批 API 支持 `tenant_access_token` 和 `user_access_token`。`tenant_access_token` 以应用身份调用，权限取决于应用数据范围。用户级审批操作必须核对任务对应的审批人身份，官方 FAQ 明确指出任务 ID 与审批人 ID 不匹配会返回无操作权限。因此模式 B 需要保存并校验当前用户的飞书身份。

官方文档给出的部分频率限制如下：创建实例 100 次/分钟，获取单个实例 1000 次/分钟和 50 次/秒，同意和拒绝任务各 100 次/分钟，转交和其他任务操作也需按照接口级限制执行。

### 4.2 桌面端适配判断

飞书长连接是三个平台中最适合桌面端实时接入的方式之一。桌面端可以使用自建应用凭据建立 WebSocket 长连接，接收审批事件并快速写入本地队列。应用最多建立的连接数、事件处理超时和集群投递语义需要在实现中作为配置与监控项处理。

飞书的应用身份和用户身份必须分开保存。应用身份用于读取审批定义、订阅审批事件和读取企业授权范围内的数据。用户身份用于执行与特定任务绑定的同意、拒绝或转交。不能因为 `tenant_access_token` 可以读取数据，就假设它可以替任意用户完成审批任务。

### 4.3 接入物料

- 企业自建应用 App ID、App Secret 和应用可用范围。
- 审批 API 权限和审批任务写权限。
- 需要接入的 `approval_code`。
- 审批节点、目标用户和用户身份授权方式。
- 审批实例、任务和事件测试样例。
- 长连接事件配置和审批定义订阅。
- 用户级操作所需的 `user_access_token` 或平台允许的等价用户授权。

## 5. 机器人与群聊协同协议调研

本专题增加「外部平台群聊机器人」作为协作入口。它与 AIFred 本地群聊承担不同职责：外部机器人负责群内触达、任务问答、状态卡片和用户确认入口；AIFred 本地群聊负责审批上下文中的多员工讨论、长内容分析和任务建议生成。外部机器人不把平台 Secret、完整审批原文或内部 Pi Session 暴露给群成员。

### 5.1 平台能力差异

| 平台 | 机器人接收 | 机器人发送 | 交互能力 | 可挖掘的协作方式 | 结论 |
|---|---|---|---|---|---|
| 钉钉企业内部应用机器人 | Stream 接收用户 `@机器人` 消息，回调主题为 `/v1.0/im/bot/messages/get`；群聊中对机器人发送语音、视频、文件存在限制 | 可发送文本、Markdown、链接、ActionCard、互动卡片，也可回复或发送群消息 | 互动卡片回传，支持 Stream，卡片回调需在超时内快速响应 | `@审批助手` 问答、任务摘要、风险播报、同意/拒绝卡片、跳转详情和群内提醒 | 适合做群内任务 Copilot。默认采用 `@` 触发，避免申请高权限读取全部群消息 |
| 飞书企业自建应用机器人 | 通过 `im.message.receive_v1` 接收消息。按权限支持用户 `@机器人`，或读取关联群聊全部用户消息；可申请接收其他机器人消息 | 应用机器人可发送、回复和更新消息 | 交互卡片、按钮、表单、回调更新；可用事件长连接或 Webhook，具体应用权限需 PoC 验证 | `@审批助手` 对话、卡片表单补充材料、用户确认、状态追问、多个机器人之间的受控协作 | 三个平台中最适合验证多轮机器人协作，但读取全部群消息和接收其他机器人消息属于高敏感权限，默认关闭 |
| 氚云群机器人 / 钉群插件 | 公开资料确认群机器人插件主要是向钉钉或企业微信群发送通知，未确认一个面向自建客户端的机器人入站对话协议 | 自动化、表单按钮发送文本/链接；钉群插件支持互动卡片、快捷入口、吊顶卡片、创建或关联群聊 | 通过群内快捷入口、互动卡片跳转氚云表单、列表和详情；氚云连接器 MCP 另提供对话式待办处理 | 任务指派通知、风险播报、群内打开表单、群内处理入口；深度对话需要氚云连接器资格或自定义接口 PoC | 适合做业务通知和卡片入口。自建桌面端不能把群机器人 Webhook 当作入站聊天通道 |

钉钉 Stream 和飞书事件长连接都由桌面端主动建立，符合用户机器无公网入站的边界。群聊消息和卡片回调进入本地事件收件箱后，必须以平台消息 ID 去重，并把耗时的 AI 分析放到异步任务，先快速确认平台回调。

飞书自定义机器人只适合发送通知，不能承担接收用户消息、读取用户身份和多轮对话。要实现群聊对话，必须使用企业自建应用机器人并申请相应消息权限。飞书若开启关联群聊全部消息或其他机器人消息权限，能够构建更深的协作编排，但数据范围、机器人循环和隐私风险显著增加。

氚云官方连接器已经把「查看待办、处理审批、评论、转交、变更和加签」组织成 MCP 业务工具，并声明按当前授权用户执行且可追溯到真实操作人。公开资料列出的支持平台为 WorkBuddy、千问办公和豆包工作，尚未确认任意第三方桌面 MCP 客户端资格。因此它是氚云深度执行的优先 PoC 方向，不能直接作为已可用的桌面协议。

### 5.2 可深挖的协作方式

| 协作方式 | 外部群聊表现 | 本地执行边界 | 适用阶段 |
|---|---|---|---|
| 任务触达 | 机器人在业务群中提醒有新的审批任务，`@` 当前处理人，附任务摘要和详情入口 | Hub 建立本地任务，不把完整原文写入群消息 | P1 |
| 群内问答 | 用户 `@审批助手` 询问「这条申请为什么建议拒绝」或「还缺什么材料」 | 机器人只读取该用户有权访问的任务快照，再交给指定员工或本地审批群聊分析 | P1 |
| 卡片审核 | 群内展示风险、建议动作、证据摘要和「同意」「拒绝」「需要复核」「查看详情」「打开 AIFred」按钮 | 卡片按钮先创建本地 Review Gate 请求。「同意」「拒绝」只有经 Hub 校验三条硬条件通过后才等价于用户确认并执行，否则降级为打开 AIFred；高风险动作不在卡片完成 | P2 |
| 结构化补充 | 用户通过卡片表单补充审批意见、缺失字段或复核理由 | 内容写入本地任务上下文，字段仍受白名单和敏感字段策略约束 | P2 |
| 本地多员工协作 | 外部群聊的一条问题进入 AIFred 本地审批群聊，由负责员工、财务员工、风控员工和协调员工讨论 | 仅固定 roster 的 Pi Session 可以接收裁剪快照；只有路由员工提交正式 `ApprovalProposal` | P1 |
| 主动风险播报 | 外部平台状态变化、即将超时、映射失败或权限失效时，机器人推送摘要 | 推送前脱敏，使用外部任务引用和跳转入口，避免把申请原文扩散到群聊 | P2 |
| 群内业务入口 | 氚云钉群快捷入口或卡片打开表单、待办列表和详情 | 通过平台原生页面或已验证的连接器处理，Hub 记录跳转和用户动作 | P2/P3 |
| 受控机器人协作 | 飞书在明确申请权限后允许接收其他机器人消息，可让审批机器人把任务转给知识机器人或风控机器人 | 必须有 `conversation_id`、`message_id`、最大 hop、去重和禁止自触发规则 | P3，需 PoC |

### 5.3 建议的统一机器人协议

在现有 Approval Protocol 之上增加一层 Bot Protocol。它只描述群聊触达和本地协作引用，不把钉钉、飞书或氚云的原始消息结构暴露给 Agent。

```ts
type ApprovalBotCapability =
  | "receive_mention"
  | "receive_group_messages"
  | "receive_bot_messages"
  | "send_text"
  | "send_card"
  | "card_callback"
  | "reply_message"
  | "update_card"
  | "open_deep_link";

interface ApprovalConversationBinding {
  provider: ApprovalProvider;
  accountId: string;
  externalConversationRef: string;
  localConversationId?: string;
  taskId?: string;
  botCapabilityVersion: string;
}

interface ApprovalBotMessage {
  messageId: string;
  conversation: ApprovalConversationBinding;
  senderExternalRef: string;
  mentionBot: boolean;
  text?: string;
  attachments?: ApprovalAttachment[];
  receivedAt: string;
}
```

统一流程为：外部机器人收到消息 → 本地去重和身份校验 → 按 `externalConversationRef + taskId` 找到任务上下文 → 把裁剪后的消息交给本地群聊或指定员工 → 生成脱敏回复或交互卡片 → 用户点击卡片后进入本地 Review Gate。平台的 `conversationId`、`messageId`、回调 token 和原始用户 ID 只留在 Adapter 及本地审计中。

外部卡片的「同意」「拒绝」只有在三个硬条件同时成立时才能当作用户确认：真实点击人等于当前外部处理人、外部状态自快照以来未变、本次授权可留痕。详见需求与设计 §3.6.1，验证项对应 P0-10。硬条件是与关系，任一条不满足就降级为「打开 AIFred 确认」。

第一版建议采用「外部机器人触达 + AIFred 本地群聊深度分析 + 外部卡片确认」的组合。外部群聊负责让用户在原有工作场所提问和收到提醒，AIFred 本地群聊负责让多个 AI 员工基于同一任务上下文讨论。审批写操作仍由用户确认和桌面 Hub 执行，不由外部群聊中的自然语言直接触发。

## 6. 能否使用一套流程接入

### 6.1 可以统一的部分

| 统一域 | 内部协议语义 |
|---|---|
| 供应商 | `dingtalk`、`h3yun`、`feishu` |
| 账号 | 本地连接账号与外部企业身份 |
| 流程 | 外部模板、应用、表单和节点的引用 |
| 任务 | 外部实例、任务、节点、处理人和截止时间 |
| 处理建议 | 动作、理由、风险、引用和建议意见 |
| 审核 | 用户接受、修改、要求重新分析或拒绝执行 |
| 执行 | 同意、拒绝、评论、转交、加签等能力集合 |
| 状态 | 本地任务状态与外部状态映射 |
| 审计 | AI 员工、当前用户、外部身份、执行结果和失败原因 |

### 6.2 不能统一的部分

| 差异 | 钉钉 | 氚云 | 飞书 |
|---|---|---|---|
| 实时来源 | Stream | 公开资料未确认标准推送，先轮询 | WebSocket 长连接或 Webhook |
| 应用凭据 | Client ID/Secret 和 accessToken | EngineCode/Secret | App ID/Secret、tenant 或 user token |
| 模板 ID | `processCode` | `SchemaCode`、流程版本、节点编码 | `approval_code` |
| 实例 ID | `instanceId` | `BizObjectId`、`WorkflowInstanceId` | `instance_code` |
| 任务 ID | `taskId` | `WorkItemId` | `task_id` |
| 用户身份 | 钉钉 `userId` | 氚云用户 ID | 飞书 `user_id` 类型和用户 token |
| 审批动作 | `agree`、`refuse` | `FinishWorkItem` 自定义封装 | approve、reject、transfer、return、add_sign |
| 限流 | 以接口返回和官方限制为准 | 1–2 次/秒 | 按接口限制，常见审批写操作 100 次/分钟 |

因此统一层必须采用「能力声明 + 最小共同子集」。UI 只显示当前平台和流程实际支持的动作，不能把所有平台的动作假设成同一组。

### 6.3 面向小白用户的接入路径

本次调查确认了技术接入能力，但不能把“技术上可接入”直接当成“用户可以自行接入”。三个平台的原生开发者接入都包含应用创建、权限申请、身份范围或流程配置，其中氚云还可能要求自定义接口代码。因此产品必须拆分两条路径。

```text
企业首次接入
我方应用安装 / 应用市场授权 / 实施方代配置
        ↓
平台权限与身份自检
        ↓
读取流程目录和节点
        ↓
普通用户扫码确认身份
        ↓
选择流程 + AI 员工
        ↓
测试任务验证 → 开始自动同步
```

普通用户路径只显示平台名称、授权、流程名称、节点名称和 AI 员工。`Client ID`、`Client Secret`、`App ID`、`App Secret`、`EngineCode`、`EngineSecret`、`processCode`、`approval_code` 和 `SchemaCode` 只能出现在企业管理员或实施方的高级配置路径。

| 平台 | 普通用户目标路径 | 企业首次接入依赖 | 当前未验证项 |
|---|---|---|---|
| 钉钉 | 扫码安装或授权 AIFred 企业应用 → 选择流程 → 确认个人身份 → 选择 AI 员工 | 我方企业应用或合作应用的安装授权 | 应用代用户执行、应用市场或合作应用授权流程 |
| 飞书 | 扫码安装或授权 AIFred 自建应用 → 选择审批定义 → 确认个人身份 → 选择 AI 员工 | 我方自建应用、审批权限和用户身份范围 | 应用安装、用户授权和审批事件范围 |
| 氚云 | 选择已验证的连接器或合作接入 → 选择流程 → 确认身份 → 开启分析 | 连接器资格、企业授权或实施方配置 | 任意第三方 MCP 客户端资格、自定义接口和真实操作人审计 |

在平台合作授权或实施配置尚未完成前，产品只能提供“已有应用凭据接入”的高级入口，不能宣称普通用户可以零配置接入。氚云在真实操作人审计通过前，只开放任务提醒、AI 分析、打开平台处理和结果对账。

## 7. 平台排序建议

1. **飞书自建应用长连接**。事件链路和任务 API 都较完整，用户级任务权限说明清晰，适合验证统一协议。
2. **钉钉企业内部应用 Stream**。能力完整，适合第二个适配器，重点验证 `actionerUserId` 与当前用户授权。
3. **氚云 OpenAPI + 自定义接口**。业务能力可覆盖，但需要客户配置自定义接口，任务事件和身份代理的标准化程度最低，应在协议确定后接入。

## 8. 调查遗留与必须 PoC 验证项

| 编号 | 验证项 | 平台 | 通过标准 |
|---|---|---|---|
| P0-1 | 应用是否可以以当前用户身份执行任务 | 钉钉 | 只允许目标用户的 `taskId`，其他用户返回无权限 |
| P0-2 | 用户授权 token 能否在桌面端安全刷新和撤销 | 钉钉、飞书 | 重启后可恢复，撤销后写操作立即失败 |
| P0-3 | 氚云自定义接口能否保留真实操作人 | 氚云 | 审计记录显示当前用户，不能由固定系统用户代办 |
| P0-4 | 氚云是否有可用的实时出站方案 | 氚云 | 无公网入站的桌面端仍能在可接受时延内发现任务 |
| P0-5 | 飞书长连接的重复、重连和多客户端投递语义 | 飞书 | 事件去重、断线补偿和同一账号单活策略通过测试 |
| P0-6 | 三个平台附件读取和审批意见附件限制 | 全部 | 任务详情中显示允许的附件，执行前不泄露无权文件 |
| P0-7 | 外部平台审批模板变更处理 | 全部 | 字段和节点版本不匹配时阻止执行并提示重新绑定 |
| P0-8 | 普通用户授权路径是否无需技术参数 | 全部 | 用户只扫码或 OAuth 登录即可完成身份绑定，界面不出现 Client ID、Secret、EngineCode 和流程编码 |
| P0-9 | 系统休眠唤醒后的长连接与事件补偿 | 钉钉、飞书 | 唤醒后能重连并在可接受时延内补齐休眠期间的任务，不出现静默漏单 |
| P0-10 | 外部卡片回调能否满足卡片确认的三个硬条件 | 钉钉、飞书 | 回调能取到可验证的真实点击人外部身份（不采信客户端自带 ID）；点击人与任务当前处理人不一致时被拒绝并留痕；点击后复查能识别外部状态已变并降级为打开 AIFred；执行后外部审计显示该点击人为真实操作人 |

## 9. 最终判断

桌面端单端接入三个平台可行。统一开发的边界是本地审批协议、任务存储、路由、审核策略、Agent 工具和 UI。钉钉、氚云和飞书各自保留独立的 Provider Adapter。第一版不应把 Manager 放入任务接收、凭据消费、外部 API 调用或审批执行路径。

这一方案会偏离当前 v1 对连接器管理面由 Manager 持有、Agent 只拉取授权配置的现行裁决，需要在正式实现前更新共享设计裁决。用户已确认桌面端单端、无云侧执行器、模式 B、多流程多员工和中间统一协议，凭据落点与用户身份授权的具体契约仍需通过 P0 PoC 收口。
