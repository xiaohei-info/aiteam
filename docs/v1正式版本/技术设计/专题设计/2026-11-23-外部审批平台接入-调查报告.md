# 外部审批平台接入：调查报告

> 调查日期：2026-11-23（开放平台接口）、2026-11-28（官方 CLI / MCP，本版主体）
> 调查对象：钉钉、飞书、氚云、企业微信
> 调查目标（owner 2026-11-28）：把其他平台的 OA 流程、审批流接到我们的应用里，由我们的员工处理或提出建议，提高工作效率。判断标准：接入简单、系统稳定、改动小、安全、用户用着舒服。
>
> 2026-11-28 改写：第 1–7 节为本轮基于官方 CLI / MCP 的调查，是[需求与设计](./2026-11-23-外部审批平台接入-需求与设计.md)的依据。原 2026-11-23 开放平台接口调查（企业应用密钥 + 事件订阅路线）结论已被替代，原文移到附录 A 保留来源；原第 5–9 节（机器人群聊协同协议、统一插件流程、排序与 PoC）随原方案作废，见 git 历史。
>
> 本报告全部来自公开文档、仓库源码和技能说明，**没有在真实企业账号上跑过**；标「P0 实测」的结论需按需求与设计 §14 验证。

## 1. 结论

| 平台 | 能不能接 | 用什么接 | 身份 | 首版 |
|---|---|---|---|---|
| 飞书 | **能**，数据最全 | 官方 `lark-cli`（larksuite/cli，MIT，v1.0.100） | 本人 `user_access_token`（`--as user`） | P0 |
| 钉钉 | **能** | 官方 `dws`（DingTalk-Real-AI/dingtalk-workspace-cli，Apache-2.0，v1.0.69） | 本人 OAuth | P0 |
| 氚云 | **现在不能** | 官方「氚云连接器」MCP 只对 WorkBuddy、千问办公、豆包工作开放；OpenAPI 只有企业级密钥 | — | 待厂商确认第三方接入 |
| 企业微信 | **不能处理** | `wecom-cli` 无审批能力；服务端 API 只有企业级密钥、没有代人审批接口、回调需公网入站 | — | 不接入 |

共同链路：**平台是真相 → 本机拉「我的待办」与详情 → 员工给建议 → 用户确认 → 执行前复查 → 本人身份写回**。两个可接平台都能装进同一个薄适配器接口（`listPending` / `getDetail` / `getAttachment` / `act` / `recheck`）。

选 CLI 而不是开放平台接口的原因：

- **本人身份**：CLI 用用户本人授权，平台审计记在本人名下；开放平台接口路线需要企业应用密钥，密钥不能下发到用户电脑。
- **接入简单**：钉钉管理员只需开启「CLI 访问管理」，用户扫码；飞书管理员在企业端填一次应用密钥，用户扫码。
- **改动小**：不需要常驻事件连接、不需要公网回调，轮询即可。
- **官方维护**：字段和接口变化由厂商在 CLI 里跟进；我们锁定版本并用录制输出做契约测试。

## 2. 飞书 `lark-cli`

来源：github.com/larksuite/cli（commit c5fbf1a，2026-11-18）、技能 `lark-approval` v1.2.0、开放平台文档《自研 Agent 接入飞书 CLI》（open.larkoffice.com/document/mcp_open_tools/feishu-cli/embed-feishu-cli-in-agent）。

| 需要 | 命令 / 能力 |
|---|---|
| 我的待办 | `approval tasks query`（`topic` 1 待办 / 2 已办 / 17 未读 / 18 已读）→ `instance_code` + `task_id` |
| 详情 | `approval instances get`：`definition_name`、`form`、`current_nodes[]`（`node_id`、`node_name`、类型 AND / OR / SEQUENTIAL、`approvers[].task_id` / `user_id`）、`tasks[]`、`operation_records[]`、`comments`；参数 `user_id_type`（`user_id` / `union_id` / `open_id`）、`locale` |
| 同意 / 拒绝 | `approval tasks approve` / `reject` |
| 退回发起人 | `approval tasks rollback`（`node_ids` 取 `START`） |
| 其他（首版不做） | `transfer`、`add_sign`、`remind`、`instances cancel` / `cc` |
| 复查 | 再调 `instances get`；写操作返回 `1395001` = 任务状态已变或已处理，官方建议最多重试 1 次、查询 1 次 |
| 附件 | 表单附件控件 `attachmentV2`，取法 P0 实测 |
| 事件（首版不用） | `event consume approval.task.status_changed_v4` 等，常驻进程、退出不取消订阅 |

认证与安全：

- 需要企业自建应用（App ID / App Secret）。用户授权走设备码：`auth login --no-wait --json`。应用未开启「刷新 user_access_token」时，token 约 2 小时且不能刷新。
- CLI 默认把凭据存在系统钥匙串；嵌入文档提供 Credential 扩展点和环境变量传入 `user_access_token` 的方式（变量名以锁定版本为准）。
- 写操作属于高风险写，需要 `--yes`；`--dry-run` 可预览。嵌入文档还提供 Restrict（允许 / 拒绝命令、最高风险级别）、Observer、Wrap 扩展点。
- `open_id` 按应用区分，跨应用不一致 → 我们固定 `user_id_type=user_id`。
- 不覆盖三方审批定义。

我们的用法：App Secret 只放 Manager，由 Manager 代换票、不保存用户 token；本机加密保存 token，经子进程环境变量传给 lark-cli。

## 3. 钉钉 `dws`

来源：github.com/DingTalk-Real-AI/dingtalk-workspace-cli（v1.0.69，2026-11-19）。

| 需要 | 命令 |
|---|---|
| 我的待办 | `oa approval list-pending`（`--page`、`--limit` ≤ 100、`--query`、`--process-code`、`--create-time-from/to`） |
| 详情 | `oa approval detail --instance-id`；`tasks --instance-id` 取我的 `taskId`；`records` 取操作历史 |
| 同意 / 拒绝 | `approve` / `reject --instance-id --task-id --remark` |
| 退回发起人 | `revert-activities` 取可退回节点，再 `revert-task --target-activity-id sid-startevent --action REVERT_FOR_RESUBMIT` |
| 其他（首版不做） | `redirect-task`（转交）、`append-task`（加签）、`oa-comments`、`oa-cc-noticer` |
| 附件 | `attachment download-url --instance-id --file-id`（临时 OSS 链接） |
| 流程表单 | `list-forms`（可能返回 `totalCount -1`）/ `search-forms` / `form-schema --process-code` |
| 事件（首版不用） | `dws event consume`，需常驻进程 |

认证与安全：

- `dws auth login` 本人 OAuth 扫码，`--device` 支持无界面；管理员需在开发者后台开启「CLI 访问管理」，未开启时 dws 自带给管理员发申请卡片的流程。
- 调用可被企业管理员追溯。
- 不需要我们保管任何钉钉企业密钥。
- dws 自带面向 Agent 的技能；**不能**把这些技能装进员工会话，否则模型可以绕过复查和用户确认直接写回。我们只由审批模块用固定参数调用。

P0 实测：非交互取二维码、成员独立配置目录、节点名与处理人姓名、错误码、意见长度、限流。

## 4. 氚云

- **氚云连接器 MCP**（help.h3yun.com/291723488/）：18 个工具，用户身份，审计记在操作人名下；待办查看、处理（审批、完善字段、意见、批量）、流转（评论、转交、变更审批人、加签）；**不支持退回**；组织人员只读。但官方列出的支持平台只有 WorkBuddy、千问办公、豆包工作；需要「AI 升级包」，每 100 次调用扣 1 AI 点数；未提到事件。
- **OpenAPI**：`EngineCode` / `EngineSecret` 企业共享密钥，只能做表单增删改查，限流每秒 1–2 次 → 密钥不能下发到用户电脑，也不是本人身份，不可用。
- 社区方案（手机号 + 密码登录、只读）→ 不可用。

结论：等厂商确认第三方 MCP 客户端可以接入后再评估；首版不做。

## 5. 企业微信

- `wecom-cli` v1.3.4 共 15 个技能，**没有审批**（已检索源码确认）。
- 服务端审批 API 使用企业级密钥，只能读审批数据和发起申请，没有代人同意 / 拒绝的接口；审批回调需要公网入站，违反「用户机器无入站」。

结论：不能处理审批，不接入。

## 6. 两个可接平台的差异与对策

| 差异 | 飞书 | 钉钉 | 对策 |
|---|---|---|---|
| 企业侧准备 | 自建应用 + 开启刷新 token | 开启「CLI 访问管理」 | 连接对话框分别提示；飞书走企业端配置表单 |
| 凭据位置 | 我们保管（加密文件） | dws 自管（成员独立目录） | 适配器各自处理，上层不感知 |
| 数据完整度 | 节点、处理人直接返回 | 节点名、处理人姓名待实测 | 统一快照缺字段时界面不显示 |
| 退回 | `rollback START` | `revert-task sid-startevent` | P0 测不通则该平台只保留同意、拒绝 |
| 状态已变 | `1395001` | 错误码待实测 | 统一为 `task_changed` |
| 用户 id | 固定 `user_id` | userId | 只在本机使用 |

> 本附录是原方案「企业应用密钥 + 事件订阅」路线的调查原文，只保留平台能力与来源，其中的接入判断不再作为设计口径。

### A.2. 钉钉 OA 审批

#### A.2.1 官方能力

钉钉官方 OA 审批方案覆盖审批表单模板、审批实例、审批任务、评论附件和状态事件。企业内部应用可以创建或更新审批模板，发起审批实例，获取实例详情，并对指定任务执行同意或拒绝。审批执行接口的核心字段包括 `processInstanceId`、`taskId`、`actionerUserId`、`result` 和 `remark`。其中 `result` 支持 `agree` 和 `refuse`，接口要求工作流实例写权限。

审批实例变更事件 `bpms_instance_change` 覆盖实例开始、结束、终止和删除。审批任务变更事件 `bpms_task_change` 覆盖任务开始、结束和转交，事件中包含实例 ID、任务 ID、流程编码、业务 ID、处理结果、处理人和事件 ID。

钉钉事件订阅支持 Stream 和 HTTP。官方把 Stream 列为推荐方式。Stream 由客户端主动建立连接，不要求用户机器提供公网回调地址，符合桌面端无入站设计。HTTP 方式要求公网地址、签名 Token 和 AES 加密配置，不适合作为桌面端首选。

钉钉应用访问凭证由应用 Client ID 和 Client Secret 获取，官方方案说明 accessToken 有效期为 2 小时。桌面端需要缓存并在到期前刷新，刷新过程应使用单实例锁，避免并发刷新。

- [同意或拒绝审批任务](https://open.dingtalk.com/document/development/approve-or-reject-the-approval-task.md)
- [审批任务开始、结束、转交](https://open.dingtalk.com/document/development/event-bpms-task-change.md)

#### A.2.2 桌面端适配判断

钉钉适配器可以在桌面端内完成。桌面端启动时使用企业内部应用凭据建立 Stream 连接，收到事件后先写入本地事件表，再按实例 ID读取详情。桌面端离线期间无法接收 Stream 事件，因此启动时必须执行增量对账。

审批写操作必须使用当前用户的外部钉钉身份。应用 Client Secret 只能作为连接凭据，不能代表 AI 员工拥有审批权。`actionerUserId` 必须与第三方平台实际允许操作该任务的用户身份一致。官方文档列出了无权限错误，但没有在公开文档中确认应用代用户审批的完整授权边界，需用真实测试企业完成 PoC。

#### A.2.3 接入物料

- 企业内部应用 Client ID 和 Client Secret。
- OA 审批相关权限，包括实例读写和任务处理所需权限。
- 需要接入的 `processCode`。
- 需要交给 AI 员工处理的节点和节点处理人。
- 当前用户的钉钉 `userId`，以及用户授权或企业内身份映射方案。
- 测试审批模板、测试审批人和可重复执行的测试实例。
- Stream 订阅配置和事件类型清单。

### A.3. 氚云流程

#### A.3.1 官方能力

氚云 OpenAPI 统一使用 `https://www.h3yun.com/OpenApi/Invoke`，请求为 HTTPS POST、JSON、UTF-8，并在请求头提供 `EngineCode` 和 `EngineSecret`。官方文档给出的调用频率是每秒 1–2 次，请求超时时间不超过 60 秒。

公开 OpenAPI 文档覆盖业务对象的创建、批量创建、查询、批量查询、更新和删除，也能取得业务对象关联的 `WorkflowInstanceId`。有流程的表单可以通过 `IsSubmit` 进入流程或停留在发起节点。

氚云后端开发者文档提供 `WorkItemManager`。其中 `GetWorkItem`、`GetWorkItems`、`FinishWorkItem`、`ForwardWorkItem` 和 `Urge` 能够处理具体工作项。`FinishWorkItem` 包含提交人员、工作项 ID、审批结果、审批意见和操作事件类型等参数。

氚云也支持自定义接口。第三方通过 OpenAPI 调用氚云自定义接口，接口在氚云内部运行并调用 `Engine`。这是把「按当前用户校验、取得工作项、完成工作项」封装成受控业务 API 的可行路径。

氚云官方还提供氚云连接器 MCP。连接器包含业务数据读写、待办查看、待办处理、评论、转交、变更和加签等能力，但官方当前列出的支持平台是 WorkBuddy、千问办公和豆包工作。公开文档没有确认任意第三方 MCP 客户端都可以直接接入，不能把该能力直接作为已验证依赖。

#### A.3.2 事件和任务发现

本次查阅的氚云官方公开文档确认了 Webhook 接收外部系统发来的数据、自动化、流程通知、后端事件和第三方连接等能力，但没有确认一个面向自建桌面客户端、用于推送流程工作项的标准公网事件通道。

因此，氚云适配器第一版应采用启动对账和定时轮询。轮询频率由统一限流器控制，不超过官方给出的 1–2 次/秒调用频率。若客户需要准实时接入，需要在氚云内配置自动化或自定义接口向外部中间服务发送事件。桌面端本身不能接收公网入站回调，所以该方案需要额外的用户侧可访问回调面或改成桌面端定期拉取。

#### A.3.3 身份与执行边界

`EngineSecret` 是企业级系统集成密钥，不能下发给 Agent Session，也不能进入模型提示词、工具参数或日志。氚云自定义接口应接收短期任务授权或外部用户身份，并在氚云内部校验工作项的参与者、流程实例和允许动作。

如果自定义接口只能使用固定系统用户执行，审计会失去真实操作人的身份，不能满足模式 B 的目标。PoC 必须确认氚云自定义接口能否安全地以当前用户身份完成工作项，或者是否可以通过氚云已有用户授权机制完成等价操作。

#### A.3.4 接入物料

- 氚云应用地址、应用编码和表单 `SchemaCode`。
- `EngineCode` 和 `EngineSecret`，以及密钥轮换负责人。
- 要接入的流程实例、流程节点编码和业务字段白名单。
- 氚云管理员提供的自定义接口代码和发布权限，或氚云连接器开通状态。

- 对工作项查询、完成、拒绝、转交、催办的接口返回样例。
- 氚云版本、套餐和 AI 升级包情况。

### A.4. 飞书原生审批

#### A.4.1 官方能力

飞书原生审批以审批定义 `approval_code` 为模板，以审批实例 `instance_code` 为实例标识，以任务 `task_id` 为节点任务标识。官方 API 支持创建审批实例、获取审批实例详情、查询用户任务、同意、拒绝、转交、退回和加签。

审批实例状态事件覆盖 `PENDING`、`REJECTED`、`APPROVED`、`CANCELED`、`DELETED`、`REVERTED`、`OVERTIME_CLOSE` 和 `OVERTIME_RECOVER` 等状态。审批任务状态事件能够表达待处理、通过、拒绝、转交和当前节点其他任务结束等变化。

飞书支持两种事件接收方式。Webhook 方式要求应用有公网服务地址。长连接方式由飞书 SDK 建立 WebSocket 全双工通道，只需要本地运行环境能够访问公网，不要求公网 IP 或域名，适合桌面端。官方文档说明长连接目前仅支持企业自建应用，事件处理需要在 3 秒内完成，否则会触发重推，连接为集群模式而不是广播模式。

审批 API 支持 `tenant_access_token` 和 `user_access_token`。`tenant_access_token` 以应用身份调用，权限取决于应用数据范围。用户级审批操作必须核对任务对应的审批人身份，官方 FAQ 明确指出任务 ID 与审批人 ID 不匹配会返回无操作权限。因此模式 B 需要保存并校验当前用户的飞书身份。

官方文档给出的部分频率限制如下：创建实例 100 次/分钟，获取单个实例 1000 次/分钟和 50 次/秒，同意和拒绝任务各 100 次/分钟，转交和其他任务操作也需按照接口级限制执行。

#### A.4.2 桌面端适配判断

飞书长连接是三个平台中最适合桌面端实时接入的方式之一。桌面端可以使用自建应用凭据建立 WebSocket 长连接，接收审批事件并快速写入本地队列。应用最多建立的连接数、事件处理超时和集群投递语义需要在实现中作为配置与监控项处理。

飞书的应用身份和用户身份必须分开保存。应用身份用于读取审批定义、订阅审批事件和读取企业授权范围内的数据。用户身份用于执行与特定任务绑定的同意、拒绝或转交。不能因为 `tenant_access_token` 可以读取数据，就假设它可以替任意用户完成审批任务。

#### A.4.3 接入物料

- 企业自建应用 App ID、App Secret 和应用可用范围。
- 审批 API 权限和审批任务写权限。
- 需要接入的 `approval_code`。
- 审批节点、目标用户和用户身份授权方式。
- 审批实例、任务和事件测试样例。
- 长连接事件配置和审批定义订阅。
- 用户级操作所需的 `user_access_token` 或平台允许的等价用户授权。
