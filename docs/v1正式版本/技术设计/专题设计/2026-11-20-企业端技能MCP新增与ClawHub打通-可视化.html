1 解决什么问题

现在的问题本方案怎么解决谁受益
签名技能包只收 SKILL.md + references/*.md，热门 ClawHub 技能（根目录 csv.md、assets/、scripts/）全被拒共享契约放宽为任意安全路径的 UTF-8 文本；Python 与 Node 同一规则、同一组用例互验；旧包哈希不变运营、企业管理员、成员
运营端 verify 不过（可疑 / 扫描中）一律拦截verify 只做完整性校验；安全结论在预览里双扫描器并列显示，不拦运营
ClawHub 不通时内部市场一起空白；只见前 20 条；每次按键都请求内外分开加载、外部可重试；400 ms 防抖；「加载更多」运营
下载前看不到文件与风险；失败只显示「下载失败」新增预览接口与抽屉；429 / 404 等原因如实透出运营
企业端技能只能手填 JSON 文件数组「导入技能」对话框：文件夹 / zip / 单个 md / 粘贴 / 网址 / ClawHub，先检查再安装（同桌面端）企业管理员
企业端 MCP 只能启用平台条目企业自建 MCP：粘贴配置或地址 → 检查鉴权与工具 → 保存；成员像平台条目一样自装企业管理员、成员
成员桌面「添加 MCP」只能粘贴配置，看不到企业已开放的 MCP「添加 MCP」增加「从企业拿」列表（平台启用 + 企业自建），一键安装；需要登录 / 令牌的接着登录或当场填写成员
不知道该装什么「让模型帮我找」：Manager 用本企业平台模型跑有界工具循环，返回候选；用量计入企业 owner企业管理员
不能保证的事（需要对外口径一致）：ClawHub 是第三方未签名内容，显示扫描结论不等于安全；图片等二进制资源不分发，依赖它们的技能可能不完整；技能附带的脚本只是文本，能否在成员机器上运行取决于本机环境；模型帮装给的是建议，可能不相关，且受 ClawHub / GitHub 可用性与限速影响；未升级客户端的成员装不了新格式技能；「一键使用」只对无需登录的 MCP 是一次点击，需要登录的还要在浏览器完成登录，需要令牌的要先填令牌。

3 数据流

边界：不向用户机器入站；会话内容不上传；平台模型 / 价格仍由 Operator 单写；Manager 租户数据全部经 TenantContext / RLS；Manager 新增的外呼（ClawHub / GitHub / 网址 / MCP 探测 / 本企业 Relay）只在管理员操作时发生，且走 SSRF 防护。

3.1 总图：谁在哪一端做什么

实线 = 同端流程；虚线 = 跨端调用。方向只有：Manager 主动拉 Operator、Agent 主动访问 Manager、Agent 本机内部；没有入站到用户机器。Manager 对外网与 Relay 的调用只在管理员发起时发生。
