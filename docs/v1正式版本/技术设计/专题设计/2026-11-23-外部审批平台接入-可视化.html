桌面端统一接入钉钉、氚云和飞书审批 2026-11-23 · 设计草案，未写代码

外部平台各自保留适配器，桌面端用统一审批协议把任务交给本地 AI 员工和本地审批群聊，经用户确认（或命中本人开启的有条件自动放行规则）后，以自己的第三方身份完成最终处理；申请人可在提交前对材料做预检。

一套内部协议

统一任务、建议、审核、执行、状态和审计，平台差异收敛在 Adapter。

桌面端单端

凭据、事件接收、轮询、任务路由和外部写操作都在桌面端完成。

默认用户确认

AI 员工只形成建议；默认由用户确认后提交，本人开启且命中有条件自动放行规则时例外。

1 解决什么问题

现在的问题本方案怎么解决谁受益
三个平台的 ID、认证、事件和动作不同统一 Approval Protocol，差异由平台 Adapter 负责用户和后续平台接入
AI 员工不能直接承担不可逆审批责任AI 员工输出建议和风险，Review Gate 要求用户确认，或按本人开启的有条件自动放行规则裁决审批人和企业审计
桌面端离线或重复点击会造成漏单和重复执行事件去重、启动对账、外部状态复查和幂等流程负责人
一个用户有多个流程，需要交给不同员工用平台账号、流程、节点和处理人映射到流程绑定多员工用户
用户想在原有办公群里直接询问审批外部机器人接收 `@` 消息，回到本地审批群聊深度分析，再回复脱敏摘要或卡片用户和流程负责人
不能保证的事：三个平台不具备相同的实时事件和用户授权能力。氚云任务事件、真实操作人审计和各平台用户级写权限必须通过 PoC 验证。
小白用户口径：技术接入可行不等于普通用户可以自行接入。目标路径是企业首次授权后，普通用户只扫码确认身份、选择流程和选择 AI 员工。企业自建应用创建、权限申请和平台编码属于企业管理员或实施方路径。

卡片点「同意」的三个硬条件（与关系，缺一不可）：① 真实点击人 = 任务当前处理人 = 绑定成员外部身份，身份取自平台可验证字段，不采信卡片自带 ID；② 外部状态自快照以来未变，含状态、节点、处理人和版本；③ 本次授权可留痕，执行后外部审计能显示该用户为真实操作人。任一条不满足即降级为「打开 AIFred 确认」；高风险动作即使三条全过也必须回桌面端二次确认。

外部机器人负责触达，本地群聊负责多员工讨论，Review Gate 负责最终确认。

3 触发事件与数据流

桌面端主动访问外部平台，平台不向用户机器发起 HTTP 入站。审批原文和运行事件留在本机，Manager 不进入审批执行路径。

3.1 总图：谁在哪一端做什么

虚线表示桌面端主动访问或本地跨组件调用，没有到用户机器的外部入站箭头。

3.2 业务触发事件

外部任务

task_received 新待办进入本地收件箱。

task_changed 表单、节点或处理人变化，旧建议失效。

task_completed_externally 外部已处理，本地停止执行。

本地分析

task_routed 匹配唯一流程绑定。

analysis_requested 创建分析任务并冻结快照。

analysis_completed 生成建议、风险和证据。

用户审核

review_requested 生成审核单。

review_confirmed 生成一次性执行意图。

review_rejected 保存用户决定，不执行外部写操作。

外部执行

execution_started 通过状态、身份和幂等检查。

execution_accepted 平台接受请求。

execution_confirmed 回查确认最终状态。

恢复与连接

sync_started 启动、定时或重连对账。

sync_failed 保留游标并显示修复入口。

credential_expired 停止写操作并要求授权。

业务反馈

proposal_accepted 用户按建议处理。

proposal_edited 用户修改动作或意见。

proposal_overruled 用户选择其他处理。

3.5 AI 建议的依据链

建议不能是一段无法追溯的结论。四层依据进入分析，每条理由必须指回具体来源，执行结果再回流成下一轮的先例和反馈。

7 责任主体与交付边界 谁来做这一次性的配置

技术上可接入不等于普通用户能自行接入。把一次性配置和日常使用拆开，才能既不骗用户，也不把工程量藏起来。

事项责任主体交付形态
企业应用创建、凭据填写、事件订阅、权限申请企业管理员 或 我方实施方管理员后台或实施方远程配置，不在桌面端普通路径
氚云自定义接口代码和发布实施方工程师交付，版本化维护
用户身份授权、流程选择、AI 员工选择每个审批人自己桌面端向导，三步完成
制度文件上传和阈值维护企业管理员 或流程负责人桌面端「制度与规则」页，可后续补
试运行自检和开启绑定审批人，管理员可代配置默认值桌面端向导内完成
对外口径只能说「两步走」：企业管理员在第三方开放平台建企业自建应用并在企业侧 Manager（生产部署在企业服务器上，由平台方实施交付、企业持有，与 Operator 分离部署）配置凭据与策略（若由实施方代录 Secret，交付验收时须由企业重置/改写），之后普通员工在桌面端扫码完成本人 OAuth 授权即可使用。不得宣传企业零配置或应用市场一键免配接入。数据面与执行面固定在桌面端，不引入我方（运营端 Operator）云侧审批组件；开发与测试环境直接按正式独立部署条件验证，不做运行期部署形态开关。

7.1 企业集中管控与员工自定义边界（双层治理结构）

治理维度企业管控强制项（不可篡改）员工自主定义项（合规框架内）违规禁止红线（强制拦截）
合规策略全局制度、金额阈值、必填材料清单、紧急禁用开关个人工作习惯与关注重点（本地 User Prompt）禁止通过 Prompt 绕过或弱化企业底线
底层模型统一指定合规模型（私有化内网模型或内部 NewAPI Relay）在企业白名单内选择偏好模型严禁私自注入未审计的外部个人 API Key
知识与记忆统一维护企业级制度库；Manager 托管 Hindsight 记忆库（向导须明示非仅存本机）习惯走本地 User Prompt；跨任务经验经白名单脱敏后入记忆严禁将审批表单正文或附件写入记忆或 RAG 查询
执行策略设定有条件自动放行上限（流程/金额/动作/24h TTL）；高风险永不自动在企业上限内逐条绑定显式开启/一键暂停有条件自动放行，并抽查记录严禁无条件自动代签、仅靠模型触发放行或突破企业上限
凭据网络企业侧 Manager 加密托管自建应用 Secret 并统一轮换/吊销扫码完成个人 OAuth 授权（用户级 Token 存本机加密 Vault）严禁导出凭据；严禁向桌面分发高权限静态应用 Secret

7.2 数据防截取与防偷传的技术保证（有条件表述）

受控网络与完整出网白名单

Node Agent 仅监听 127.0.0.1（Bearer JWT + CORS 来源白名单 AITEAM_AGENT_ALLOWED_ORIGINS），零公网入站。企业出口防火墙白名单须覆盖：第三方平台域名（*.dingtalk.com / *.feishu.cn / www.h3yun.com）、企业模型/Relay 端点、企业侧 Manager 及交付包声明的静态资源（当前未启用 updater；交付前须收紧 tauri.conf.json 的 img-src 去掉通配 https: 并清理测试服硬编码地址，或按实显式声明）。

控制面数据面脱钩与策略契约

桌面端主动向 Manager 拉取治理策略（离线分层降级：人工沿用缓存、自动放行超时 24h 降级人工、治理摘要默认关）。摘要上报经白名单契约强拦截，治理摘要开启时桌面端常驻提示员工；孤岛模式可关闭上报。

凭据分层与本机防护边界（按实写）

企业应用 Secret 托管于企业侧 Manager 仅作 OAuth 换票/续期（请求期间瞬时经手但不持久化用户级 Token，记录成员可查换票审计并支持一键停用）；用户级 Token 存桌面端本地加密 Vault（AES-256-GCM：Windows DPAPI / Unix 0600 文件，未接 Keychain），经 UDS/命名管道 + 每启动随机 72 字符 token 瞬时注入；SQLite 依赖目录权限与 OS 全盘加密，同账户防护依赖 OS 账户隔离。

模型路径与记忆/附件边界

接入企业内网私有化模型（vLLM/Ollama）时表单正文不出企业内网；经企业 NewAPI Relay 时正文经过 Relay 与上游模型提供方（不落 Manager 业务库）。附件默认按次授权（on_demand）；表单正文与附件禁入记忆，知识库检索裁剪或禁用。

企业白盒审计抽检标准（须对照所选部署前提）：企业安全团队可在测试机运行 Wireshark/mitmproxy 抓包，核验交付包 CSP 收口基线，验证全部出站命中声明白名单且发往 Manager 的请求不含表单正文、附件与聊天记录；核查分层守卫测试与离线/孤岛降级行为。
