外部审批平台接入 · 方案总览

2026-11-28 按 owner 确认的业务流程整体改写。原 9 方法插件、事件订阅、规则集、自动放行、原生确认框等方案作废。标「P0 实测」的内容只来自文档，尚未跑过。

一句话：审批还在钉钉、飞书里做，平台上的状态说了算。桌面端每 3 分钟拉一次「我的待办」，交给负责这个流程的 AI 员工给建议；建议以卡片出现在「员工名 · 审批」对话里，用户点同意 / 拒绝 / 退回并确认后，以本人身份经官方 CLI 写回平台。
目标（owner）怎么做到
接入简单钉钉：管理员开 CLI 访问，用户扫码。飞书：管理员在企业端填一次应用密钥，用户扫码。用户只需再选「这个流程交给谁」
稳定只轮询；平台是唯一真相；结果不明不自动重试
改动小本机 Agent 加一个审批模块（11 个本机接口、3 张表）；桌面端加对话与卡片；企业端只为飞书加 4 个接口；运营端不改
安全员工只有「提交建议」1 个工具，没有写回能力；每次写回都由用户点击、本人身份；执行前复查；内容不离开本机
好用卡片上直接处理和追问；多条自动排队；新流程只问一次

主流程

① 连接用户扫码授权（本人身份）
→
② 同步每 3 分钟拉我的待办 + 新待办详情
→
③ 分给员工按流程 → 员工；没有则默认员工；都没有等用户选
→
④ 员工分析排队；员工读单据和知识库，提交建议
→
⑤ 卡片「员工名 · 审批」对话里出现，未读 +1
→
⑥ 确认用户点动作，浮层核对意见后提交
→
⑦ 写回复查仍是我的待办 → 本人身份调 CLI

在平台上被别人或用户自己处理掉的待办：下一轮完整拉取后不在列表里，卡片收起为「已在钉钉 / 飞书处理」。

多条待办怎么排

规则内容
上下文隔离每条待办一个隐藏分析会话，追问只在这条里
每个员工一次一条同一员工按到达顺序逐条分析
全局最多 2 条不同员工之间并行
插队「先分析这条」、展开追问、让员工看附件
刚连上只自动分析最近 20 条，其余「点此分析」
不合并不批量同一流程多条也是各自一张卡片，首版没有批量同意

写回与防错

浮层提交动作 + 意见 + 看到的快照版本 + 幂等键
→
版本比对不一致 → 「单据已更新」
→
复查仍是我的待办？否 → 「已变化」
→
本人身份调 CLI同意 / 拒绝 / 退回
→
结果成功 / 已变化（查一次）/ 超时（查一次，查不清待确认）/ 失败

同一任务提交中拒绝新提交；结果不明一律不自动重试；平台拒绝已处理任务作最终兜底。
