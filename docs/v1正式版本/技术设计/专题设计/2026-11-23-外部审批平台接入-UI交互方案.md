## 1. 用户看到什么

| 位置 | 新增内容 | 用途 |
|---|---|---|
| 单聊列表（`/chat` 左侧面板） | 顶部固定一项「审批待办」；每个负责审批的员工多一项「员工名 · 审批」 | 日常入口 |
| 「员工名 · 审批」对话 | 这个员工负责的待办，一条待办一张卡片 | 看建议、追问、处理 |
| 「审批待办」 | 所有员工的待办汇总；还没有负责员工的待办只在这里 | 总览、给新流程选员工 |
| 确认浮层 | 点同意 / 拒绝 / 退回后弹出 | 核对动作和意见后提交 |
| 设置 → 外部审批 | 钉钉、飞书连接；默认员工；流程 → 员工对应表 | 一次性设置，之后很少进 |
| 企业端网页 → 企业设置 → 飞书审批应用 | App ID、App Secret | 管理员一次性配置（仅飞书） |

注意与现有「工具权限审批」弹窗（`components/Approvals/ApprovalDialog.tsx`）区分：那是员工调用工具前请求用户允许，和本专题无关。本专题界面文案统一用「审批待办」「× × 审批」，组件目录用 `components/ExtApproval/`。

## 2. 单聊列表

### 2.1 「审批待办」项

- 连接了至少一个平台后出现，固定在单聊列表最顶部（置顶会话之上），不可删除、不可取消置顶。
- 图标：剪贴板勾选图标（lucide `ClipboardCheck`），金色描边。
- 第二行摘要：「待处理 12 · 3 条待选员工」；没有待办时「没有待处理的审批」。
- 角标：待选员工的条数（红点数字）；为 0 时不显示。
- 连接需要处理时（登录过期、未开通），摘要改为红色「钉钉需要重新连接」。

### 2.2 「员工名 · 审批」项

- 员工第一次被分配审批待办时出现；该员工没有待处理、也没有 7 天内的已处理时自动从列表隐藏（数据保留，有新待办时再出现）。
- 排序：和普通会话一起按最近时间排序；最近时间 = 该员工最近一条新建议或新待办的时间。
- 头像：员工头像 + 右下角审批小标记（与自动化任务执行会话的 `panel-conv-auto-mark` 同一位置和做法，图标换成 `ClipboardCheck`）。
- 名称：「张三 · 审批」。第二行：最近一条待办的「流程名 · 申请人」，或「排队中 3 条」。
- 未读：有新建议、用户还没打开过的待办条数（`advice_seen_at` 为空）；沿用现有未读徽标组件。
- 右键菜单只有「全部标为已读」「打开审批设置」；没有删除、置顶、改名。
- 侧栏「单聊」导航的未读数包含审批未读。

和该员工的普通私聊是两项，互不影响：普通私聊里员工有命令、文件等工具，审批内容不进那里。

## 3. 「员工名 · 审批」对话

### 3.1 页面结构

```
┌ 张三 · 审批 ─────────────── 钉钉·飞书 ▾  ⟳ 刷新（2 分钟前同步）  ⚙ ┐
│ [连接需要处理时的提示条]                                           │
│ 待处理 5                                                          │
│  ┌ 卡片 ┐                                                         │
│  ┌ 卡片 ┐                                                         │
│ ▸ 已处理（最近 7 天 8 条）                                          │
└───────────────────────────────────────────────────────────────────┘
```

- 顶栏：标题「张三 · 审批」；平台筛选（全部 / 钉钉 / 飞书，只有一个平台连接时不显示）；「刷新」按钮带上次同步时间，同步中显示转圈，10 秒内重复点击无效果；齿轮跳到设置 → 外部审批。
- 没有底部输入框。追问在卡片里展开（§3.4）。
- 待处理区：按待办到达时间从新到旧排；「单据已更新」「分析失败」「结果待确认」的卡片不改变位置，只改卡片状态。
- 已处理区：默认折叠，显示最近 7 天；展开后是收起状态的卡片（§3.5）。
- 打开对话时：距上次同步超过 30 秒立即同步一次（需求 §5.1）。
- 列表滚动：卡片多时整页滚动，顶栏固定。游标分页，滚到底加载更多。
- 从「审批待办」或系统通知跳进来时，目标卡片滚动到可视区并闪烁一次金色描边（1 秒）。

### 3.2 卡片

```
┌──────────────────────────────────────────────────────────────┐
│ [钉] 差旅报销 · 李四 · 今天 09:12            在原平台打开 ↗   │
│ 上海出差报销 3 天                                             │
│ 金额 ¥4,280 · 出差地点 上海 · 部门 销售二部   展开全部字段 ▾    │
│ 附件 3：发票.pdf（1.2MB）、行程单.png、酒店水单.pdf              │
│ 当前节点：部门负责人审批（我）                                  │
│ ┌ 张三的建议 ────────────────────────────────────────────┐   │
│ │ 建议 [退回]  住宿超标且缺酒店发票                          │   │
│ │ · 住宿每晚 680 元，超过标准 500 元（依据：差旅制度.docx）  │   │
│ │ · 只有水单没有发票（依据：附件清单）                      │   │
│ │ 缺少：酒店发票                                           │   │
│ │ 注意：出差天数与行程单一致                               │   │
│ │ 拟写意见：住宿超标，请补酒店发票并说明超标原因。           │   │
│ └──────────────────────────────────────────────────────────┘   │
│ [退回]  [同意]  [拒绝]                    追问 ▾    ⋯         │
└──────────────────────────────────────────────────────────────┘
```

- 头部：平台小图标、流程名、申请人、提交时间；右侧「在原平台打开」（用系统浏览器或平台客户端打开该审批的链接）。
- 标题一行；关键字段默认显示前 4 个（按平台返回顺序，跳过附件和明细表），「展开全部字段」展开全部表单，明细表以表格显示，长文本折叠为 3 行。
- 附件清单只显示文件名和大小，点文件名 = 在原平台打开；本机不预览附件（需求 §6.4）。
- 当前节点与处理人：显示节点名和「（我）」或并行处理人名字，数据来自快照。
- 建议块：
  - 建议动作用药丸标签：同意（绿）、拒绝（红）、退回（橙）、需要人工判断（灰）。
  - 一句话结论；理由逐条，依据用弱化文字括注；依据为「无」时显示「（无依据）」。
  - 缺少材料、注意事项各一行列表，为空时不显示。
  - 拟写意见原文显示，可复制。
- 动作按钮：
  - 同意、拒绝、退回三个按钮常驻（退回在该平台不可用时不显示），**无论有没有建议都能点**。
  - 员工建议的动作排在最前并用金色描边强调，其余普通样式；建议为「需要人工判断」或没有建议时按「同意、拒绝、退回」排列，都不强调。
  - `missing` 非空时「退回」排最前（需求 §6.3），但不替用户选。
- 「追问」展开卡片内追问区（§3.4）。
- 「⋯」菜单：重新分析、先分析这条（仅排队中）、更换负责员工、在原平台打开。

### 3.3 卡片状态

建议块位置按状态显示不同内容；动作按钮除「提交中」外始终可用。

| 状态（推导，不是存储字段） | 建议块显示 | 卡片其他变化 |
|---|---|---|
| 排队中 | 「排队中，前面还有 k 条」+「先分析这条」 | — |
| 待手动分析（`analysis_mode=manual`） | 「点此分析」按钮 | — |
| 分析中 | 骨架屏 +「张三正在看…」 | — |
| 有建议 | 建议内容 | 未读时左侧金色竖条，打开详情接口后消失 |
| 单据已更新（建议版本落后快照） | 建议内容上方黄色条「单据已更新，建议可能已过时」；自动分析流程显示「重新分析中」，手动的显示「重新分析」按钮 | — |
| 分析失败 | 「分析失败」+ 原因（超时 / 模型不可用）+「重试」 | — |
| 提交中 | 不变 | 三个动作按钮置灰，被点的按钮转圈 |
| 结果待确认（`phase=unknown`） | 不变 | 卡片顶部黄色条「已提交，结果待确认，下次同步后更新」；动作按钮置灰 |
| 已处理（这里） | 收起 | §3.5 |
| 已在平台处理（别处） | 收起 | §3.5 |
| 需要处理（连接失效等） | 不变 | 动作按钮置灰，提示「重新连接后可处理」；「在原平台打开」可用 |

### 3.4 卡片内追问

- 点「追问」：卡片下方展开追问区，高度上限为窗口高度的 60%，内部滚动；同时只展开一张卡片，展开新的会收起旧的。
- 追问区显示这条待办的分析会话里用户可见的消息（首条组装提示词不显示，显示为一行「张三已读取这条审批」），消息样式复用 `MessageBubble`。
- 输入框：一行起，最多 6 行；Enter 发送，Shift+Enter 换行；员工回复中输入框可用但发送按钮变「停止」。
- 「让员工看附件」：输入框左侧的回形针按钮，弹出附件勾选列表（文件名、大小，超过 20 MB 的置灰并注明，最多勾 5 个），确认后发起分析（需求 §8.1 #10 带 `attachment_ids`）。员工回复里注明哪些附件未读取。
- 员工在追问中更新了建议时，卡片建议块就地更新，并在追问区插一行「建议已更新：拒绝 → 退回」。
- 展开追问的卡片会插队到分析队列最前（需求 §6.2）。

### 3.5 已处理卡片

收起为一行：

```
[钉] 差旅报销 · 李四 · 上海出差报销 3 天     已退回 · 我在这里处理 · 10:24     ▸
[飞] 采购申请 · 王五 · 办公椅 20 把           已在飞书处理 · 11:02              ▸
```

- 「这里处理」显示动作和时间；「已在钉钉 / 飞书处理」只说明已不在待办里，不猜别人做了什么。
- 点开显示当时的快照、建议、我提交的意见和处理记录，全部只读，没有动作按钮，「在原平台打开」可用。
- 处理成功后，卡片在待处理区停留 3 秒并显示「已同意」，然后移到已处理区（动画 200ms，系统开启减少动态效果时直接移动）。

### 3.6 多条同时到达

- 一条待办一张卡片，不合并，没有批量同意。
- 同一员工的待办按到达顺序逐条分析，卡片依次从「排队中」变为「有建议」；不同员工之间并行，全局同时最多 2 条（需求 §6.2）。
- 刚连上账号时只自动分析最近 20 条，其余卡片显示「点此分析」，对话顶部一次性提示「较早的 35 条待办没有自动分析，可逐条点击分析」，可关闭。
- 新待办到达时不抢滚动位置：如果用户不在列表顶部，顶部浮出「3 条新待办 ↑」按钮，点击回到顶部。

## 4. 确认浮层

用 `ChatDialog` 的结构，宽 520px，内容区可滚动，底部按钮固定。

```
┌ 确认退回 ───────────────────────────────────── × ┐
│ 差旅报销 · 李四 · 上海出差报销 3 天                │
│ 退回给发起人，申请人修改后可重新提交。               │
│                                                  │
│ 审批意见（必填）                          46/1000 │
│ ┌──────────────────────────────────────────────┐ │
│ │住宿超标，请补酒店发票并说明超标原因。          │ │
│ └──────────────────────────────────────────────┘ │
│ 已填入张三拟写的意见，可修改。                     │
│                                                  │
│ ⓘ 张三建议的是「退回」。                          │
├──────────────────────────────────────────────────┤
│                          [取消]  [提交退回]        │
└──────────────────────────────────────────────────┘
```

- 标题：「确认同意 / 确认拒绝 / 确认退回」。
- 第一行：流程名 · 申请人 · 标题，让用户确认是哪一条。
- 动作说明一句：同意「同意后流转到下一节点」；拒绝「拒绝后流程结束」；退回「退回给发起人，申请人修改后可重新提交」。
- 意见输入框：默认填员工拟写的意见（没有建议时为空），可改；最少 3 行，最多 10 行后内部滚动；右上角字数「n/1000」，超出变红并禁用提交。拒绝、退回为必填，空时提交按钮禁用并提示「请填写意见」。
- 提示行（只提示，不拦截）：
  - 用户选的动作和建议不同：「张三建议的是『退回』。」
  - 同意且员工列出了缺少材料：「张三认为缺少：酒店发票。」
  - 建议依据的快照已过时：「单据已更新，建议可能已过时。」
- 按钮：「取消」「提交同意 / 提交拒绝 / 提交退回」。拒绝和退回的提交按钮用危险色。
- 提交中：提交按钮转圈，文字不变；取消、关闭、Esc、点遮罩都不可用（防止用户以为取消了）。
- 结果：

| 返回 | 浮层 | 卡片 |
|---|---|---|
| 成功 | 关闭，Toast「已退回」 | §3.5 |
| 409 `snapshot_changed` | 不关闭，顶部黄色条「单据已更新，请重新查看后再提交」，按钮变「重新查看」，点击关闭浮层并刷新卡片（意见保留在浮层的草稿里，再次打开时恢复） | 刷新 |
| 409 `task_changed` | 关闭，Toast「该审批已在别处处理或已变化」 | 刷新为对应状态 |
| 409 `action_in_progress` | 关闭，Toast「上一次提交还在进行中」 | 提交中 |
| 422 `comment_too_long` | 不关闭，字数处标红「平台最多 n 字」 | — |
| 结果不明 | 关闭，Toast「已提交，结果待确认」 | 结果待确认 |
| 其他失败 | 不关闭，红色条显示原因 +「重试」；「在原平台打开」链接 | — |

- 键盘：打开时焦点在意见输入框末尾；Esc 关闭（提交中除外）；⌘/Ctrl+Enter 提交。提交按钮不响应 Enter 单键，避免换行时误提交。

## 5. 「审批待办」

### 5.1 页面结构

```
┌ 审批待办 ─────────── 全部员工 ▾  钉钉·飞书 ▾   ⟳ 刷新（2 分钟前）  ⚙ ┐
│ [连接提示条]                                                       │
│ 待选员工 3                                                         │
│  ┌ 卡片（无建议块，显示「选择员工」） ┐                                │
│ 张三 5 · 李四 2                                                    │
│  ┌ 卡片（同 §3.2，右上角显示负责员工头像） ┐                          │
└────────────────────────────────────────────────────────────────────┘
```

- 「待选员工」分组固定在最上方；其余按员工分组，组标题「张三 · 5 条」，点击组标题进入「张三 · 审批」。
- 卡片与员工对话里的卡片相同，可以直接处理；点卡片空白处跳到对应员工的「审批」对话并定位。
- 员工筛选、平台筛选；刷新规则同 §3.1。

### 5.2 选择员工

待选员工的卡片在建议块位置显示：

```
这个流程（差旅报销）还没有负责员工。
[选择员工 ▾]   ☑ 以后「差旅报销」都交给他
```

- 下拉只列当前用户在企业端有权使用的员工，带头像和职位。
- 勾选默认打开：选定后写入流程 → 员工对应表（需求 §8.1 #4），该流程所有待选待办一起移到这个员工名下并按规则入队；不勾选只改这一条。
- 设置了默认员工时，新流程直接交给默认员工，不进「待选员工」；该员工对话里这类卡片头部显示一次「新流程，已按默认交给张三 · 修改」，点「修改」弹出同样的选择下拉。
- 负责员工被停用或不再有权使用时，相关待办回到「待选员工」，提示「张三已不可用，请重新选择」。

### 5.3 空状态

| 情况 | 显示 |
|---|---|
| 未连接任何平台 | 不出现「审批待办」项；设置页有入口 |
| 已连接，首次同步中 | 骨架屏 +「正在拉取钉钉待办」 |
| 没有待办 | 「没有待处理的审批」+ 上次同步时间 |
| 同步失败 | `RequestErrorState`：原因 +「重试」 |

## 6. 设置 → 外部审批

在设置页加一个卡片「外部审批」，放在「系统通知」之后。

### 6.1 平台连接

```
外部审批
把钉钉、飞书里待你审批的单据交给 AI 员工先看一遍。审批内容只保存在这台电脑上。

[钉] 钉钉    已连接 · 张三（天元科技）    上次同步 2 分钟前     [断开]
[飞] 飞书    未连接                                          [连接]

默认员工  [张三 ▾]   新流程默认交给他；不设置则每个新流程都需要你选。
```

- 状态：未连接 / 已连接（账号名 + 企业名）/ 需要处理（红色，原因 +「重新连接」）。
- 「断开」二次确认：「断开后不再同步钉钉待办，本机保存的登录会删除，历史记录保留。」按钮「断开」（危险色）/「取消」。

### 6.2 连接对话框

`ChatDialog`，宽 440px：

| 步骤 | 内容 |
|---|---|
| 说明 | 一句话说明要做什么：「用你自己的钉钉账号扫码授权。之后 AI 员工只给建议，每次同意、拒绝、退回都要你点击确认，以你本人名义提交。」按钮「开始」 |
| 扫码 | 二维码（需求 §8.1 #2 返回的内容）+ 倒计时；「用钉钉扫码」/「用飞书扫码」；下方「无法扫码？复制链接」 |
| 等待 | 每 2 秒查登录结果（需求 §8.1 #3），二维码过期显示「二维码已过期」+「刷新」 |
| 成功 | 「已连接：张三（天元科技）」→ 第一次连接时进入「选择默认员工」小步骤（可跳过），完成后关闭并立即同步 |
| 企业未开通（钉钉） | 「你的企业还没有开启钉钉 CLI 访问」+ 说明 dws 会给管理员发申请；按钮「已发送申请，稍后再试」/「关闭」 |
| 企业未配置（飞书） | 「企业管理员还没有在企业端配置飞书审批应用」+ 管理员需要做的两步；按钮「关闭」 |
| 失败 | 原因 +「重试」 |

扫码前不需要用户填写任何密钥、App ID 或命令。

### 6.3 流程 → 员工

连接后，卡片下方出现表格：

| 平台 | 流程 | 负责员工 | 自动分析 | 最近待办 |
|---|---|---|---|---|
| 钉钉 | 差旅报销 | [张三 ▾] | [开] | 今天 |
| 飞书 | 采购申请 | [未选择 ▾] | [开] | 昨天 |

- 只列出现过待办的流程（不拉平台的流程模板）。
- 改负责员工：已在队列和已有建议的待办不受影响，之后的新待办交给新员工；表格下方提示一次「已有的待办仍由原员工负责，可在卡片的 ⋯ 菜单里逐条更换」。
- 关闭自动分析：该流程的新待办显示「点此分析」。
- 超过 10 行时表格内部滚动并提供搜索框。

### 6.4 通知

在现有「系统通知」卡片里加一个开关「外部审批有新建议」，默认开：

- 应用不在前台时，一轮同步或分析完成后合并发一条：「3 条审批有新建议」，点击打开「审批待办」；只有一个员工时打开该员工的「审批」对话。
- 同一分钟内最多一条；用户正在看审批界面时不发。
- 连接需要处理时发一条「钉钉登录已过期，点击重新连接」，同一原因 24 小时内只发一次。

## 8. 页面与接口对照

| 界面 | 调用（需求 §8） |

## 9. 文案

| 场景 | 文案 |
|---|---|
| 建议动作 | 同意 / 拒绝 / 退回 / 需要人工判断 |
| 已处理 | 已同意 / 已拒绝 / 已退回 · 我在这里处理；已在钉钉处理；已在飞书处理 |
| 过时 | 单据已更新，建议可能已过时 |
| 结果不明 | 已提交，结果待确认，下次同步后更新 |
| 登录过期 | 钉钉登录已过期，重新连接后继续同步 |
| CLI 输出不符 | 同步失败，请升级桌面端 |
| 限流 | 同步稍慢，稍后会自动继续 |
| 待办过多 | 待办过多，只显示最近 1000 条 |

不用「AI 已批准」「自动处理」「风险等级」等说法；动作永远是「你提交」，员工只「建议」。

## 10. 验证清单

交互（每项留截图或录屏）：

1. 连接钉钉、飞书各走通一次扫码；二维码过期、企业未开通、飞书未配置各验证一次提示。
2. 同时到达 30 条待办（两个员工、一个无负责员工）：列表项、未读数、排队提示、首次只自动分析 20 条、「待选员工」分组都符合 §3.6、§5。
3. 每种卡片状态（§3.3 表 11 行）各截一张。
4. 确认浮层：三种动作、意见必填、1000 字上限、建议不同提示、7 种返回结果（§4 表）。
5. 提交中关闭不了浮层；结果待确认时动作按钮置灰。
6. 追问：展开、发送、停止、让员工看附件（含 >20 MB 置灰）、建议就地更新、同时只展开一张。
7. 选择员工：勾选「以后都交给他」与不勾选两种结果。
8. 断开后列表项消失、历史可在已处理中查看。
9. 全局事件断线重连后列表正确刷新。

可用性（按 AGENTS.md「UI 验证要验能不能用」）：

- 长内容：卡片 20 个字段、明细表 30 行、意见 1000 字、追问 30 条消息；短内容：只有 1 个字段、没有建议。
- 小窗口 1440×640 和默认窗口各测一次：确认浮层的提交按钮、卡片动作按钮、追问输入框都在可视区内，用 Playwright `elementFromPoint` 确认真实鼠标能点到，不用强制点击。

- 键盘：Tab 顺序、Esc、⌘/Ctrl+Enter；读屏能读出卡片状态和建议动作。
