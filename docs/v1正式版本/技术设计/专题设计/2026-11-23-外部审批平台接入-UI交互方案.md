# 外部审批平台接入 UI 交互方案

> 关联设计：[需求与设计](./2026-11-23-外部审批平台接入-需求与设计.md)  
> UI 是信息结构方案，不是最终视觉稿。实现时沿用桌面端现有设置页、Dialog、列表、Toast 和错误模型。

> 评审修订（2026-11-27）：平台接入步骤、应用 Secret 录入与换票、事件接收为候选方案，P0 实测前待定（需求与设计 §13 #12）。写操作确认经桌面宿主私有通道一次性下达，本地 HTTP 只能发起确认请求。外部机器人与卡片确认**首版不做**（需求与设计 §3.6，旧设计见其附录 B）。  
> 2026-11-27 第二轮：UI 改为一套通用流程，平台差异由插件 `describe()` / `authSteps` 提供。  
> 2026-11-28 第五轮：每个页面功能的接口与字段见需求与设计 §10.2 对照表（本地接口 24 个）；高风险动作改由宿主弹系统原生确认框；缺失材料改为「勾选知悉后可同意 + 独立『退回补件』按钮」（owner 裁决）。

## 1. 信息架构

在桌面端新增「外部审批」入口，包含六个页面或页签（第 6 个供申请人使用）：

1. **审批任务**：按 5 个主状态（`open` / `executing` / `done` / `stale` / `blocked`）及原因码查看任务，见 §2。
2. **流程绑定**：把插件返回的流程、节点和当前用户绑定到 AI 员工。
3. **连接**：列出已安装的平台插件，按插件提供的授权步骤完成本人授权，并显示 `describe()` 自检结果。核心 UI 不按平台分页面。
4. **制度与规则**：只读展示企业侧 Manager 下发的规则投影（制度文件版本、金额分档、必需材料、高风险条件），本机不改规则主数据。
5. **执行记录**：查看每次确认或自动放行（按 `execution_id` 汇总 `ext_approval_execution` 的只追加条目）、外部结果、对账状态和用户反馈（`GET …/executions`）。页内提供「自动放行抽查」筛选（`approval_method = auto_rule`）、「这条建议准不准」补打分与「标记误放行」（`POST …/executions/{executionId}/feedback`，只追加反馈条目）。

6. **提交前预检**：申请人在原平台提交前检查自己的材料，见 §11。

「制度与规则」是企业侧 Manager 规则与治理策略的本机只读投影（需求与设计 §2.2、§5.2、§13 #9）。审批人个人关注点不在此页维护，而是写在流程绑定高级设置的本地 User Prompt 里（§5），只能补充、不能覆盖企业规则。没有可用规则时，AI 建议只能输出「未找到可用制度依据」。

### 1.1 制度与规则页面

| 区块 | 内容 | 权限 |
|---|---|---|
| 制度文件列表 | 文件名、适用流程范围、版本、生效时间、装载状态 | 全员只读；上传与替换在企业侧 Manager |
| 规则清单 | 按流程模板分组展示金额分档、必需材料、高风险条件和建议意见模板 | 全员只读；编辑在企业侧 Manager |
| 规则集来源 | 每个规则集来自哪个行业模板（模板名称与版本）。行业模板由运营端维护、Manager 拉取并由企业引入为规则集后发布，桌面端只看到规则集（需求与设计 §3.9） | 只读 |
| 投影状态 | 规则版本、最近同步时间；拉取失败时显示「沿用上次同步的规则」 | 全员可见 |
| 装载状态提示 | 未装载制度的流程绑定显示「该流程暂无制度依据，AI 只能做形式检查」 | 全员可见 |

本页数据全部来自本机投影 `GET …/policies`；制度文件正文与条款定位来自 `GET …/policies/documents/{docId}`。流程绑定向导和任务详情都要提供进入该页的入口。规则投影更新到新版本后，旧版本生成的建议失效并要求重新分析。

页面顶部展示连接状态摘要（`GET …/overview`，收到 `GET …/events` 状态推送后刷新）：

- 已连接插件数量。
- 待处理任务数量（`open` 且已有建议）。
- 需要重新授权数量（`blocked` · `credential_expired`）。
- 最近同步时间。
- 离线或对账状态。
- 企业开启治理摘要上报时的知情条「企业已开启治理摘要上报」，可展开查看上报字段白名单。
- 自动放行一键暂停开关（至少一条流程开启了有条件自动放行时显示，`PATCH …/preferences`）。

### 1.2 首次接入和日常使用的分界

产品必须把“企业首次接入”和“普通用户使用”拆开。普通用户不应进入平台开发者后台，也不应填写 API、Secret、流程编码或节点编码。平台首次接入由企业管理员（可由实施方代办）按插件要求在第三方开放平台创建企业自建应用、配置最小权限；凭据托管方待定（需求与设计 §13 #12）。

普通用户只有一套通用接入流程（需求与设计 §2.5）：

```text
选择平台插件
  ↓
按插件 authSteps 完成本人授权（如扫码 OAuth；回调复用 /api/agent/mcp-auth/callback）
  ↓
自检：显示 describe() 四项能力 read / actions / attachments / push
  ↓
选择流程与 AI 员工
  ↓
试运行（一条测试任务的分析，校验身份、处理人与写回能力）
  ↓
开启绑定，之后自动同步与分析
```

UI 只渲染插件提供的授权步骤说明与 `describe()` 结果，不出现平台专有字段或按平台分支的页面。接入完成页统一显示：授权身份、`read`、`actions`（已验证可写回的动作列表）、`attachments`、`push`、最近同步时间和修复入口。`actions` 为空时绑定可以保存为只读分析模式，但不能显示“审批可执行”。企业尚未完成应用配置时显示「当前企业未完成配置」。应用市场安装不在 v1 范围。

**插件候选差异（P0 待验证，见需求与设计附录 A）**

以下只是插件实现的输入，不进入核心 UI；P0 前四项能力全部按「未验证」处理（需求与设计 §3.1.1），UI 一律隐藏对应入口（动作例外：仍显示，点击引导到原平台处理）。

| 插件（候选） | 授权候选 | 当前口径 |
|---|---|---|
| 飞书 | 扫码 OAuth，经企业侧换得本人 `user_access_token` | 用户级写回、审计操作人与按用户接收事件待 P0；未验证前显示「可分析，暂不可提交」 |
| 钉钉 | 扫码 OAuth | 写回可能只能用应用凭据、事件接收方式待定（可能经企业侧服务）；未验证前只读分析 |
| 氚云 | 企业已配置的开放接口或已验证连接器 | 自定义接口能否保留真实操作人未验证；未验证前只读分析（提醒、AI 分析、在原平台打开、对账） |
| fake（测试用） | 无需真实授权 | 四项能力全部通过，用于验证通用 UI |

### 1.3 业务触发事件入口

用户不需要理解内部事件名称，但界面必须让事件产生的结果可追踪。事件与落点对应需求与设计 §2.4（不单建事件表）。

| 用户场景 | 内部触发事件 | 界面反馈 |
|---|---|---|
| 外部平台出现待办 | `task_received` | 新任务通知，任务进入 `open` |
| 表单、版本或处理人发生变化 | `task_changed` | 任务置 `stale`，旧建议作废，提示重新查看 |
| 外部已处理、撤销、超时或转交 | `task_closed` | 任务置 `done` 并显示原因，关闭可执行入口 |
| 无绑定、多绑定冲突或员工不可用 | `route_blocked` | 任务置 `blocked`，显示原因码和处理入口 |
| AI 员工提交建议 | `proposal_submitted` | 显示建议、风险和依据（展示态「已有建议」） |
| 用户在详情发起确认 | `decision_requested` | 打开宿主确认，执行记录新增待确认行 |
| 宿主确认通过或有条件放行通过 | `decision_confirmed` | 显示执行前复查与执行中 |
| 外部状态确认已改变 | `execution_finished` | 显示执行成功和审计记录，任务置 `done` |
| 写回结果暂不可确认 | `execution_unknown` | 显示「结果待对账」，禁止重试按钮 |
| 重读发现变化、身份不符或插件明确失败 | `execution_failed` | 显示失败原因，任务置 `stale` 或 `blocked` |
| 凭据过期、权限变化或同步失败 | `connection_degraded` | 连接显示降级与修复入口，停写回，任务保留 |

用户修改或推翻 AI 建议不是单独事件，记在执行行的 `feedback` / `feedback_diff_json`（§4.2）。

## 2. 任务列表

### 2.1 列表结构

每个任务卡片包含：

- 插件标识和流程名称。
- 申请标题和摘要（平台摘要；没有时用白名单内前 3 个字段拼出，不调用模型）。
- 当前节点。
- 申请人和当前外部处理人。
- 分配的 AI 员工。
- 风险标签。
- 状态（主状态中文标签 + 原因码中文说明）。
- 外部截止时间。
- 最近同步时间。
- 主操作。

持久化主状态只有 5 个（需求与设计 §3.2）。「分析中」「已有建议」「待审核」是展示态，由建议是否存在和会话运行状态推导，不写入主状态。主操作按状态显示：

| 主状态（原因码） | 展示 | 主操作 | 次操作 |
|---|---|---|---|
| `open`，无建议、无会话运行 | 待分析 | 让员工分析 | 查看详情、在群聊讨论 |
| `open`，会话运行中 | 分析中 | 查看进度 | 停止分析、打开群聊 |
| `open`，已有建议 | 已有建议 · 待审核 | 审核建议 | 重新分析、查看详情 |
| `executing`（`confirm` / `auto_rule`） | 执行中 | 查看执行状态 | 刷新 |
| `executing`（`result_unknown`） | 结果待对账 | 查看执行状态 | 立即同步（不提供重试） |
| `done`（`done_here`） | 已在本机完成 | 查看记录 | 在原平台打开 |
| `done`（其他原因码） | 外部已处理 / 已撤销 / 已超时 / 已转交 | 查看记录 | 在原平台打开 |
| `stale` | 任务已变化 | 重新查看 | 查看变化 |
| `blocked`（`credential_expired` / `capability_missing`） | 需要重新授权 / 当前账号不支持 | 去连接页修复 | 查看详情 |
| `blocked`（`route_missing` / `route_conflicted` / `employee_unavailable` / `policy_disabled`） | 无法路由 / 已停用 | 去流程绑定处理 | 查看详情 |
| `blocked`（`mapping_unknown`） | 状态无法识别 | 查看插件诊断 | 等待插件更新后重新同步 |
| `blocked`（`execution_failed`） | 执行失败 | 查看错误 | 立即同步 |

原因码完整取值以需求与设计 §3.2 为准。列表不展示平台原始状态；插件返回无法映射的值时任务为 `blocked`（`mapping_unknown`），禁止继续执行。

### 2.2 筛选

筛选项（全部对应 `GET /api/agent/approvals/tasks` 的查询参数，需求与设计 §10.2）：

- 插件。
- 流程绑定。
- AI 员工。
- 风险等级。
- 主状态。
- 原因码。
- 时间范围。
- 是否需要用户处理（`open` 已有建议、`stale`、`blocked`）。

展示态（分析中、已有建议）只作为 `open` 下的次级快捷筛选，由前端推导，不作为后端状态值。筛选条件应写入 URL 或本地页面状态，刷新后能够恢复。列表使用游标分页，不能一次加载所有历史审批。

### 2.3 空状态

- 没有连接时，显示「先连接一个审批平台」和「添加连接」按钮。
- 有连接但没有流程绑定时，显示「先选择一个流程交给员工处理」和「新建流程绑定」按钮。
- 有绑定但没有任务时，显示最近同步时间和「立即同步」按钮。
- 同步失败时显示失败原因、最近成功同步时间和「重试同步」按钮。

## 3. 任务详情

任务详情采用两栏结构。

### 左栏：外部审批内容

- 插件、流程、节点信息。
- 申请人、当前处理人、提交时间和截止时间。
- 绑定版本（`revision`）。
- 字段白名单内的表单字段。
- 允许读取的附件列表。
- 外部流程时间线（插件提供时；未勾选「流程意见」字段时不显示意见正文）。
- 「在原平台打开」链接（快照 `externalUrl`；没有时隐藏）。

左栏数据均来自 `GET …/tasks/{id}` 返回的白名单快照（需求与设计 §3.3）；附件预览来自 `GET …/tasks/{id}/attachments/{attachmentId}`。

### 右栏：AI 员工建议

- AI 员工名称和头像。
- 建议动作。
- 风险等级。
- 建议理由。每条理由后跟一个来源标签，展示见 §3.1。
- 引用的字段和附件。
- 命中的风险规则名称和所属制度文件版本。
- 缺失材料清单，阻塞项单独标记。
- 置信度，低于中等时显示「依据不足，建议人工复核」。
- 建议审批意见。
- 是否建议人工审核。
- 分析时间和模型信息摘要。
- 主状态与原因码；`blocked`（`mapping_unknown`）时显示「状态无法识别」和「查看插件诊断」入口（诊断取插件本地脱敏日志，不展示平台原始字段）。
- 本节点全部可用动作（插件按平台原文案给出）；不能在桌面端直接写回的动作标注原因（如「当前账号未验证该动作」「绑定未允许」）。
- 「在群聊中讨论」入口和当前本地审批群聊状态。

右栏底部使用固定操作区：

- 按任务的 `actions` 原样显示动作按钮，文案用平台原文（如「同意」「拒绝」「退回」「加签」「转交」）；动作多于 4 个时，前 3 个平铺，其余收进「更多动作」。
- 在 `describe().actions` 与绑定动作白名单交集内的动作直接打开确认弹窗；不在交集内的动作按钮仍可点，点击后打开「在原平台处理」提示（说明原因并给出跳转），不发起写回。
- `退回补件`：仅在存在阻塞类缺失材料时显示，规则见 §4；建议为 `need_info` 时作为推荐动作高亮。
- `重新分析`
- `暂不处理`：本地延后（`POST …/tasks/{id}/defer`，可选延后到明天 / 下周一 / 自定义），任务在列表里沉底并不计入角标，到期自动恢复；不改主状态，不写回外部。

`actions` 为空（只读分析模式）时，操作区只保留 `重新分析`、`暂不处理` 和「在原平台打开」。

操作区在 1440×640 小窗口中必须保持可见，表单和建议内容在中间区域滚动。长文本和多附件不能把按钮推到窗口外。

### 3.1 建议依据的展示

用户要能当场判断「这条理由是从哪里来的」，否则建议只是一段无法校验的文本。每条理由都渲染为「理由文本 + 来源标签」，来源标签来自 `proposal_json.reasons[].citation`（需求与设计 §3.8）。

| citation 类型 | 标签文案 | 点击行为 |
|---|---|---|
| `form.<field>` | 字段名，如「报销金额」 | 滚动并高亮左栏对应字段 |
| `attachment:<name>#p<n>` | 文件名 + 页码，如「报价单.pdf · P2」 | 打开附件预览并跳到该页 |
| `policy:<doc>#<条>` | 制度名 + 条号，如「差旅管理办法 · 3.2」 | 打开制度文件并定位条款 |
| `local:ext_approval_task#<id>` | 「历史先例」 | 打开该已完成（`done`）任务的详情与执行记录 |

展示约束：

1. 没有可解析 citation 的理由不展示。不得用「模型分析」这类空标签充数。
2. 来源标签必须可点。点不动的标签等于没有依据，属于缺陷。
3. 附件未授权读取内容时，标签显示「仅文件名」并置灰，不假装已读过正文。
4. 制度未装载时，右栏顶部显示「该流程暂无制度依据」条带和「查看制度与规则」入口，指向制度与规则页（只读）。
5. 规则投影版本或任务快照版本变化后，整个依据区置灰并提示「依据已过期，请重新分析」。

### 3.2 群聊讨论

任务详情提供「在群聊中讨论」入口，打开或创建与当前任务绑定的 AIFred 本地群聊（`POST …/tasks/{id}/conversation`）。群聊固定显示任务上下文条和参与员工，不把外部平台 Secret 或完整原始响应放入消息。群聊内容只在本机，不发往第三方平台。

群聊界面包含：

- 任务上下文条，显示插件、流程、节点、主状态与原因码、最近同步时间。
- 参与者列表，显示负责员工、协调员工和已授权的财务/风控员工。参与者来自固定 roster，不能在消息框中临时加入未授权员工。只有负责员工能提交建议，其他员工只提供分析意见。
- 消息时间线，区分用户、AI 员工和系统状态消息。AI 员工回复显示来源员工和所引用的字段。
- 输入框支持文本、字段引用和 `@` 已有参与者。发送消息只触发本地群聊投递，不调用第三方写接口。
- 建议卡片，展示建议动作、风险、证据和「去详情确认」按钮。确认只能在任务详情发起。

用户在群聊中输入「同意」「拒绝」等自然语言时，不执行任何动作，只提示「请到任务详情发起确认」并提供跳转。任务进入 `stale`、`done` 或 `blocked` 后，群聊保留历史并切换为只读，显示最终状态或「任务已变化」提示。

## 4. 审核确认弹窗

点击可直接写回的动作按钮后打开确认弹窗。可选动作只来自任务 `actions` 与 `describe().actions`、绑定动作白名单的交集；核心只透传动作 id、参数与意见。

弹窗内容：

1. 插件和流程任务。
2. 当前用户外部身份。
3. 即将执行的动作。
4. AI 员工建议和风险等级。
5. 审批意见编辑框（按动作的 `comment` 要求显示必填 / 选填 / 不显示）；动作带 `params` 时按参数类型渲染表单：`member` 为人员选择（先显示插件给出的初始候选；参数 `searchable = true` 时可输入姓名搜索，经本地接口实时调插件 `searchParamOptions`，输入防抖 300ms、最多 50 条、同名用部门区分；不可搜索且候选为空时该动作只提供「在原平台处理」；搜索失败显示「搜索失败，可重试或去原平台处理」），`node` 为节点下拉，`choice` 为单选，`text` 为输入框；必填项未填时确认按钮置灰。
6. 影响提示。
7. 当前外部状态的最后同步时间。

确认按钮文案必须包含动作，用平台原文案拼成「确认{label}并提交」，例如「确认同意并提交」，不能使用没有业务含义的「确定」。

确认流程（需求与设计 §3.4）：

1. 点击确认按钮调用 `POST …/tasks/{id}/decision`，只生成待确认记录，不执行。请求体携带弹窗渲染时的 `seenSnapshotVersion` 与 `seenProposalVersion`（没有建议时为 `null`）；Hub 发现任一版本已变时返回 409，弹窗切换为「任务或建议已更新，请重新查看」并重新加载详情，不生成待确认记录。
2. 界面随即调用 Tauri 宿主命令；宿主经私有通道读取待确认记录并下达一次性确认。确认票据不经过 WebView 与 HTTP，界面只显示「正在确认」。待确认记录为高风险时，宿主先弹系统原生确认框（见下文）。
3. 执行前由 Hub 重新读取外部任务，比对版本与处理人；不一致时任务置 `stale`，弹窗切换为冲突状态（「任务已变化，请重新查看」）并阻止提交。
4. 写回使用幂等键；结果暂不可确认时显示「结果待对账」，不提供重试按钮。

弹窗打开时也刷新一次任务状态；状态、处理人、节点或版本已变化时直接显示冲突状态。

**高风险动作的系统原生确认框**（owner 2026-11-28 裁决，需求与设计 §3.4 第 3 条）：

- 是否高风险由 Hub 按企业规则投影与流程绑定算出并记在待确认记录里，不采信界面传入值。弹窗内只显示风险等级与命中规则，供用户预知。
- 高风险时，点击「确认{label}并提交」后由宿主弹出操作系统原生确认框，内容由宿主按私有通道读到的待确认记录生成：流程名称、任务标题、动作原文案、参数显示名与命中的高风险规则名。用户在原生框点「取消」则不下达确认，弹窗回到可编辑状态。
- 原生框替代界面内的确认词与二次确认按钮，界面不再做这两种确认。
- 普通动作仍是弹窗内一次点击，不弹原生框。

弹窗还要显示两组阻塞信息：

- **缺失材料**（`missing_items` 中存在 `blocking = true`，统一口径见需求与设计 §3.8 约束 3）：
  - 从 `kind = approve` 的动作按钮打开弹窗时，弹窗顶部列出缺什么、为什么缺，并显示复选框「我已知材料缺失」；未勾选时「确认{label}并提交」不可点，勾选后可提交（请求体 `missingAck = true`）。
  - 弹窗是从具体动作按钮打开的，**弹窗内没有动作切换，也不做任何默认改选**；要换动作就关闭弹窗、点另一个按钮。
  - 详情固定操作区另有独立的「退回补件」按钮：取任务动作中第一个 `kind = return` 的动作，没有则取第一个 `kind = comment`，打开该动作的弹窗并预填补充材料要求；两类都没有时按钮变为「在原平台处理」。按钮文案带所取动作的平台原文，如「退回补件（退回申请人）」。建议为 `need_info` 时该按钮高亮为推荐动作。
- `confidence` 低于中等时，顶部显示「依据不足，建议人工复核」，不自动禁用提交，但默认焦点落在「取消」。

### 4.1 外部卡片确认

首版不做，见需求与设计 §3.6、附录 B。

### 4.2 反馈入口

没有反馈就没有采纳率，也就无法评估 AI 员工。反馈不能做成额外问卷，而是从用户本来就要做的动作里自然采集。反馈追加为 `ext_approval_execution` 的 `feedback` 条目（`accepted` / `edited` / `overruled`，差异写 `feedback_diff_json`），不单建反馈表，也不改已写入的行（需求与设计 §6 执行记录口径）。

| 入口 | 采集时机 | 写入 |
|---|---|---|
| 直接按建议提交 | 用户未修改动作和意见 | `feedback = accepted` |
| 弹窗内修改动作、参数或意见 | 提交时自动记录修改前后差异 | `feedback = edited`，差异写 `feedback_diff_json` |
| 选择与建议相反的动作（按 `kind` 判断：建议为 `approve` 而选 `reject` / `return`，或反之） | 弹出一行可选原因（依据不对 / 遗漏信息 / 制度理解有误 / 其他） | `feedback = overruled`，原因写 `feedback_diff_json`，可跳过 |
| 执行记录页的「这条建议准不准」 | 任务结束后可补打分（`POST …/executions/{executionId}/feedback`） | 追加一条 `feedback` 条目：`feedback_source = rating`、`feedback_rating`、可选原因写 `feedback_diff_json`；不改已有行 |
| 执行记录页「自动放行抽查」里的「标记误放行」 | 仅对 `approval_method = auto_rule` 的执行 | 追加一条 `feedback` 条目：`feedback_source = misrelease`、`feedback = overruled`；界面同时提示可一键暂停该流程的自动放行 |
| 外部结果与建议不一致 | 对账发现时自动记录 | 记在该执行行（外部结果）与任务行（`done` 原因码） |

反馈约束：只采集用户在本产品内的操作，未在桌面端确认就结束的任务不采集、不计入统计；原因选项必须可跳过，不能阻塞用户完成审批；反馈数据默认只在本地；采纳率统计不用于考核审批人，只用于评估规则和员工配置。

## 5. 流程绑定向导

普通用户只走前三步：连接平台插件、选择流程、选择 AI 员工。节点、处理策略、字段和附件范围由系统按 `describe()` 结果和流程模板预填，收在「高级设置」里默认折叠，用户不改也能保存绑定。

### 第一步：连接平台插件

列出已安装的平台插件（来自 `GET /api/agent/approvals/plugins`），每个插件一张卡片，卡片结构对所有插件相同。

每张卡片显示连接状态、授权身份、最近同步时间和 `describe()` 四项能力：

- `read`：可读取本人待办与详情 / 不可读取。
- `actions`：已验证可写回的动作列表（如「同意、拒绝、评论」）；为空时显示「仅分析，暂不可提交」。
- `attachments`：可按次读取附件 / 仅附件元信息。
- `push`：有推送 / 定时同步（只影响同步间隔）。

用户在这一步只做两件事：按插件 `authSteps` 完成扫码或登录授权，确认授权身份是自己。未验证的能力在能力卡片上不列出；任务详情里的对应动作仍显示，点击引导到原平台处理。

企业尚未完成应用配置或权限配置时，卡片显示「当前企业未完成配置」，并给出联系管理员或实施方的说明。普通用户路径不出现 Client ID、Client Secret、App ID、App Secret、EngineCode、EngineSecret 等平台凭据或编码字段。

### 第二步：选择流程

先加载插件可读取的流程模板（`GET …/bindings/{id}/templates`，插件 `listTemplates`，游标分页），只显示流程名称和所在分类。不要让用户直接输入 ID 作为默认方式。

选择后显示（`GET …/bindings/{id}/templates/{templateRef}`，插件 `getTemplate`）：

- 流程名称。
- 流程版本。
- 当前可识别节点。
- 字段和附件预览。
- 模板最后更新时间。

高级设置允许手动输入插件提供的流程引用（`templateRef`），用于插件未返回流程列表的例外情况；输入后同样调 `getTemplate` 预览，预览失败则不能保存。本步同时为流程选择企业已发布的规则集（来自 `GET …/policies`；只有一个匹配时自动预选，没有时提示「该流程暂无制度依据，AI 只能做形式检查」）。核心 UI 不出现平台字段名。

### 第三步：选择 AI 员工

显示当前本地已授权员工。每个员工卡片显示名称、职能、可用状态和已授权能力。流程绑定不能临时添加一个未加载的员工。

### 高级设置（默认折叠，系统预填）

以下四项由系统按 `describe()` 结果、流程模板和企业策略预填。用户展开修改后，该项显示「已自定义」标记。

1. 节点和外部身份：默认全部可匹配节点，外部身份固定为第一步授权的用户身份。如果插件只能以应用身份执行，`actions` 为空，绑定只能保存为只读分析模式。
2. 处理策略：默认「总是由我审核（`always_review`）」。当且仅当企业管控上限允许时才显示「有条件自动放行（`conditional_auto`）」选项；开启必须由用户本人按单条流程逐个勾选并通过二次同意弹窗，明确展示企业金额/动作上限、确定性规则+模型一致双闸门、高风险永不自动及离线超时（24h）自动降级人工的说明。开启后，审批页顶栏与托盘提供一键暂停开关，执行记录页提供「自动放行抽查」视图。
3. 字段与附件范围：默认只同步绑定白名单字段；附件默认按次授权（`on_demand`，仅展示元信息，正文需在详情页点「允许读取」），选 `always` 时提示附件正文会默认经过 Relay 与上游模型。`attachments` 为 false 时只能选 `never`。习惯类偏好保存在本地 User Prompt（只补充，不覆盖企业规则）；审批会话与预检会话不写任何记忆，记忆召回与知识库检索默认关闭。
4. 绑定版本号与治理知情：保存后生成绑定版本号供任务详情与审核弹窗比对；当企业开启治理摘要上报时，审批页顶栏常驻显示「企业已开启治理摘要上报」并可查看上报字段白名单。

### 确认

展示完整摘要：插件、流程、节点、外部身份、AI 员工、审核模式、动作白名单和数据范围。摘要必须包含一行「高级设置：使用系统默认 / 已自定义 N 项」，避免用户不知道自己改过什么。保存前可选「试运行」（`POST …/bindings` 带 dryRun），查看一条测试任务的分析结果。

## 6. 平台连接流程

连接分两条路径，界面上不能混在一起：

- 普通用户路径（桌面端「连接」页）：按插件 `authSteps` 完成本人授权（扫码或 OAuth 登录），确认授权身份，查看 `describe()` 自检结果。流程见 §1.2，对所有插件相同。
- 管理员 / 实施方路径：应用创建、凭据填写、事件订阅和权限申请，在第三方开放平台与企业侧完成，不在桌面端普通路径，普通用户不可见。凭据托管方与换票方式待定（需求与设计 §13 #12）；任何方案下不向员工桌面下发应用 Secret，管理界面不得回显完整 Secret。

授权的具体形式（扫码、OAuth 跳转、是否保留 refresh token）依赖平台应用形态，P0 用真实企业验证后由插件的 `authSteps` 表达，核心 UI 不改。任何在[需求与设计 §3.1.1](./2026-11-23-外部审批平台接入-需求与设计.md#311-平台能力实测p0-口径) 仍为「未验证」或「不通过」的能力，在 UI 中一律隐藏且不可开启（动作例外：仍显示，点击只提供「在原平台处理」）。

各插件候选接入方式见需求与设计附录 A，以下仅为插件说明（候选）。

### 6.1 钉钉插件说明（候选）

扫码 OAuth 确认本人身份；写回是否只能用应用凭据、事件如何按本人接收待 P0，可能经企业侧服务承接。未验证前只读分析。

### 6.2 氚云插件说明（候选）

经企业已配置的开放接口或已验证连接器读取；自定义接口能否保留真实操作人未验证。未验证前只提供任务提醒、AI 分析、在原平台打开和结果对账。

### 6.3 飞书插件说明（候选）

扫码 OAuth 换得本人 `user_access_token`；用户级写回、平台审计操作人与按用户接收事件待 P0。只有应用身份能读取时显示「可分析，暂不可提交」。

## 7. 桌面端常驻与通知

本节的常驻要求仅适用于采用本机长连接接收事件的插件（需求与设计 §7.5，接收方式待定 §13 #12）。其他插件依靠 Hub 定时调用 `listPending` 同步，常驻只影响到达及时性，不是功能前提；设置页只在已连接长连接插件时显示「常驻为该插件所需」的提示。

### 7.1 常驻与自启设置

设置项放在应用设置或「连接」页底部：

- 关闭窗口后继续运行（默认开启）。
- 开机自动启动（默认开启，首次开启前征得用户同意）。
- 允许后台分析（默认关闭；关闭时任务仍接收，分析等用户打开应用）。
- 系统通知开关，按新任务、需要审核、授权过期、执行失败、外部已处理分别可关。

关闭「关闭窗口后继续运行」或「开机自动启动」时，必须显示影响提示：任务不再实时到达，下次启动时补齐。不允许静默关闭。

### 7.2 托盘与角标

托盘或菜单栏图标常驻，显示待审核数量。菜单至少包含：

- 待审核任务数量和最近几条任务。
- 立即同步。
- 连接状态和最后同步时间。
- 打开主窗口。
- 退出。

角标数字只统计当前用户已启用绑定的待审核任务（`open` 且已有建议）。连接断开或授权过期时，图标必须显示降级状态，不能只靠数字表达。

### 7.3 系统通知

| 场景 | 通知内容 | 点击行为 |
|---|---|---|
| 新任务到达 | 平台、流程名称、任务标题 | 打开任务详情 |
| 分析完成需要审核 | 平台、流程名称、任务标题、风险级别（不含建议动作） | 打开任务详情 |
| 授权过期 | 平台 | 打开连接页 |
| 执行失败 | 平台、流程名称、任务标题、失败原因码的中文说明 | 打开执行记录 |
| 外部已处理 | 平台、流程名称、任务标题、关闭原因码的中文说明（如「已在原平台处理」） | 打开任务详情 |

通知内容不超出平台、流程名称、任务标题和风险级别（需求与设计 §7.5 约束 2）；「执行失败」「外部已处理」另带原因码的中文说明。不包含金额、附件名、申请人隐私字段、建议动作和 AI 建议正文。通知不提供「同意」「拒绝」快捷按钮。宿主由 `GET …/events` 状态推送触发通知。

### 7.4 唤醒与重连

系统唤醒、网络切换或授权恢复后，界面按以下顺序反馈：

1. 连接状态显示正在重连（长连接插件）或正在同步。
2. 任务列表显示正在补齐。
3. 对账完成后更新最近同步时间和角标。
4. 休眠期间已被外部处理的任务显示为 `done` 及原因，不再进入待审核。

连续重连或同步失败时，托盘和页面同时显示降级状态，并给出手动同步入口。

## 8. 执行状态和错误交互

| 场景 | 展示 | 用户动作 |
|---|---|---|
| 需要重新授权（`blocked` · `credential_expired`） | 红色状态和插件名称 | 重新授权 |
| 外部任务已被处理（`done`） | 灰色状态，显示外部最终结果 | 在原平台打开 |
| 外部任务处理人或版本变化（`stale`） | 黄色冲突提示 | 重新查看 |
| 模板字段变化 | 任务置 `stale`；插件暂时无法识别时为 `blocked`（`mapping_unknown`） | 重新查看；等待插件更新后重新同步 |
| 连接降级（事件 `connection_degraded`，任务状态不变） | 黄色提示，显示最近成功同步时间和下次同步时间 | 立即同步 |
| 写操作权限不足（`blocked` · `capability_missing`） | 红色错误，显示当前身份，动作按钮仍显示，点击只提供「在原平台处理」 | 重新授权或联系管理员 |
| 网络断开 | 连接断开和最后同步时间 | 重连、立即对账 |
| 附件不可读取 | 单个附件显示原因 | 跳过附件或在原平台打开 |
| 重复执行保护 | 显示已有执行记录 | 查看执行结果 |
| 写回结果未知（`executing` · `result_unknown`） | 「结果待对账」，不提供重试 | 立即同步 |
| 平台状态无法识别（`blocked` · `mapping_unknown`） | 「状态无法识别」和暂停原因 | 查看插件诊断、等待插件更新后重新同步 |

错误详情不显示 Secret、Token、平台原始字段、原始响应中的隐私字段或完整附件 URL。

## 9. UI 验证清单

### 9.1 交互验证

- 普通用户向导能三步完成：连接插件、选流程、选员工；不展开高级设置也能保存绑定。
- 接入第二个（fake）插件时 UI 无需新增页面或分支：连接页、流程绑定、任务列表与详情、确认弹窗都只靠 `describe()` / `authSteps` 渲染。
- 连接卡片只显示 `describe()` 四项能力；`describe().actions` 未列出的动作按钮仍显示，点击只打开「在原平台处理」，不进入确认弹窗；`actions` 为空时只能保存为只读分析模式。
- 普通用户路径任何页面都不出现平台凭据或编码字段（Client ID、Secret、EngineCode、平台流程编码等）。
- 采用长连接的插件：关闭主窗口后仍能收到新任务通知，托盘角标同步更新；非长连接插件按定时同步补齐。
- 关闭常驻或开机自启时显示影响提示，不是静默生效。
- 系统休眠唤醒和网络切换后连接恢复，且补齐休眠期间的任务。
- 通知不包含金额、附件名、建议动作和 AI 建议正文，也没有直接审批按钮。
- 托盘角标数量与任务列表的待审核数量一致。
- 高级设置展开并修改后，确认页显示「已自定义 N 项」。
- 每条建议理由都带可点来源标签，点字段标签能高亮左栏字段，点附件标签能跳到对应页，点制度标签能定位条款，点历史先例能打开对应已完成任务。
- 制度未装载时显示「该流程暂无制度依据」条带，入口能跳到制度与规则页（只读）。
- 存在阻塞类缺失材料时：详情操作区出现「退回补件」按钮（按 `return` → `comment` → 在原平台处理的顺序取动作）；从同意类按钮打开的弹窗在勾选「我已知材料缺失」前不可提交、勾选后可提交；弹窗内没有动作切换、不默认改选。
- 高风险动作提交时弹出系统原生确认框，内容与待确认记录一致；在原生框取消不产生外部写操作；普通动作不弹原生框。
- 弹窗打开期间任务快照或建议更新后提交，返回 409 并提示重新查看；「无建议」时打开弹窗、期间生成了建议，同样被拒绝。
- 「暂不处理」后任务沉底、不计入角标，到期自动恢复；执行记录页能补打分、自动放行抽查能标记误放行，且已有执行条目不被修改。
- 制度与规则页、绑定向导流程预览、治理摘要知情条的数据都来自需求与设计 §10.2 对照表列出的接口。
- 修改建议动作或意见后提交，能在执行记录里看到修改前后差异（`feedback_diff_json`）。
- 选择与建议相反的动作时出现原因选项，且跳过后仍能完成审批。
- 确认经宿主一次性确认完成；WebView 与本地 HTTP 拿不到确认票据，`POST …/decision` 单独调用不产生外部写操作。
- 任务列表能够打开详情、按主状态 / 原因码 / 插件筛选、分页和刷新；展示态（分析中、已有建议）由前端推导。
- AI 员工能够从详情页启动分析并显示进度。
- 任务详情能够打开本地审批群聊，用户可以发送消息、@固定参与者并看到流式回复；群聊里输入「同意」只提示去详情发起确认。
- 任务 `stale` / `done` / `blocked` 时群聊切换为只读。
- 审核弹窗能够编辑意见、取消和确认。
- 外部任务在确认前发生变化时，提交被阻止，任务置 `stale`。
- 插件返回无法识别的状态时，任务显示 `blocked`（状态无法识别）和「查看插件诊断」，提交按钮被阻止。
- 重复点击提交不会产生第二次外部写操作；结果未知时只能对账，不出现重试按钮。
- 连接断开、重连、授权过期和同步失败都能恢复。
- 同一个用户配置三条流程并分配给两个 AI 员工时，任务路由不串线。

### 9.2 视觉和可用性验证

- 使用多条任务、长表单、长建议和多个附件测试。
- 使用 1440×640 小窗口测试。
- 主操作按钮在可视区可点击，使用 `elementFromPoint` 检查真实命中。
- 中间内容能滚动到底部，底部操作区不被内容覆盖。
- 短内容不产生异常空白。
- 弹窗使用组件库推荐的固定结构（`Dialog` 下直接放默认 `height="fill"` 的 `Layout`，header/content/footer 分开），并保留结构守卫测试。
- 键盘可以进入列表、详情、弹窗和确认按钮。
- 弹窗关闭后焦点回到触发控件。
- 屏幕阅读器可以识别插件、状态、风险和主操作。
- 颜色不是状态的唯一表达方式。

## 10. 文案口径

- 「AI 员工建议」表示分析结果。
- 「确认并提交」表示用户同意调用第三方写接口。
- 「当前身份」表示第三方平台最终记录的操作人。
- 「需要审核」表示暂不调用第三方写接口。
- 「外部已处理」表示第三方平台已改变任务状态。
- 「同步」表示读取第三方最新状态，不表示执行审批。
- 「仅分析，暂不可提交」表示当前插件未验证任何可写回动作。
- 「结果待对账」表示写回结果暂不可确认，系统会按外部状态判断是否生效，不表示失败。

- 页面必须明确提示：AI 员工只提交建议；写操作由本人确认，或由本人开启的有条件自动放行规则触发，并使用本人在第三方平台的身份（执行身份待实测）。
- 首版没有外部机器人与卡片确认（需求与设计 §3.6），审批原文、附件和内部 Pi Session 不回传外部群聊。

## 11. 提交前预检（申请人侧）

范围与规则见[需求与设计](./2026-11-23-外部审批平台接入-需求与设计.md) §16。入口是「外部审批」的第 6 个页签「提交前预检」，不要求完成平台授权。

### 11.1 页面结构

| 区域 | 内容 |
|---|---|
| 记录列表 | 流程名称、更新时间、结果状态；可新建、打开、删除 |
| 左栏：我的材料 | 选择流程与 AI 员工、附件、提取并经本人核对的字段 |
| 右栏：检查结果 | 状态、问题项（说明、依据标签、修改建议）、所用规则版本 |

### 11.2 状态与动作

| 状态 | 展示 | 可用动作 |
|---|---|---|
| 未开始 | 说明需要哪些材料 | 放入附件、填写字段、开始检查 |
| 检查中 | 进度 | 取消 |
| 需补充或调整 | 阻塞项置顶 | 修改后重新检查、复制清单 |
| 无法判断 | 缺什么导致无法判断（规则未装载、字段不足、附件读不到） | 补充后重新检查 |
| 有提示项 | 提示项列表 | 修改、复制清单 |
| 未发现阻塞项 | 「按已装载规则未发现阻塞项」 | 复制清单 |
| 已过期 | 说明输入或规则已变化 | 重新检查 |
| 分析失败 | 失败原因 | 重试 |

页面固定提示「结果仅供提交前自查，不代表审批结论，请到原平台提交」。页面没有提交、同意或拒绝按钮。

### 11.3 验证

- 多问题项、长字段、多附件在 1440×640 窗口下可滚动到底，主按钮用 `elementFromPoint` 验证可点击；短内容不撑出空白。
- 键盘可完成放附件、改字段、开始检查；状态不只用颜色表达。
