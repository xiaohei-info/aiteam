# 外部审批平台接入 UI 交互方案

> 关联设计：[需求与设计](./2026-11-23-外部审批平台接入-需求与设计.md)  
> UI 是信息结构方案，不是最终视觉稿。实现时沿用桌面端现有设置页、Dialog、列表、Toast 和错误模型。

## 1. 信息架构

在桌面端新增「外部审批」入口，包含六个页面或页签（第 6 个供申请人使用）：

1. **审批任务**：查看待分析、待审核、执行中、已完成和失败任务。
2. **流程绑定**：把外部流程、节点和当前用户绑定到 AI 员工。
3. **平台连接**：配置钉钉、氚云、飞书账号和用户身份。
4. **制度与规则**：上传制度文件、维护金额阈值和必需材料清单，对应 `approval_policy`。
5. **执行记录**：查看建议、审核、第三方执行、失败重试和采纳反馈记录。

6. **提交前预检**：申请人在原平台提交前检查自己的材料，见 §11。

「制度与规则」页面对应需求与设计 §2.4 的责任主体划分，由企业管理员或流程负责人维护，普通审批人只读。没有它，AI 建议就没有制度依据，只能输出「未找到可用制度依据」。

### 1.1 制度与规则页面

| 区块 | 内容 | 权限 |
|---|---|---|
| 制度文件列表 | 文件名、适用流程范围、版本、生效时间、装载状态 | 管理员可上传替换，成员只读 |
| 规则清单 | 按流程模板分组展示金额分档、必需材料、高风险条件和建议意见模板 | 管理员可编辑 |
| 行业模板 | 运营内置的费用报销、采购申请等模板，一键引入后可改 | 管理员选择 |
| 装载状态提示 | 未装载制度的流程绑定显示「该流程暂无制度依据，AI 只能做形式检查」 | 全员可见 |

流程绑定向导和任务详情都要提供进入该页的入口。制度文件更新生成新版本，旧版本生成的建议失效并要求重新分析。

页面顶部展示连接状态摘要：

- 已连接平台数量。
- 待审核任务数量。
- 需要重新授权数量。
- 最近同步时间。
- 离线或对账状态。

### 1.2 首次接入和日常使用的分界

产品必须把“企业首次接入”和“普通用户使用”拆开。普通用户不应进入平台开发者后台，也不应填写 API、Secret、流程编码或节点编码。平台首次接入由企业管理员（可由实施方代办）在第三方开放平台创建企业自建应用，并在企业侧 Manager 配置凭据；员工本人授权的具体形式以 P0 验证结果为准。

```text
企业首次接入
授权平台应用 → 权限自检 → 读取流程目录 → 配置默认规则
                                      ↓
普通用户使用
扫码确认身份 → 选择流程 → 选择 AI 员工 → 查看测试结果 → 开启绑定
                                      ↓
日常处理
任务自动到达 → AI 自动分析 → 用户确认 → 平台执行 → 结果同步
```

### 钉钉接入流程

```text
选择钉钉
  ↓
扫码授权本企业自建应用（管理员已配置）
  ↓
系统检查审批读取、任务处理、应用可见范围和 Stream 状态
  ↓
自动读取可用审批流程和节点
  ↓
用户扫码确认自己的钉钉身份
  ↓
选择流程与 AI 员工
  ↓
执行只读测试，随后用测试任务验证写权限
  ↓
开启“分析提醒”或“确认后执行”
```

用户看到的是应用授权、流程名称和员工选择。`Client ID`、`Client Secret`、`processCode` 和 Stream 订阅属于企业管理员或实施方的配置界面，不能作为普通用户入口。应用市场安装不在 v1 范围；企业尚未配置应用时显示「当前企业未完成配置」。

### 飞书接入流程

```text
选择飞书
  ↓
扫码授权本企业自建应用（管理员已配置）
  ↓
系统检查审批权限、用户身份范围和长连接状态
  ↓
自动读取可用审批定义和节点
  ↓
用户完成飞书身份授权
  ↓
选择流程与 AI 员工
  ↓
用测试任务校验当前用户能否执行
  ↓
开启绑定，后续由长连接发现任务并在重连时对账
```

如果连接只能读取审批而不能使用当前用户身份执行，状态显示“可分析，暂不可提交”，用户仍可以使用分析、提醒和打开飞书处理。应用权限、用户授权和审批事件范围需要 P0 通过后才能显示为可执行。

### 氚云接入流程

```text
选择氚云
  ↓
使用企业已配置的接入方式（开放接口或已验证连接器）
  ↓
系统检查应用、表单、待办和工作项读取能力
  ↓
用户确认氚云身份与当前处理人
  ↓
选择流程与 AI 员工
  ↓
先开启“任务提醒与 AI 分析”
  ↓
真实操作人审计通过后，才显示同意、拒绝和转交
```

当前公开资料尚未证明任意第三方桌面客户端可以直接使用氚云连接器 MCP，也未确认自定义接口能够保留真实操作人。普通用户不应自行输入 `EngineCode`、`EngineSecret`、自定义接口地址或编写接口代码。未完成验证时，氚云只开放任务提醒、AI 分析、打开氚云和结果对账。

所有平台的接入完成页都要显示：授权身份、可读取流程、任务发现方式、当前用户级写权限、支持动作、最近同步时间和修复入口。只读自检通过时可以保存绑定，但不能显示“审批可执行”。

### 1.3 业务触发事件入口

用户不需要理解内部事件名称，但界面必须让事件产生的结果可追踪。

| 用户场景 | 内部触发事件 | 界面反馈 |
|---|---|---|
| 外部平台出现待办 | `task_received` | 新任务通知、进入待分析 |
| 表单或处理人发生变化 | `task_changed`、`task_transferred` | 建议失效、要求重新同步 |
| AI 员工完成分析 | `analysis_completed` | 显示建议、风险和依据 |
| 用户从群聊生成审核单 | `review_requested` | 显示待审核卡片 |
| 用户确认动作 | `review_confirmed` | 显示执行前校验 |
| 外部平台已经处理 | `task_completed_externally` | 关闭本地执行按钮，显示外部结果 |
| 外部 API 返回成功 | `execution_accepted` | 显示已提交，等待最终状态 |
| 外部状态确认完成 | `execution_confirmed` | 显示执行成功和审计记录 |
| 授权、网络或权限异常 | `credential_expired`、`sync_failed`、`permission_changed` | 显示修复入口，禁止误执行 |
| 用户修改 AI 建议 | `proposal_edited` | 保存修改前后差异，用于反馈统计 |

## 2. 任务列表

### 2.1 列表结构

每个任务卡片包含：

- 平台标识和流程名称。
- 申请标题和摘要。
- 当前节点。
- 申请人和当前外部处理人。
- 分配的 AI 员工。
- 风险标签。
- 本地状态和外部状态。
- 外部截止时间。
- 最近同步时间。
- 主操作。

主操作按状态显示：

| 本地状态 | 主操作 | 次操作 |
|---|---|---|
| 待分析 | 让员工分析 | 查看详情、在群聊讨论、暂停 |
| 分析中 | 查看进度 | 停止分析、打开群聊 |
| 待审核 | 审核建议 | 重新分析、查看详情 |
| 执行前状态过期 | 重新同步 | 查看变化 |
| 执行中 | 查看执行状态 | 刷新 |
| 执行成功 | 查看记录 | 打开第三方详情 |
| 执行失败 | 重试 | 查看错误、重新同步 |
| 外部已处理 | 查看记录 | 关闭本地任务 |
| 外部状态无法识别 | 查看平台状态 | 查看诊断、等待 Adapter 更新 |

列表中的「本地状态」只使用 `ApprovalTaskState` 的中文标签。平台原始状态作为次级信息展示，例如「统一状态：待审核 · 平台状态：PENDING」，未知或歧义值显示「平台状态无法识别」，禁止继续执行。

### 2.2 筛选

筛选项：

- 平台。
- 流程绑定。
- AI 员工。
- 风险等级。
- 本地状态。
- 外部状态。
- 时间范围。
- 是否需要用户处理。

筛选条件应写入 URL 或本地页面状态，刷新后能够恢复。列表使用游标分页，不能一次加载所有历史审批。

### 2.3 空状态

- 没有平台连接时，显示「先连接一个审批平台」和「添加平台」按钮。
- 有平台但没有流程绑定时，显示「先选择一个流程交给员工处理」和「新建流程绑定」按钮。
- 有绑定但没有任务时，显示最近同步时间和「立即同步」按钮。
- 同步失败时显示失败原因、最近成功同步时间和「重试同步」按钮。

## 3. 任务详情

任务详情采用两栏结构。

### 左栏：外部审批内容

- 平台、流程、实例和节点信息。
- 申请人、当前处理人、提交时间和截止时间。
- 绑定版本。
- 字段白名单内的表单字段。
- 允许读取的附件列表。
- 外部流程时间线。
- 「在钉钉 / 氚云 / 飞书打开」链接。

### 右栏：AI 员工建议

- AI 员工名称和头像。
- 建议动作。
- 风险等级。
- 建议理由。每条理由后跟一个来源标签，展示见 §3.1。
- 引用的字段和附件。
- 命中的风险规则名称和所属制度文件版本。
- 缺失材料清单，阻塞项单独标记。
- 置信度，低于中等时显示「依据不足，建议人工复核」。
- 建议审批意见。
- 是否建议人工审核。
- 分析时间和模型信息摘要。
- 本地统一状态和平台原始状态的映射结果。
- 映射版本、最近观测时间和 Adapter 版本。
- 映射失败原因，包含未知值、歧义值或当前账号不支持。
- 当前能力声明允许的动作，以及被禁用动作的原因。
- 「在群聊中讨论」入口和当前本地审批群聊状态。

右栏底部使用固定操作区：

- `同意并执行`
- `拒绝并执行`
- `需要人工复核`
- `重新分析`
- `暂不处理`

操作区在 1440×640 小窗口中必须保持可见，表单和建议内容在中间区域滚动。长文本和多附件不能把按钮推到窗口外。

### 3.1 建议依据的展示

用户要能当场判断「这条理由是从哪里来的」，否则建议只是一段无法校验的文本。每条理由都渲染为「理由文本 + 来源标签」，来源标签来自 `evidence_json.reasons[].citation`。

| citation 类型 | 标签文案 | 点击行为 |
|---|---|---|
| `form.<field>` | 字段名，如「报销金额」 | 滚动并高亮左栅对应字段 |
| `attachment:<name>#p<n>` | 文件名 + 页码，如「报价单.pdf · P2」 | 打开附件预览并跳到该页 |
| `policy:<doc>#<条>` | 制度名 + 条号，如「差旅管理办法 · 3.2」 | 打开制度文件并定位条款 |
| `local:approval_outcome#<id>` | 「历史先例」 | 打开该历史任务的结果记录 |

展示约束：

1. 没有可解析 citation 的理由不展示。不得用「模型分析」这类空标签充数。
2. 来源标签必须可点。点不动的标签等于没有依据，属于缺陷。
3. 附件未授权读取内容时，标签显示「仅文件名」并置灰，不假装已读过正文。
4. 制度未装载时，右栅顶部显示「该流程暂无制度依据」条带和「去配置」入口，指向制度与规则页。
5. 制度文件版本或任务快照版本变化后，整个依据区置灰并提示「依据已过期，请重新分析」。

### 3.2 群聊讨论

任务详情提供「在群聊中讨论」入口，打开或创建与当前任务绑定的 AIFred 本地群聊。群聊固定显示任务上下文条和参与员工，不把外部平台 Secret 或完整原始响应放入消息。

群聊界面包含：

- 任务上下文条，显示平台、流程、节点、统一状态、映射版本和最近同步时间。
- 参与者列表，显示负责员工、协调员工和已授权的财务/风控员工。参与者来自固定 roster，不能在消息框中临时加入未授权员工。
- 消息时间线，区分用户、AI 员工和系统状态消息。AI 员工回复显示来源员工和所引用的字段。
- 输入框支持文本、字段引用和 `@` 已有参与者。发送消息只触发本地群聊投递，不调用第三方写接口。
- 建议卡片，展示建议动作、风险、证据和「生成审核单」按钮。生成审核单后仍需用户在 Review Gate 确认。
- 外部机器人入口。用户可以把脱敏摘要发送回已绑定的钉钉或飞书群，或在外部群 `@审批助手` 后回到本地群聊继续分析。

用户在群聊中输入「同意」「拒绝」等自然语言时，界面显示待确认的审核卡片，不把文字当成外部执行授权。任务进入 `stale`、`mapping_failed`、`canceled` 或 `expired` 后，群聊保留历史并切换为只读。

## 4. 审核确认弹窗

点击 `同意并执行` 或 `拒绝并执行` 后打开确认弹窗。

弹窗内容：

1. 外部平台和流程实例。
2. 当前用户外部身份。
3. 即将执行的动作。
4. AI 员工建议和风险等级。
5. 审批意见编辑框。
6. 影响提示。
7. 当前外部状态的最后同步时间。

确认按钮文案必须包含动作，例如「确认同意并提交」，不能使用没有业务含义的「确定」。

弹窗在提交前重新请求任务状态。状态、处理人、节点或版本发生变化时，弹窗切换为冲突状态并阻止提交。

高风险动作需要额外输入确认词，或使用二次确认按钮。风险规则由流程绑定决定，界面显示具体命中规则。

弹窗还要显示两组阻塞信息：

- `missing_items.blocking = true` 时，默认选中「需要补充材料」，「确认同意并提交」置灰，并列出缺什么、为什么缺。用户坚持同意时必须先显式勾选「我已知材料缺失」。
- `confidence` 低于中等时，顶部显示「依据不足，建议人工复核」，不自动禁用提交，但默认焦点落在「需要人工复核」。

### 4.1 外部卡片确认的三个硬条件

用户也可以在钉钉或飞书群的卡片上直接点「同意」。这条路径绕过了桌面端弹窗，所以只有三个硬条件同时成立时才算用户确认（定义见需求与设计 §3.6.1）。界面必须把校验结果回到卡片上，不能静默失败。

| 硬条件 | 通过时卡片表现 | 失败时卡片表现 |
|---|---|---|
| 真实点击人 = 当前处理人 | 继续执行，卡片更新为「已提交，等待平台确认」 | 卡片回复「该任务不由你处理」，不展示任务内容 |
| 外部状态未变 | 同上 | 卡片更新为「任务已变化，请打开 AIFred 重新确认」，按钮置灰 |
| 授权可留痕 | 同上 | 卡片更新为「当前连接不能执行用户级审批」，引导重新授权 |

高风险动作即使三条全通过也不在卡片完成，卡片只提供「打开 AIFred 确认」。卡片上永远不出现金额、附件名和建议正文。

### 4.2 反馈入口

没有反馈就没有采纳率，也就无法评估 AI 员工。反馈不能做成额外问卷，而是从用户本来就要做的动作里自然采集。

| 入口 | 采集时机 | 写入 |
|---|---|---|
| 直接按建议提交 | 用户未修改动作和意见 | `proposal_accepted` |
| 弹窗内修改动作或意见 | 提交时自动记录修改前后差异 | `proposal_edited`，含 `before_json` / `after_json` |
| 选择与建议相反的动作 | 弹出一行可选原因（依据不对 / 遗漏信息 / 制度理解有误 / 其他） | `proposal_overruled`，原因可跳过 |
| 执行记录页的「这条建议准不准」 | 任务结束后可补打分 | 补充写入 `approval_feedback` |
| 外部结果与建议不一致 | 对账发现时自动记录 | `approval_outcome` |

反馈约束：原因选项必须可跳过，不能阻塞用户完成审批；反馈数据默认只在本地；采纳率统计不用于考核审批人，只用于评估规则和员工配置。

## 5. 流程绑定向导

普通用户只走前三步：授权账号、选择流程、选择 AI 员工。节点、处理策略、字段和附件范围由系统按平台能力和流程模板预填，收在「高级设置」里默认折叠，用户不改也能保存绑定。

### 第一步：授权平台账号

显示三种平台卡片：

- 钉钉
- 氚云
- 飞书

每张卡片显示连接状态、授权身份、最近同步时间、能力状态和映射版本。用户在这一步只做两件事：完成扫码或登录授权，确认授权身份是自己。

能力状态至少区分「可读取」「可分析」「可提交建议」「可执行同意」「可执行拒绝」「可接收 @机器人」和「可发送交互卡片」。能力未验证时不显示对应动作。

企业尚未完成应用配置或权限配置时，卡片显示「当前企业未完成配置」，并给出联系管理员或实施方的说明。普通用户路径不出现 Client ID、Client Secret、App ID、App Secret、EngineCode、EngineSecret。

### 第二步：选择流程

先加载平台可读取的流程模板，只显示流程名称和所在分类。不要让用户直接输入 ID 作为默认方式。

选择后显示：

- 流程名称。
- 流程版本。
- 当前可识别节点。
- 字段和附件预览。
- 模板最后更新时间。

高级设置允许输入 `processCode`、`SchemaCode` 或 `approval_code`，用于平台未返回流程列表的例外情况。

### 第三步：选择 AI 员工

显示当前本地已授权员工。每个员工卡片显示名称、职能、可用状态和已授权能力。流程绑定不能临时添加一个未加载的员工。

### 高级设置（默认折叠，系统预填）

以下四项由系统按平台能力、流程模板和企业策略预填。用户展开修改后，该项显示「已自定义」标记。

1. 节点和外部身份：默认全部可匹配节点，外部身份固定为第一步授权的用户身份。如果平台只返回应用身份，显示「当前连接不能执行用户级审批」，阻止保存绑定。
2. 处理策略：默认「总是由我审核（`always_review`）」。当且仅当企业管控上限允许时才显示「有条件自动放行（`conditional_auto`）」选项；开启必须由用户本人按单条流程逐个勾选并通过二次同意弹窗，明确展示企业金额/动作上限、确定性规则+模型一致双闸门、高风险永不自动及离线超时（24h）自动降级人工的说明。开启后，审批页顶栏与托盘提供一键暂停开关，执行记录页提供「自动放行抽查」视图。
3. 字段、附件与记忆范围：默认只同步绑定白名单字段；附件默认按次授权（`on_demand`，仅展示元信息，正文需在详情页点「允许读取」），选 `always` 时给出仅建议用于私有化内网模型的风险提示。习惯类偏好保存在本地 User Prompt；向导须显式提示：**「员工长期记忆（Hindsight）保存在企业侧 Manager，不是只在这台电脑上；审批表单正文与附件严禁写入记忆，仅脱敏后的跨任务经验摘要可写入。」**
4. 绑定版本号与治理知情：保存后生成绑定版本号供任务详情与审核弹窗比对；当企业开启治理摘要上报时，审批页顶栏常驻显示「企业已开启治理摘要上报」并可查看上报字段白名单。

### 确认

展示完整摘要：平台、流程、节点、外部身份、AI 员工、审核模式、动作白名单和数据范围。摘要必须包含一行「高级设置：使用系统默认 / 已自定义 N 项」，避免用户不知道自己改过什么。

## 6. 平台连接流程

连接分两条路径，界面上不能混在一起：

- 普通用户路径：只做平台账号授权（扫码或 OAuth 登录）并确认授权身份。
- 实施方路径：应用创建、凭据填写、事件订阅和权限申请，属于企业管理员或实施方，入口在「企业连接配置」，普通用户不可见。

三条普通用户授权路径的具体形式（扫码、OAuth 跳转、是否保留 refresh token）都依赖平台应用形态，必须在 P0 用真实企业验证后才能定稿。

### 6.1 钉钉

普通用户：

1. 点击钉钉卡片，使用钉钉扫码或跳转授权。
2. 确认返回的身份是本人，保存用户 token 引用。
3. 显示可读取的流程列表。

实施方（企业侧 Manager 后台配置，不在桌面端普通路径；若由平台方实施代录 Secret，交付验收时须由企业重置/改写一次，见 `09-部署分发与入户绑定.md` §14.4）：

1. 在企业侧 Manager 录入企业自建应用的 Client ID 和 Client Secret（加密存储于租户空间，不向员工桌面端分发静态应用 Secret；换票/续期时 Manager 瞬时经手但不持久化用户级 Token，并记录成员可查的换票审计）。
2. 测试应用凭据与 OAuth 换票通道。
3. 配置 Stream 订阅与权限范围。
4. 绑定企业策略上限（允许自动放行范围、紧急禁用开关、治理摘要开关）。
5. 显示实例和任务读写权限。
6. 用测试任务验证读取和用户级执行权限。

界面不得把 Secret 回显为完整文本。重新编辑只显示末尾四位；员工桌面端本地加密 Vault 只保存本人换票得到的用户级 Token。

### 6.2 氚云

普通用户：

1. 点击氚云卡片，使用氚云账号登录授权。
2. 确认返回的身份是本人。
3. 显示可读取的流程和表单。

用户级授权形式尚未验证。写入操作能力验证通过前，氚云普通用户路径只开放任务提醒、AI 分析和打开氚云处理。

实施方（企业侧 Manager 后台配置）：

1. 在企业侧 Manager 录入 EngineCode 和 EngineSecret（加密存储，不向普通员工桌面端分发）。
2. 选择氚云应用和表单。
3. 配置自定义接口地址或官方 OpenAPI 模式。
4. 测试业务对象读取。
5. 测试工作项读取。
6. 测试当前用户工作项完成能力。
7. 未通过真实用户校验时，连接状态显示「仅可读取」。

### 6.3 飞书

普通用户：

1. 点击飞书卡片，跳转飞书 OAuth 授权（经企业 Manager 代换本人 `user_access_token` 落本机加密 Vault）。
2. 确认返回的身份是本人，保存 user token 引用。
3. 显示可读取的审批定义列表。

实施方（企业侧 Manager 后台配置）：

1. 在企业侧 Manager 录入企业自建应用的 App ID 和 App Secret（加密存储，不向员工桌面端分发静态应用 Secret）。
2. 测试 OAuth 换票与长连接权限范围。
3. 读取审批定义和审批权限。
4. 订阅选定的审批定义事件。
5. 用测试任务验证当前用户可以执行。

长连接断开时，连接卡片显示重连状态和最后收到事件时间。单纯连接成功不能显示「审批可执行」；任何在 [需求与设计 §3.1.1](./2026-11-23-外部审批平台接入-需求与设计.md#311-三平台能力实测矩阵p0-验证口径) 仍标注为「未验证」或「不通过」的平台能力，在 UI 中一律隐藏且不可开启。

## 7. 桌面端常驻与通知

任务实时到达依赖桌面端常驻。这一组能力是功能要求，不是可选设置。

### 7.1 常驻与自启设置

设置项放在应用设置或「平台连接」页底部：

- 关闭窗口后继续运行（默认开启）。
- 开机自动启动（默认开启，首次开启前征得用户同意）。
- 允许后台分析（默认关闭；关闭时任务仍接收，分析等用户打开应用）。
- 系统通知开关，按新任务、需要审核、授权过期、执行失败、外部已处理分别可关。

关闭「关闭窗口后继续运行」或「开机自动启动」时，必须显示影响提示：任务不再实时到达，下次启动时补齐。不允许静默关闭。

### 7.2 托盘与角标

托盘或菜单栏图标常驻，显示待审核数量。菜单至少包含：

- 待审核任务数量和最近几条任务。
- 立即同步。
- 连接状态和最后同步时间。
- 打开主窗口。
- 退出。

角标数字只统计当前用户已启用绑定的待审核任务。连接断开或授权过期时，图标必须显示降级状态，不能只靠数字表达。

### 7.3 系统通知

| 场景 | 通知内容 | 点击行为 |
|---|---|---|
| 新任务到达 | 平台、流程名称、任务标题 | 打开任务详情 |
| 分析完成需要审核 | 流程名称、建议动作、风险级别 | 打开任务详情 |
| 授权过期 | 平台名称 | 打开平台连接 |
| 执行失败 | 流程名称、失败原因摘要 | 打开执行记录 |
| 外部已处理 | 流程名称、外部最终结果 | 打开任务详情 |

通知不包含金额、附件名、申请人隐私字段和 AI 建议正文。通知不提供「同意」「拒绝」快捷按钮。

### 7.4 唤醒与重连

系统唤醒、网络切换或授权恢复后，界面按以下顺序反馈：

1. 连接状态显示正在重连。
2. 任务列表显示正在补齐。
3. 对账完成后更新最近同步时间和角标。
4. 休眠期间已被外部处理的任务显示外部最终结果，不再进入待审核。

连续重连失败时，托盘和页面同时显示降级状态，并给出手动同步入口。

## 8. 执行状态和错误交互

| 场景 | 展示 | 用户动作 |
|---|---|---|
| 需要重新授权 | 红色状态和平台名称 | 重新授权 |
| 外部任务已被处理 | 灰色状态，显示外部最终结果 | 查看外部记录 |
| 外部任务处理人变化 | 黄色冲突提示 | 重新同步并重新绑定 |
| 模板字段变化 | 黄色版本不匹配 | 更新字段映射 |
| 平台限流 | 黄色等待提示，显示下次重试时间 | 查看队列 |
| 写操作权限不足 | 红色错误，显示当前身份 | 切换身份或联系管理员 |
| 网络断开 | 连接断开和最后同步时间 | 重连、立即对账 |
| 附件不可读取 | 单个附件显示原因 | 跳过附件或打开第三方 |
| 重复执行保护 | 显示已有执行记录 | 查看执行结果 |
| 平台状态无法识别 | 显示原始状态摘要、映射版本和暂停原因 | 查看诊断、等待更新后重新同步 |

错误详情不显示 Secret、Token、原始响应中的隐私字段或完整附件 URL。

## 9. UI 验证清单

### 9.1 交互验证

- 普通用户向导能三步完成：授权账号、选流程、选员工；不展开高级设置也能保存绑定。
- 关闭主窗口后仍能收到新任务通知，托盘角标同步更新。
- 关闭常驻或开机自启时显示影响提示，不是静默生效。
- 系统休眠唤醒和网络切换后连接恢复，且补齐休眠期间的任务。
- 通知不包含金额、附件名和 AI 建议正文，也没有直接审批按钮。
- 托盘角标数量与任务列表的待审核数量一致。
- 高级设置展开并修改后，确认页显示「已自定义 N 项」。
- 每条建议理由都带可点来源标签，点字段标签能高亮左栅字段，点附件标签能跳到对应页，点制度标签能定位条款。
- 制度未装载时显示「该流程暂无制度依据」条带，「去配置」能跳到制度与规则页。
- 存在阻塞类缺失材料时，弹窗默认选中「需要补充材料」且同意按钮置灰，勾选知悉后才可继续。
- 修改建议动作或意见后提交，能在执行记录里看到修改前后差异。
- 选择与建议相反的动作时出现原因选项，且跳过后仍能完成审批。
- 外部卡片由非处理人点击时被拒绝，卡片不泄露任务内容；外部状态已变时卡片降级为「打开 AIFred 确认」。
- 任务列表能够打开详情、筛选、分页和刷新。
- AI 员工能够从详情页启动分析并显示进度。
- 任务详情能够打开本地审批群聊，用户可以发送消息、@固定参与者并看到流式回复。
- 审核弹窗能够编辑意见、取消和确认。
- 外部任务在确认前发生变化时，提交按钮被阻止。
- 平台状态未知或歧义时，任务显示映射失败，提交按钮被阻止。
- 重复点击提交不会产生第二次外部写操作。
- 连接断开、重连、授权过期和限流都能恢复。
- 同一个用户配置三条流程并分配给两个 AI 员工时，任务路由不串线。
- 外部群聊 `@审批助手` 的重复消息只产生一次本地分析，脱敏回复和卡片状态可追踪。

### 9.2 视觉和可用性验证

- 使用多条任务、长表单、长建议和多个附件测试。
- 使用 1440×640 小窗口测试。
- 主操作按钮在可视区可点击，使用 `elementFromPoint` 检查真实命中。
- 中间内容能滚动到底部，底部操作区不被内容覆盖。
- 短内容不产生异常空白。
- 键盘可以进入列表、详情、弹窗和确认按钮。
- 弹窗关闭后焦点回到触发控件。
- 屏幕阅读器可以识别平台、状态、风险和主操作。
- 颜色不是状态的唯一表达方式。

## 10. 文案口径

- 「AI 员工建议」表示分析结果。
- 「确认并提交」表示用户同意调用第三方写接口。
- 「当前身份」表示第三方平台最终记录的操作人。
- 「需要审核」表示暂不调用第三方写接口。
- 「外部已处理」表示第三方平台已改变任务状态。
- 「同步」表示读取第三方最新状态，不表示执行审批。

- 页面必须明确提示：AI 员工不会直接完成审批，最终动作使用当前用户在第三方平台的身份。
- 外部机器人消息是触达与确认入口，完整审批原文、附件和内部 Pi Session 不回传外部群聊。
- 卡片上的「同意」表示用户确认，但它是有条件的：只有三条硬条件全通过才会提交，否则卡片显示降级原因。文案不得暂称卡片点击「一定能完成审批」。

## 11. 提交前预检（申请人侧）

范围与规则见[需求与设计](./2026-11-23-外部审批平台接入-需求与设计.md) §16。入口是「外部审批」的第 6 个页签「提交前预检」，不要求完成平台授权。

### 11.1 页面结构

| 区域 | 内容 |
|---|---|
| 记录列表 | 流程名称、更新时间、结果状态；可新建、打开、删除 |
| 左栏：我的材料 | 选择流程与 AI 员工、附件、提取并经本人核对的字段 |
| 右栏：检查结果 | 状态、问题项（说明、依据标签、修改建议）、所用规则版本 |

### 11.2 状态与动作

| 状态 | 展示 | 可用动作 |
|---|---|---|
| 未开始 | 说明需要哪些材料 | 放入附件、填写字段、开始检查 |
| 检查中 | 进度 | 取消 |
| 需补充或调整 | 阻塞项置顶 | 修改后重新检查、复制清单 |
| 无法判断 | 缺什么导致无法判断（规则未装载、字段不足、附件读不到） | 补充后重新检查 |
| 有提示项 | 提示项列表 | 修改、复制清单 |
| 未发现阻塞项 | 「按已装载规则未发现阻塞项」 | 复制清单 |
| 已过期 | 说明输入或规则已变化 | 重新检查 |
| 分析失败 | 失败原因 | 重试 |

页面固定提示「结果仅供提交前自查，不代表审批结论，请到原平台提交」。页面没有提交、同意或拒绝按钮。

### 11.3 验证

- 多问题项、长字段、多附件在 1440×640 窗口下可滚动到底，主按钮用 `elementFromPoint` 验证可点击；短内容不撑出空白。
- 键盘可完成放附件、改字段、开始检查；状态不只用颜色表达。
