审批「该问才问，授权过不再问」 2026-11-19 · 设计草案，未写代码

一句话：把审批从「按工具名黑名单」升级为「风险分级 + 节流 + 无人值守 + 授权延续」→ 定时任务不再被审批卡死，无风险动作不打扰，授权过的能力不重复问，MCP 用量与平台密钥口径一致。

触发策略

风险分级（无风险不弹）+ 节流（短时间不重复弹）+ 无人值守（定时任务不弹，未授权动作跳过并记录）。

授权延续

安装或使用时用户给了权限，之后不再询问；授权仅本会话有效；会话授权限来源，外部未签名内容（新技能安装）每次询问。

计量与密钥

MCP 用量计入 token 统计（取消整轮免计）；平台密钥按成员对 MCP / 企业信息的权限按需下发并审计。

阅读提示：工作量用 S / M / L 粗估，只表示相对大小，不是排期承诺；UI 为示意图，不是最终视觉稿；表格里标「新」的是仓库里目前没有的东西。配套设计文档：2026-11-19-审批策略与能力授权-需求与设计.md。

1 解决什么问题

现在的问题本方案怎么解决谁受益
定时任务（无人值守）遇到需审批动作会弹框，10 分钟后过期并中止整次运行，提示「请把权限调高」。无人值守运行默认不弹框：已授权能力自动执行；未授权动作跳过并记录原因，运行结束后汇总通知，不中止整次运行。成员企业
同一会话同一工具反复调用会反复弹，没有冷却与合并。节流：同参数直接复用已有审批；同工具在冷却窗口内不重弹；同批次一次审批覆盖整批；前端把多条待批合并为队列卡片。成员
无风险任务也弹：未知工具一律按高风险；只读白名单是硬编码，新增只读工具要改代码。风险分级表：只读/查询类不弹；本地写改为低风险（节流后弹）；外部与未知仍按高风险必弹。成员
安装/使用时给了权限，之后仍可能弹；「本会话不再询问」对技能安装不限来源。能力授权记录（仅本会话有效）：批准安装/使用时写入授权，本会话内不再问；外部来源（ClawHub / 网址 / 粘贴）新技能安装每次都询问。成员
用了个人能力（含 MCP）的整轮 token 与费用都不进 outbox，MCP 用量不计入统计。取消「整轮免计」：只要用了 MCP 就正常上报整轮用量；个人能力仅用于审计与展示。企业运营
企业自有 MCP 的平台应用密钥，任何在职成员的本机都能取。下发前校验：企业已启用 + 成员在职；用到时才请求（按需下发）并记审计。员工自配 MCP 的凭据只在本机，不经过这里。企业
不能保证的事（对外口径一致）：不保证所有工具都能自动判级（未知工具仍按高风险弹）；不保证定时任务在存在未授权动作时结果完整（被跳过的动作不会执行）；不保证密钥下发到成员本机后的存储安全（只做按需下发与审计）。

3 数据流

边界：不向用户机器入站；会话内容不上传；平台模型状态单写者；Manager 租户数据经 TenantContext / RLS。

3.1 总图：谁在哪一端做什么

实线 = 同端流程；虚线 = 跨端调用。方向只有：Operator→Manager 服务间调用、Agent 主动访问 Manager、Agent 本机内部；没有入站到用户机器。

3.2 主流程

工具调用模型发起 toolCall
→
风险分级无风险 / 低 / 高
→
场景判定交互 / 无人值守 / 只读
→
授权检查能力授权 / 会话授权
→
触发或跳过弹框 / 复用 / 跳过
→
执行并记录审计 + 用量

3.3 状态与处置矩阵

状态交互会话无人值守（定时任务）只读会话
无风险直接执行，不弹直接执行，不弹直接执行
低风险（本地写）首次弹，冷却窗口内不重弹已授权则执行；未授权跳过并记录拒绝执行
高风险（外部 / 未知）必弹；已授权可不弹已授权则执行；未授权跳过并记录拒绝执行
重复请求同参数复用已有审批；同工具冷却窗口内不重弹；同批次一次审批覆盖整批同左

6 契约与数据变更

变更内容影响面风险
approval_session_grant授权键带来源：subject 由 skill 细化为 skill:platform_catalog / skill:external（或新增 source 列）；外部来源不允许写会话授权。Agent + 桌面端中
member_capability_grant（新）成员对能力（MCP ref / 技能 id）的授权：tenant、member、capability_kind、capability_ref、source、scope、created_at。Agent + 桌面端 + Manager高
work_records.usage不再因「用了个人能力」整轮置空；MCP 运行正常计入（逻辑变更，不改表）。Agent + Manager 用量中
oauth_client 路由响应结构不变；增加权限校验与审计（新逻辑，不改表）。Manager + Agent中
审批记录复用 approval_batch_id 做批次合并；节流命中不需要新字段（按 canonicalArgsHmac + 时间窗口查询）。Agent低
高风险：member_capability_grant 新表与授权键细化属共享契约变更，需按 AGENTS.md §8「高风险操作」确认后再实施。建议发布顺序：先升级 Agent / 前端（能读旧键、写新键），再发布 Manager 校验，最后下线旧键。

7 阶段与依赖

阶段内容依赖验收
P0 验证复现定时任务「弹框→过期→中止」；确认 findApprovalForTool 复用条件与 approval_batch_id 语义；确认 MCP 工具 readOnlyHint 可得。本机 Agent + 测试会话给出三条结论并回填本设计的触发规则
P1 触发策略风险分级表、节流、无人值守不弹、待批队列合并、跳过清单。P0定时任务不再因审批中止；同参数 / 同工具冷却窗口内不重弹；无风险工具不弹。
P2 授权延续member_capability_grant 表 + 安装/使用授权 + 设置页 + 会话授权限来源。P1安装后同能力不再询问；外部来源不出现会话授权；撤销后恢复询问。
P3 密钥权限oauth_client 增加权限校验与审计。P2（授权数据）未授权成员取不到密钥；下发有审计记录。
P4 用量移除整轮免计，MCP 用量计入 token 统计。P1用个人 MCP 的运行 token/费用正常进 outbox 与账单。

P1 与 P4 可并行（P4 只改用量口径）；P3 依赖 P2 的授权数据；P2 依赖 P1 的触发与跳过语义。
