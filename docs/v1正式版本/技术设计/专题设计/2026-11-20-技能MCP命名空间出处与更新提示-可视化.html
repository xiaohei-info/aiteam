技能和 MCP 带上「谁做的」，改动后各端都看得到「有更新」 2026-11-20 · 设计已拍板，按阶段实施

一句话：现在看不出技能是谁做的、从哪来的，平台改了技能企业端会多出一条、成员端看不到更新 → 加命名空间与出处、他方技能可编辑成我方副本、各层原地更新 → 三端都显示 taiyim/weather 这样的名字和「有更新」。

命名空间是展示字段

运营端 taiyim/、企业端 企业名/；SKILL.md name 和 MCP ref 不改，pi 与已装记录不受影响。

他方技能可编辑成副本

ClawHub / 平台技能「编辑」后生成我方副本，标「改自 …」，原件保留。

一条技能、原地更新

企业端「平台有新版本 · 更新」，桌面「有更新 · 全部更新」，下一次对话用新版本。

阅读提示：工作量用 S / M / L 粗估，只表示相对大小，不是排期承诺；UI 为示意图，不是最终视觉稿；表格里标「新」的是仓库里目前没有的东西。配套设计文档：2026-11-20-技能MCP命名空间出处与更新提示-需求与设计.md。

1 解决什么问题

现在的问题本方案怎么解决谁受益
看不出技能 / MCP 是平台做的、企业做的，还是从 ClawHub 拿的列表新增 namespace 与 provenance：标题显示 taiyim/x 或 企业名/x；其他平台的显示「来自 ClawHub owner/slug ↗」运营、企业管理员、成员
运营端 ClawHub 技能、企业端平台技能只能看不能改加「编辑」：保存成我方副本（我方前缀 + 「改自 …」），原件保留运营、企业管理员
企业端编辑导入技能后，原来的 ClawHub / 网址出处丢失编辑时保留出处并标为「改自」企业管理员
平台技能更新时企业端新增一行，成员看到两条，专家还绑旧的原地更新同一行：标识、开关、专家绑定不变企业管理员、成员
成员已装技能看不到「有更新」桌面「能力」页对比企业目录：行内「有更新」、页顶「N 项有更新 · 全部更新」成员
同 SKILL.md name 的两个技能都能装上，pi 只用第一个桌面显示「冲突」，安装需「替换」成员
不能保证的事：进行中的对话继续用旧版本，下一次对话才用新版本；副本不再收到 ClawHub / 平台的更新；招募和方案应用不会把企业已有的技能升到或降到方案写的版本；不推送，成员打开「能力」页或同步后才看到「有更新」；旧版本桌面不显示前缀与出处。

3 数据流

边界：不向用户机器入站（Agent 打开页面或同步时自己去企业端读）；会话内容不上传；平台目录单写者是运营端；企业端数据经 TenantContext / RLS。

3.1 总图：谁在哪一端做什么

实线 = 同端流程；虚线 = 跨端调用。方向只有：Manager 拉 Operator、Agent 主动访问 Manager；没有入站到用户机器。

3.2 主流程（一次平台技能更新）

运营端改技能保存成新版本，自动开放
→
企业端看到「平台有新版本 vX」
→
管理员更新同一行原地替换
→
成员看到「有更新」/「全部更新」
→
下一次对话用新版本

3.3 状态与处置矩阵

桌面状态判断按钮点下去
可安装本机没有这个标识，也没有同名技能安装取签名包、验签、落盘
已安装本机版本 = 目录版本——
有更新同一标识，版本（技能）或修订号（MCP）不同更新替换安装；MCP 保留本机令牌 / 登录
冲突本机已有同 SKILL.md name（技能）或同 ref（MCP）的其他条目替换安装先撤销本机那一个，再装

变更内容影响面风险

pull / 列表接口只增 namespace、provenance三端中
