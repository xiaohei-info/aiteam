## 一、已安装的 MCP 调用不再每次弹审批框（只读会话仍弹）

**改了什么**
- `server/agent_service/src/approval-service.ts`：`approvalRiskForTool` 不再把 `connector_my_*` 一律判为 `external`；新增 `isPersonalConnectorTool()` 与 `personalConnectorRisk()`。
- `server/agent_service/src/pi/session-host.ts`：审批门的风险取 `approvalRiskForTool(tool) ?? personalConnectorRisk(tool, permissionMode)`。

**口径**
| 场景 | 是否弹框 |
|---|---|
| 成员自己装的 MCP（`connector_my_*`），会话权限 = 工作区写 / 完全访问 | **不弹**，直接执行 |
| 成员自己装的 MCP，会话权限 = **只读** | **弹框**（只读不允许写，不静默失败） |
| 企业配置的 MCP（`connector_*`） | **仍然每次弹**（未改） |
| 其他外部工具（`external*` / `jira*`） | 仍然每次弹（未改） |

### 测试用例

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| 1.1 | 个人 MCP 免审批（工作区写） | ① 能力页给自己装一个 MCP（如 `http://127.0.0.1:xxxx/mcp`）② 建一个「工作区写」权限的对话 ③ 让员工调用该 MCP 的工具 | 不弹审批，直接调用成功 |
| 1.2 | 个人 MCP 免审批（完全访问） | 同上，权限改为「完全访问」 | 不弹审批 |
| 1.3 | 只读会话仍弹框 | ① 装好个人 MCP ② 建「只读」权限对话 ③ 让员工调用 | 弹出审批框；同意后仍会被只读拦截并给出提示 |
| 1.4 | 企业 MCP 仍每次弹 | 企业端配一个 MCP 并授权给专家，对话里让员工调用 | 每次调用都弹审批 |
| 1.5 | 未装过的能力不受影响 | 让员工调用 `read` / `bash` | `read` 不弹；`bash` 按原规则弹 |
| 1.6 | 名字相近的工具不误判 | 工具名 `connector_my_`（空 ref）、`connector_notion`（企业） | 前者不算个人能力；后者算企业，仍弹 |

## 二、个人 MCP / skill 只在本机，用了不计入用量上报

**改了什么**
- `server/agent_service/src/usage.ts`：新增 `isPersonalCapabilityTool()`、`usedPersonalCapability(entries, ownsSkillLocation)`。
- `server/agent_service/src/pi/session-host.ts`：命中则该次运行**不进用量 outbox、不触发上报**（`workRecords.finish` 不传 summary）。
- `server/agent_service/src/custom-skills.ts`：新增 `ownsLocation()`，判定技能块 `location` 是否为本成员导入的技能。

**判定依据（为什么可信）**
- 个人 MCP：本次运行的助手消息里出现 `connector_my_*` 工具调用。
- 个人技能：Pi 会把 `/skill:` 展开成用户消息里的 `<skill name="..." location="...">`，`location` 指向技能目录；`ownsLocation` 只认本成员 `custom-skills` 目录下的路径。
- 上报内容本身只有 token/时长/费用聚合，**不含**能力名、工具名、会话内容；审批记录只在本机 SQLite。

### 测试用例

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| 2.1 | 用个人 MCP 后不计用量 | 装个人 MCP → 对话里调用它 → 等用量刷新 | 该次运行不上报（日志 `usage.skipped_personal_capability`） |
| 2.2 | 用本机导入技能后不计用量 | 导入一个自定义技能 → 对话里 `/skill:该技能` | 该次运行不上报 |
| 2.3 | 用企业技能仍计用量 | 对话里用企业目录技能 | 照常上报 |
| 2.4 | 普通对话仍计用量 | 不发技能、不调个人能力，正常问答 | 照常上报（有 pending 用量） |
| 2.5 | 个人能力不上传 | 装好后抓包 / 看上报 body | 只有聚合数字，无能力名、无工具名、无会话内容 |
| 2.6 | 审批记录只在本机 | 装/用个人能力后检查本机 SQLite 与 Manager | 本机有记录；Manager 侧无会话内容 |

## 四、对话页粘贴后发送按钮不可用

**改了什么**
- `clients/desktop/src/components/Chat/MentionInput.tsx`：`handleInput` 不再因 `window.getSelection()` 为 null / rangeCount 为 0 而提前 `return`；改为照常 `extract(el)` + `onChange`（selection 缺失时只关闭 @ 菜单）。

**根因**：粘贴（尤其跨应用粘贴）后 selection 可能短暂不在输入框内，旧代码提前返回 → `mentionText` 不更新 → 发送按钮一直禁用。

### 测试用例

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| 4.1 | 单聊粘贴 | 单聊输入框粘贴文字 | 发送按钮立即可用 |
| 4.2 | 群聊粘贴（核心） | 群聊输入框粘贴文字 | 发送按钮立即可用（修复前禁用） |
| 4.3 | 群聊粘贴后立即点发送 | 粘贴 → 直接点发送 | 消息发出，内容完整 |
| 4.4 | 粘贴后用 @ | 群聊粘贴 → 输入 `@` | 成员菜单正常弹出（selection 恢复后） |
| 4.5 | 粘贴长文本 | 粘贴 500 字 | 输入框撑高、可滚动，发送可用 |
| 4.6 | 粘贴图片/文件 | 粘贴截图 | 走原有附件路径，行为不变 |
| 4.7 | 普通键入 | 逐字输入 | 行为不变（不回归） |
| 4.8 | 清空后发送禁用 | 全选删除 | 发送按钮禁用（不回归） |

## 五、审批的「本会话不再询问」选项（补充需求）

**口径（你拍板的）**：所有外部工具（MCP 连接器等）· 仅当前会话 · 只读会话也生效。

**改了什么**
- `server/agent_service/src/storage/sqlite.ts`：新表 `approval_session_grant(tenant_id, member_id, conversation_id, tool_name)`，随会话删除清空。
- `server/agent_service/src/approval-service.ts`：新增 `SESSION_GRANT_APPROVER`；`execute` 命中会话授权就按策略批准（仍建审批记录）；`decide` 新增 `sessionAllow`，只接受 `risk_level=external` 的批准。
- `server/agent_service/src/http/server.ts`：决定接口 body 新增 `session_allow`。
- `clients/desktop/src/components/Approvals/ApprovalDialog.tsx`：`risk_level=external` 的审批显示「本会话内不再询问该工具」复选框；三条批准路径（允许 / 覆盖安装 / 改名安装）都会携带。

### 测试用例

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| 5.1 | 勾选后不再弹 | 会话里触发 MCP 审批 → 勾「本会话内不再询问」→ 允许 → 再次触发同一工具 | 第二次直接执行，不弹框 |
| 5.2 | 不勾选仍每次弹 | 同上但不勾 | 每次都弹（行为不变） |
| 5.3 | 只对当前会话生效 | 会话 A 授权后，在会话 B 触发同一工具 | 会话 B 仍弹 |
| 5.4 | 换工具要重新授权 | 会话里授权了 MCP-A，再触发 MCP-B | MCP-B 仍弹 |
| 5.5 | 只读会话也生效 | 只读会话里授权 → 再触发 | 不弹（按你的选择） |
| 5.6 | 删除会话后失效 | 授权后删除会话，重新建会话触发 | 重新弹 |
| 5.7 | 本地工具不受影响 | 触发 bash 审批 | 弹窗**不出现**该复选框 |
| 5.8 | 审计仍在 | 授权后的自动批准 | 审批记录里 `approved_by = policy:session-grant`，仍可被审计 |
| 5.9 | 拒绝不写授权 | 勾选后点「拒绝」 | 不写入授权，下次仍弹 |
| 5.10 | 技能安装也有该选项 | 装一个**企业自建技能** → 弹窗 | 出现「本会话内不再询问安装技能」；勾选并允许后，本会话再装技能不再问 |
| 5.11 | MCP 安装不给该选项 | 装一个需要登录/令牌的 MCP → 弹窗 | **不出现**该复选框（审批弹窗还要收集凭据） |
| 5.12 | 技能授权不影响 MCP 安装 | 技能授权后，再装 MCP | MCP 仍照常询问 |

## 两个需要你拍板的点

1. **用量不计入的粒度**：现在是「该次运行用了个人能力 → 整次运行的 token/费用都不上报」。若同一次运行里既有企业能力又有个人能力，也会整次不计。是否接受？
2. **个人技能的识别**：靠 Pi 展开的 `<skill location=...>` 判定。若模型不通过 `/skill:` 而是自己读技能文件，则不计入的判定不生效（这种用法也很少）。是否接受？
