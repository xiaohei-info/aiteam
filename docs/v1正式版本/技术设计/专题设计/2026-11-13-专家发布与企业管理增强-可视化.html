专家发布与企业管理增强（9 项） 2026-11-13 · 设计草案，未写代码

一句话：运营端草稿、专家发布、企业账号缺少常用操作，企业端选模型、复制专家的入口难找或没有 → 操作统一放进现有列表的「⋯」菜单和抽屉里，不新增页面 → 运营和企业管理员都能在一个界面里完成操作。

运营端 5 项（R1–R5）

草稿可删除、可继续生成；配置专家不再选模型（模型只在企业端选），并能按行业 / 标签指定发布范围；在企业账号行里直接重置管理员密码；企业可以「注销 → 删除」两步删除。

企业端 4 项（R6–R9）

招募时必须选模型，没选就招募失败（应用方案也一样）；新增「复制专家」；顶栏显示企业名称，点开可设置新密码。

边界不变

发布范围由运营端过滤（单写者）；删除企业只让企业端拒绝访问，不向用户机器推送，本机会话也不会被删除。

阅读提示：工作量用 S / M / L 粗估，只表示相对大小，不是排期承诺；UI 为示意图，不是最终视觉稿；表格里标「新」的是仓库里目前没有的东西。配套设计文档：2026-11-13-专家发布与企业管理增强-需求与设计.md（现状代码位置都在里面）。

1 解决什么问题

现在的问题本方案怎么解决谁受益
R1 草稿列表没有任何行操作；生成服务停了，草稿会一直停在「生成中」列表每行加「⋯」菜单：继续生成 / 删除 / 取消生成（新）。列表返回最近一次任务的状态，能看出哪些生成失败了运营
R2 运营端配置专家必须选模型和思考档位，企业只能被动接受运营端去掉模型和思考档位（表单、详情、卡片、契约都不再有）；模型只在企业招募时选；行业方案发布的专家也不再带模型运营企业管理员
R3 专家对所有企业都可见；已有 visible_scope 字段，但没有任何代码读它企业增加行业和标签字段；发布时选「全部企业 / 指定行业或标签」；企业端拉目录时带上租户身份，由运营端过滤；范围收窄后，范围外企业已招募的员工停用；方案里的专家也各自按范围过滤运营
R4 重置密码要手输 enterprise_id；重置后旧会话仍然有效入口改到企业账号行菜单，自动带入企业；重置后负责人全部登录下线、须重新登录，清除其通行密钥等二次验证并解绑第三方登录，并记审计运营
R5 没有删除功能；「注销」只改了运营端的状态，企业端照常可以登录先注销、再删除：企业端下线该租户，拒绝登录和同步；平台 Relay 令牌吊销；保留期过后再清理数据运营
R6 招募时不能选模型，模型只能事后在抽屉深处改招募 / 应用方案弹窗里模型必填，没选不能提交，后端也拒绝（422，不落库）；应用方案时已招募的专家也可以顺手改模型；编辑时允许清空（二次确认）企业管理员
R7 想基于现有专家改一个自己的版本，做不到行菜单增加「复制」，只需填一个名称，复制完直接打开编辑抽屉企业管理员
R8 企业端看不出当前登录的是哪家企业顶栏右侧固定显示「企业名称 ▾」，点开是账号菜单企业成员
R9 登录后不能自己改密码账号菜单「设置新密码」：输入当前密码和新密码，成功后其他设备下线企业成员
不能保证的事（需要对外口径一致）： ①「继续生成」不是断点续跑，而是用原资料重新跑一次，耗时和费用都和首次生成相当； ② 取消生成时，已经产生的模型费用不能退； ③ 删除企业后，用户电脑上的本地会话仍然保留，平台无法远程清除； ④ 发布范围收窄会停用范围外企业已招募的员工，但用户端要到下次同步才生效，进行中的执行不中断； ⑤ 删除企业后，财务和审计记录会匿名保留，不会彻底抹除； ⑥ 招募必选模型只保证招募那一刻模型可用，模型之后被平台下架，员工仍会变为不可用； ⑦ 重置管理员密码会清除其通行密钥、解绑第三方登录，负责人需要重新登录、重新登记二次验证； ⑧ 设置新密码后，离线的桌面端要等下次联网访问企业端时才会被要求重新登录。

3 数据流

边界：不向用户机器入站；会话内容不上传；平台模型状态和发布范围由 Operator 单写；Manager 租户数据经 TenantContext / RLS 访问；企业的行业、标签只存在 Operator，Manager 不持有。

3.1 总图：谁在哪一端做什么

实线 = 同端流程；虚线 = 跨端调用。箭头从发起方指向被调用方。只有三种方向：Operator→Manager 服务调用、Manager 主动拉 Operator 目录、Agent 主动访问 Manager；没有任何入站到用户机器的调用。

3.2 主流程

R2 + R3 + R6：运营端发布（不含模型）→ 企业招募时必选模型

运营发布表单无模型项，范围 = 制造业
→
Manager 拉目录带 tenant_id；Operator 按行业 / 标签过滤
→
招募（必选模型）弹窗选模型 + 部门；只有 1 个可用模型时默认选中
→
Manager 校验已开通 + 已发布 + 价格已知；不通过 422，不落库
→
Agent sync快照带模型，员工立即可用

R3：发布范围收窄 → 范围外企业的员工停用

运营改范围去掉「零售」行业
→
notify 提示visibility_changed（契约已有）；Manager 逐个受影响 tenant 重新 pull 并对账（管理员打开人才市场时再对账一次兜底）
→
Manager 停用相关员工 paused + 不在发布范围
→
Agent sync拿不到快照，员工标为不可用；本机历史保留
→
站内通知企业管理员收到被停用员工清单；范围恢复时自动恢复并再通知

R5：删除企业

注销Operator closed → Manager closed（拒新登录与 sync）
→
删除system_admin 输入企业名；Operator 置 deleting
→
下线Manager deleted + 吊销会话；Relay 令牌吊销
→
完成Operator 置 deleted；30 天后清理并匿名化
