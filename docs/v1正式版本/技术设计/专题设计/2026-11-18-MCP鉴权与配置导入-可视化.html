需要登录的 MCP：成员自己去服务方登录，令牌只存在自己电脑上 2026-11-18 · 设计稿，未写代码

一句话：cr-test 这类 MCP 不带凭据就返回 401 → 成员在浏览器登录服务方账号（或填服务方发的固定令牌），本机 Agent 接住结果、加密存本机文件 → 之后调用自动带上，令牌不进模型、不出电脑。

服务方发起鉴权，成员本人登录

支持两种：浏览器登录（OAuth，如 cr-test）和固定令牌（Bearer / 自定义请求头）。参考 pi-mcp-adapter 的做法。

凭据只在成员电脑

存 Agent 数据目录，文件仅本人可读、内容加密、绑定 MCP 地址；企业端 / 运营端不保存成员令牌。

粘贴配置即可添加

运营端「登记 MCP」和桌面端新增「添加 MCP」都能直接粘贴 JSON / 链接；运营端可自动读取工具。

阅读提示：工作量用 S / M / L 粗估，只表示相对大小，不是排期承诺；UI 为示意图，不是最终视觉稿；表格里标「新」的是仓库里目前没有的东西。配套设计文档：2026-11-18-MCP鉴权与配置导入-需求与设计.md（现状核对带文件行号）。

1 解决什么问题

现在的问题本方案怎么解决谁受益
个人 MCP 安装前不带凭据读工具列表，cr-test 返回 401，安装直接失败Agent 探测到 401：能发现 OAuth 元数据 → 浏览器登录；发现不到 → 要求填固定令牌。登录 / 填完后带凭据再读工具、完成安装成员
调用个人 MCP 不带凭据；只有运维手配的企业连接器能带令牌每个已装 MCP 记录鉴权方式，调用时从本机凭据文件取令牌；OAuth 令牌快过期时自动刷新成员、专家
令牌如果走对话会进入模型上下文安装参数里没有凭据字段；登录走浏览器、令牌走桌面端直连本机 Agent，审批记录 / 事件流 / 日志都不含令牌成员、企业安全
成员不能自己添加 MCP，只能靠对话让专家装桌面端「个人能力」新增「添加 MCP」窗口：粘贴配置或链接 → 探测 → 登录 / 填令牌 → 安装成员
运营端登记要逐项手填、工具名手打；只有「需要凭据：是 / 否」，需要凭据的成员装不了登记窗口支持粘贴配置导入、「读取工具」；「需要凭据」改为鉴权方式（无 / 浏览器登录 / 固定令牌），需要鉴权的条目成员也能装平台运营
有的服务不允许自动注册应用，浏览器登录走不通默认自动注册（名称 "AI Team"）；「高级」里可填服务方发的应用编号 client_id / client_secret，平台目录里的 secret 加密保存成员、平台运营
不能保证的事（需要对外口径一致）： ① 服务方的 OAuth 不规范（不返回登录地址、没有元数据）时浏览器登录走不通，只能用固定令牌； ② 本机凭据文件加密只防误拷贝 / 误上传，不防同一系统账号下运行的恶意程序； ③ 平台目录里的 client_secret 会到成员电脑内存里使用，懂技术的成员能取到，这是桌面应用做 OAuth 的固有限制； ④ 服务方吊销令牌后，要到下次调用失败才会发现，届时提示重新登录； ⑤ 成员如果在对话里直接粘贴带令牌的配置，令牌已经进了对话（这是成员自己的输入），Agent 不会用也不会存，并提示改用「添加 MCP」窗口。

3 数据流

边界：不向用户机器入站（登录回调是成员自己的浏览器访问本机 Agent）；会话内容不上传；成员令牌不出成员电脑、不进模型；Manager 数据经 TenantContext / RLS；平台目录真相只由运营端写。

3.1 总图：谁在哪一端做什么

实线 = 同端流程；虚线 = 跨端 / 对外调用，方向只有：Operator→服务方（probe）、Manager 拉 Operator、Agent 主动访问 Manager、Agent 主动连服务方。浏览器回调是成员自己的浏览器访问本机 127.0.0.1，不是控制面入站。成员令牌没有任何一条线去往 Manager / Operator。

3.2 主流程（浏览器登录）

① 请求安装专家 capability_install，或成员「添加 MCP」
→
② 探测401 + 元数据 → 浏览器登录；无元数据 → 固定令牌
→
③ 审批「允许并登录」；自动安装授权也不跳过这步
→
④ 登录取编号（手填 / 自动注册）→ PKCE + state → 打开浏览器
→
⑤ 回调校验 state → 换令牌 → 加密存本机 → 读工具 → 安装完成

3.3 状态与处置矩阵

鉴权状态专家调用工具设置「个人能力」自动安装（§11.3）
无需登录直接调用只有「卸载」按原规则直接装
已登录 / 已填令牌带令牌调用；快过期自动刷新重新登录 / 退出登录；更新 / 清除令牌本机已有该地址有效凭据 → 直接装
登录中—（安装还没完成）显示「等待浏览器登录」—
需要重新登录返回「需要重新登录，请到 设置 · 个人能力」，不自动弹浏览器「重新登录」高亮仍弹窗，只问登录
登录失败 / 超时安装失败，模型收到「用户未完成登录，可稍后重试」不产生安装记录—

位置要做什么阶段量级

agent_service（Node）新加密凭据存储（AES-256-GCM，密钥文件 0600，绑定地址）；探测判定；SDK OAuthClientProvider（自动注册 "AI Team" / 手填编号、PKCE、刷新）；回调路由；bearer 安装；调用带凭据 + 每 MCP 超时；重新登录 / 清除 / 添加 MCP 接口；local_capability 加列P0L
全部统一 application/problem+json；OpenAPI 与门禁；令牌不出现在模型可见内容 / 日志的断言；跨租户隔离测试随各期M
注意：回调路由是 Agent 唯一新增的免登录路由，必须只认本 Agent 发起过的一次性 state、只接受 127.0.0.1；SDK 的 OAuth 发现请求不能把 MCP 的令牌发到别的域。
