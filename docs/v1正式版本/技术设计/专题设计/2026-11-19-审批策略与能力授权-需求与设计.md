## 1. 背景与目标

PR #218 把「个人 MCP / 导入技能 / MCP 目录」带进了审批与授权链路。复核后产品侧给出 4 条口径：

1. 审批**必要时仍弹，但不能频繁**：定时任务不能弹（否则影响执行）、短时间不能多次弹、无风险任务不能弹。
2. **安装或使用的时候给了权限，就不再询问。**
3. **使用 MCP 的用量必须计入 token 用量统计。**
4. **平台密钥需要按成员对 MCP / 企业信息的权限限制，不能无条件下发。**

本设计把这 4 条落成可实施的机制，并给出契约、阶段与待决策。

## 3. 方案

### 3.1 触发策略：风险分级 + 节流 + 无人值守

**风险分级**（扩展 `SAFE_TOOLS` 为注册表，避免新增只读工具要改代码）：

| 级别 | 判定 | 默认行为 |
|---|---|---|
| 无风险 | 只读 / 查询类工具（含工具自带 `readOnlyHint`、MCP 只读方法） | 直接执行，不弹 |
| 低风险 | 本地写 / 改（`bash` / `write` / `edit`） | 首次弹；冷却窗口内不重弹 |
| 高风险 | 外部工具、未知工具、有副作用的 MCP 方法 | 必弹（除非已授权） |

**节流**（不频繁）：

- 同参数：复用已有审批（已有 `canonicalArgsHmac` 机制），不重弹。
- 同工具冷却窗口：同一会话同一工具在 **30 分钟**内不重弹；批准可复用上次决定，拒绝不自动放行。
- 同批次：一次审批覆盖整批（扩展 `approval_batch_id` 的批准方向）。
- 前端：同一会话多条待批合并为一个队列卡片，不连续弹窗。

**无人值守**（定时任务不弹）：

- 仅 `record.activeBackground` 算无人值守。
- 默认不弹框：已授权能力自动执行；未授权动作**跳过并记录**（写入本次运行的「跳过清单」），不中止整次运行。
- 运行结束后把跳过清单随结果通知成员；若跳过影响结果完整性，提示成员去授权。
- 保留 `abortBackgroundRunOnExpiry` 作为兜底，但正常路径不再触发。

### 3.2 授权延续：安装 / 使用即授权

- 新增「能力授权」：成员对某能力（MCP `ref` / 技能 `id`）的授权记录，**仅本会话有效**。
- 批准安装（`capability_install`）或首次使用某能力时写入授权；**本会话内**调用命中授权即放行（除只读会话 / 高风险动作）。
- 会话授权（本会话不再询问）保留为显式选项，但**限来源**：只对平台 / 企业目录来源生效；外部来源（ClawHub / 网址 / 粘贴）**新技能安装每次都询问**。
- 授权可在「设置 → 能力授权」查看与撤销（列表按本会话展示）；撤销后恢复询问。
- 与现有 `full-access` 的关系：`full-access` 继续作为「本地工具整体免弹」的会话开关；能力授权是更细的按能力粒度补充。

### 3.3 用量计入 token 统计

- 移除 `usedPersonalCapability()` 对整轮的上报排除：只要运行用了 MCP，整轮 token / 费用正常进 outbox 与账单。
- 个人能力概念保留用于审计与展示，不再影响上报口径。
- 理由：MCP 调用的 token 影响主要通过工具结果进入后续上下文，难以精确拆分到「某一次调用」；统一计入口径一致、可实现。

### 3.4 平台密钥按权限下发

**范围：只针对企业自有 MCP**（平台目录收录、企业登记了 OAuth 应用密钥的 MCP）。员工在自己客户端配置的 MCP，凭据由员工本人持有、只在本机，Manager 不参与、也不受本节限制。

- `GET /api/manager/grants/mcp-servers/{server_id}/oauth-client` 下发前校验：
  1. 企业已启用该 MCP；
  2. 成员在该 MCP 的可安装 / 可见范围（目录可见性、角色、授权）；
  3. 已定：成员对该 MCP 有授权（授权后才可取）才下发。
- 每次下发记审计（谁、何时、哪个 server）。
- 响应结构不变；不在范围内返回 403 / 404（与现有问题码一致）。

## 4. 契约与数据变更

| 变更 | 内容 | 影响面 | 风险 |
|---|---|---|---|
| `approval_session_grant` | 授权键带来源：`subject` 由 `skill` 细化为 `skill:platform_catalog` / `skill:external`（或新增 `source` 列）；外部来源不允许写会话授权 | Agent + 桌面端 | 中 |
| `member_capability_grant`（新） | tenant、member、capability_kind、capability_ref、source、scope、created_at | Agent + 桌面端 + Manager | 高 |
| `work_records.usage` | 不再因「用了个人能力」整轮置空（逻辑变更，不改表） | Agent + Manager 用量 | 中 |
| `oauth_client` 路由 | 响应不变；增加权限校验与审计 | Manager + Agent | 中 |
| 审批记录 | 复用 `approval_batch_id` 做批次合并；节流按 `canonicalArgsHmac` + 时间窗口查询，不新增字段 | Agent | 低 |

**高风险提示**：`member_capability_grant` 新表与授权键细化属共享契约变更，按 AGENTS.md §8 需确认后实施。

## 5. 风险与边界

- **不能保证所有工具自动判级**：未知工具仍按高风险弹；MCP 方法的 `readOnlyHint` 以平台声明为准，可能被误标。
- **不能保证定时任务结果完整**：未授权动作被跳过，结果可能缺项；必须把跳过清单明确告知成员。
- **不能保证密钥在下发后的本机存储安全**：只做按需下发与审计，不能约束成员机器上的使用。
- **红线**：不向用户机器入站；会话内容不上传；平台模型状态单写者；Manager 租户数据经 TenantContext / RLS。
- **兼容性**：授权键由 `skill` 细化后，旧键需保留可读一个版本，避免升级期间行为回退。

---

## 6. 发布顺序

1. **先升级下游**：Agent / 桌面端能读旧授权键、写新键；前端能显示来源与撤销入口。
2. **再发布上游**：Manager 的密钥权限校验与审计。
3. **最后下线旧键**：确认无旧客户端后再停止写 `skill` 旧键。
4. 迁移需带 `-- deploy-compat: contract`，避免再被 CI 判为收缩型迁移。

## 7. 阶段与验收

| 阶段 | 内容 | 依赖 | 验收 |
|---|---|---|---|
| P0 验证 | 复现定时任务「弹框→过期→中止」；确认 `findApprovalForTool` 复用条件与 `approval_batch_id` 语义；确认 MCP 工具 `readOnlyHint` 可得 | 本机 Agent + 测试会话 | 三条结论回填 §3.1 |
| P1 触发策略 | 风险分级表、节流、无人值守不弹、待批队列合并、跳过清单 | P0 | 定时任务不再因审批中止；同参数 / 同工具冷却窗口内不重弹；无风险工具不弹 |
| P2 授权延续 | `member_capability_grant` 表 + 安装 / 使用授权 + 设置页 + 会话授权限来源 | P1 | 安装后同能力不再询问；外部来源不出现会话授权；撤销后恢复询问 |
| P3 密钥权限 | `oauth_client` 增加权限校验与审计 | P2 | 未授权成员取不到密钥；下发有审计记录 |

P1 与 P4 可并行；P3 依赖 P2 的授权数据；P2 依赖 P1 的触发与跳过语义。

## 9. 已决定（不再讨论）

- 定时任务不弹框，不影响执行。
- 短时间不重复弹。
- 无风险任务不弹。
- 安装 / 使用时授权后不再询问。
- MCP 用量计入 token 统计。
- 平台密钥按成员权限下发。
- 无人值守未授权动作：跳过并记录。
- 节流窗口：30 分钟。
- 能力授权：仅本会话有效。
- 新技能安装：每次都询问。
- 企业自有 MCP 密钥：授权后才可取。
