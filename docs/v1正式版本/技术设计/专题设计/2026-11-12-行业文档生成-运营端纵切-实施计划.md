## 1. 目标与边界

**目标**：`system_admin` / `system_operator` 在运营端上传行业资料（docx / pptx / xlsx / pdf / md / txt / html / png / jpg / webp），选择平台模型与图片识别方式、填补充说明，生成「专家团队 + 协调专家 + 协作说明 + 交付要求」草稿；人工审核（编辑、处理敏感项、看证据）后发布为平台公共方案。

**非目标（本期不做）**：旧格式 .doc/.ppt/.xls 转换；网页链接抓取；OCR 实现；企业端生成与私有池；跨端脱敏提炼；`components` / `requirements` 契约变更与环境镜像；制品；AI 自动发布；Manager `document_parser` 迁到 shared（P2b 再做，避免本期动企业端知识入库）。

```text

```

## 3. 关键设计

### 3.1 Node worker：`server/solution_authoring_worker/`

- 独立 `package.json` + lockfile，依赖仅 Pi SDK / pi-ai / typebox；**不 import `server/agent_service`**（后者是用户端交付物，D15）；`registerRuntimeProvider` 这段约 40 行按需复制。
- 协议：stdin 一个 JSON（`mode: generate | recognize`、`model`（base_url / api_protocol / model_id / api_key / capabilities）、`budget`、`sources`、`prompt`），stdout 只输出一行最终 JSON（`{status: succeeded|failed, result?, error_code?, usage}`），日志走 stderr 且不含正文与密钥。
- 隔离：cwd / agentDir 为每任务临时空目录；`DefaultResourceLoader` 关闭 extensions / skills / prompt templates / themes / context files；`tools` 只列 custom tools，不启用 bash / read / write / edit；`SettingsManager.inMemory`、`SessionManager` 内存态；compaction、retry 关闭。
- 预算：最大轮数、最大工具调用、token 上限（按 usage 事件累计）、墙钟超时；超限 `abort` 并返回 `budget_exceeded`。
- `submit_solution` 在 worker 内按 JSON Schema 校验，失败把错误回给模型修订（最多 N 次）；Python 宿主再用 Pydantic 做一次权威校验。
- 文档内容作为**数据**：工具返回的片段包在明确的数据边界内，system prompt 规定不得执行文档中的指令。
- 识别模式（方案 B）：逐图调用视觉模型产出 `RecognizedText`；模型 `capabilities.input` 不含 `image` 时直接拒绝。

### 3.2 Python 共享核心：`server/shared/solution_authoring/`

- `schemas.py`：`SourceChunk`、`ImageAsset`、`RecognizedText`、`Evidence`、`SensitiveFinding`、`GeneratedExpert`、`GeneratedSolution`、`AuthoringResult`（均 `extra=forbid`）。
- `parsing.py`：stdlib zip+xml 解析 docx（段落、表格、内嵌图片）、pptx（按幻灯片、内嵌图片）、xlsx（按 sheet 行）；PyPDF2 解析 pdf（按页文本，无文本页抽取页内图片）；文本 / html；独立图片。全部带 `locator`（文件 / 页 / 幻灯片 / sheet / 段落序号）。限文件大小、页数、图片数与像素（Pillow 校验）。
- `recognizers.py`：`ImageRecognizer` 协议；`VisionImageRecognizer`；`NoopImageRecognizer`（图片记 `image_unrecognized`）。OCR 实现后续加。
- `sensitive_scan.py`：规则扫描（手机号、邮箱、身份证、银行卡、金额、常见公司后缀），输出发现项（库内留原文片段供定位与一键脱敏，对外只给打码后的展示值，见 §7 调整 1）。
- `runner.py`：`PiWorkerRunner`，spawn 参数固定、密钥只走 stdin、清空继承环境（只留 PATH / NODE 相关）、超时 kill、stdout 大小上限、stderr 截断。
- `prompts/generate_system_v1.md`、`prompts/recognize_system_v1.md`：平台版本化 system prompt（`PROMPT_VERSION="v1"`）；使用者补充说明只追加在独立段落。

### 3.3 运营端

- 迁移 `0018_solution_authoring.sql`：`solution_source_document`（库里只记元数据、相对路径与 sha256；文件存 Operator 主机目录 `SOLUTION_AUTHORING_STORAGE_DIR`，单文件与每草稿总量设上限；多实例部署需共享盘）、`solution_generation_job`（`queued → parsing → analyzing → succeeded | failed`，lease / attempts / 安全错误码）、`solution_draft`（package jsonb、evidence jsonb、状态 `draft → generating → ready_for_review → in_review → approved → published | rejected | archived`、`published_solution_id`）、`solution_sensitive_finding`、`solution_review_event`；授权 `app_rw`。
- 仓储：内存 + Pg 两实现（沿用 `CatalogRepository` 形态）；任务领取 `FOR UPDATE SKIP LOCKED` + lease。
- 模型注入 `ModelConfigResolver`（`solution_authoring_models.py`，生产实现 `RelayModelConfigResolver`；目录读取经 `PlatformModelCatalog`，只用平台目录已有的公开方法，不改 `platform_provider_service.py`）：校验 `PlatformModelRef` 已发布且有价格；`base_url` 用 NewAPI relay 地址，`api_protocol` 取 Provider；**凭据 = 平台内部专用 relay key（新 env `SOLUTION_AUTHORING_RELAY_TOKEN`，仅 Operator 进程持有）**。方案原写「短期 relay token」，按任务签发短期 token 作为后续项（见 §6 风险 2）。
- 北向接口（新增，需评审）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET / POST | `/api/operation/solution-authoring/drafts` | 列表 / 新建（模型引用、图片识别方式、补充说明） |
| GET / DELETE | `…/drafts/{draft_id}` | 详情（含发现项、证据）/ 归档（生成中不可归档；同时删除资料原件） |
| POST | `…/drafts/{draft_id}/sources` | 上传资料（multipart；单文件 20 MB、每草稿 20 份 / 100 MB；上传即解析，不支持或损坏直接 422） |
| DELETE | `…/drafts/{draft_id}/sources/{source_id}` | 删除资料 |
| POST | `…/drafts/{draft_id}/generate` | 发起生成（`Idempotency-Key`），返回 job |
| GET | `…/drafts/{draft_id}/jobs/{job_id}` | 任务状态 |
| PUT | `…/drafts/{draft_id}/package` | 编辑草稿内容（`{version, package}`，版本过期 409） |
| POST | `…/drafts/{draft_id}/findings/{finding_id}/resolve` | 处理发现项（`resolution`: `redact` / `remove` / `accept_public` / `acknowledge`） |
| POST | `…/drafts/{draft_id}/submit-review` · `approve` · `reject` | 审核流转（approve / reject 限 `system_admin`；reject 必填说明） |
| POST | `…/drafts/{draft_id}/publish` | 写入目录并发布（限 `system_admin`；有未处理发现项则 409；失败可原样重试） |

- 权限：读 / 建 / 生成 / 编辑 `system_admin | system_operator`；审批与发布 `system_admin`。
- 审计：`solution_review_event` 只记动作、操作人、摘要，不记正文；日志带 `request_id`，不含文档内容与密钥。
- 进程内 worker：仿 `install_relay_token_lifecycle_lifespan`，仅在配置了 DB 时启动；并发上限可配。

| `SOLUTION_AUTHORING_STORAGE_DIR` | 资料原件目录；生产缺失返回 503，开发回落到系统临时目录 |
| `SOLUTION_AUTHORING_WORKER_ENABLED` | `1/0` 覆盖默认（配置了业务库与管理库连接时默认开启） |
| `SOLUTION_AUTHORING_WORKER_CONCURRENCY` | 进程内并发，1–4，默认 1 |
| `SOLUTION_AUTHORING_WORKER_DIR` / `SOLUTION_AUTHORING_NODE` | 可选；worker 目录与 node 可执行文件位置 |
| `SOLUTION_AUTHORING_FAUX=1` | 仅开发 / 测试：用脚本化假模型；生产环境设置会直接报错 |

### 3.4 运营端前端 `web/operation/src/features/solution-authoring/`

（按实现更新，2026-11-12 PR #191 复核后对齐。）

- **列表页**：未归档草稿，按最近更新倒序。
- **新建草稿是对话框**（不是独立页面）：标题、生成模型（只列已发布且有价格的平台模型）、图片识别方式、补充说明。图片识别两个选项始终都显示；选了「用所选模型识别图片」而模型不支持图片输入时，在该字段报错并阻止提交（没有按模型隐藏选项）。**上传资料不在对话框里，在草稿工作台。**
- **草稿工作台**（一页）：资料清单（上传、删除、开始 / 重新生成）、敏感项与提示、方案正文（查看 / 编辑）、操作记录，以及提交 / 通过 / 驳回 / 发布 / 归档。
  - 进度：生成期间每 2 秒轮询**草稿详情**（不是任务接口），状态离开「生成中」即停。
  - 依据：在方案和每位专家下方**内联列出**（来源、位置、摘录），不是抽屉。
  - 正文编辑：未保存的修改只在编辑器里，服务端数据刷新不会清掉它；编辑期间禁用处理敏感项、提交审核和重新生成。保存遇到版本冲突时保留本地修改并提示，可选择覆盖保存或放弃修改。
  - 二次确认：重新生成、删除资料、归档、发布。
  - 批量上传逐个进行，结束后一律刷新清单，并汇总成功与失败的数量和原因。
  - 按角色和状态显示按钮，与后端规则一致（见 §7.4）。
- 导航加入口。只调 `/api/operation/*`。

## 6. 风险与需确认项

1. **新增北向接口**（§3.3 表）与 **oper 库迁移 0018** —— AGENTS §8 高风险，需你确认。
2. **平台内部凭据**：本期用 Operator 独占的内部 relay key（env），而非方案里的「每任务短期 token」。好处是不碰 relay token 生命周期这块复杂代码；代价是一把长期 key，需限定可用模型与额度。短期 token 作为后续项。
3. **源文档存本地磁盘目录**（用户选定）：库里记路径与 sha256，读取时校验 hash；多实例部署需共享盘，后续可换对象存储（只改存储实现）。
4. **扫描 PDF**：只抽页内嵌入图片（扫描件通常是整页图），不做页面栅格化（不新增 pdf 渲染依赖）；矢量图表类 PDF 页识别不到，记 `image_unrecognized`。
5. **生成的专家模板**需要 `platform_model_ref` 与 `category` 等必填项：默认用本次生成所选模型、分类由 Agent 给出并在审核时可改。
6. Pi SDK 的内置工具禁用方式以步骤 2 实测为准；若白名单不能完全排除内置工具，改用显式 `noTools` 选项或在 worker 内断言工具集合后再启动。（实测：`tools` 白名单只注册所列 custom tools；worker 仍在发首条消息前断言工具集合。）

## 7. 方案调整（实施中发现并已落地）

按「发现不合理的点可以修改方案」的授权，以下各项与原方案 / 本计划初稿不同，已按调整后的口径实现并有测试覆盖。

### 7.1 发现项与敏感信息

1. **发现项在库里保存原文片段**（与草稿同库同表权限），接口、日志、审计事件只给打码值。原设想「只存指纹」做不到定位与一键脱敏。
2. **状态与处理动作改名**：状态 `open / redacted / removed / accepted_public / acknowledged`；动作 `redact / remove / accept_public / acknowledge`。去掉方案里的 `accepted_internal`（运营端发布即对外，没有「仅内部」这一档）与 `false_positive`（由 `accept_public` 覆盖）。
3. **两类发现项**：内容项（指向草稿里某个字段）可脱敏 / 删除 / 确认可公开，文本被改掉后自动关闭，改回来会重新打开；提示项（Agent 备注、未识别图片）只能确认已知悉。
4. **闸门**：提交审核、通过、发布三处都检查「没有未处理发现项，且内容里每个规则命中都已确认可公开」，而不只在发布时检查。

### 7.2 解析与图片

1. **上传即解析**：不支持的格式（含旧版 .doc/.ppt/.xls）与损坏文件在上传时 422 拒绝并给出原因，不等到生成时才失败；任务执行时重新解析。
2. **图片识别放在解析阶段**，Agent 读的是识别后的文本片段；本期去掉「Agent 自己看图 / 重新识别」工具。
3. 图片统一转成 JPEG 再送识别；每个任务最多识别 60 张，超出记提示项；视觉模式下超过一半图片识别失败则任务失败（`image_recognition_failed`）。
4. **解析放进独立子进程**（PR #191 评审后调整）：上传与任务两条路径都调用 `isolated_parse.parse_source_isolated`——`python -I` 启动、环境变量白名单、stdin/stdout 传 JSON（不用 pickle）、墙钟超时 60 秒（`parse_timeout`）、子进程内设 CPU 时间与 2 GiB 地址空间上限（平台不支持时跳过）；崩溃或输出异常记 `parse_failed`。PDF 库由已停更的 PyPDF2 换成 pypdf（Manager 知识库仍用 PyPDF2，另行迁移）。
5. **Office XML 用 defusedxml 解析**（PR #191 复核后调整）：由解析器拒绝 DTD 与实体声明。原先在解析前按字节查找 `<!DOCTYPE` / `<!ENTITY`，UTF-16 编码的 XML 可以绕过，标准库会照常展开实体。

### 7.3 Agent 与任务

1. **模型调用的临时错误由 Pi 内置重试处理**（PR #191 评审后调整，原为关闭）：预算新增 `model_retries`（默认 3，0–5）与 `retry_base_delay_ms`（默认 2 秒，指数退避），只重试限流 / 5xx / 网络类错误，额度不足与 4xx 不重试；重试计入轮数与总超时预算，超时会截断退避。provider SDK 自身的重试关闭，避免两层叠加。上下文压缩仍关闭。宿主任务层另有最多 3 次领取（超出 `attempts_exhausted`）。
2. **Agent 不写库**：宿主校验后在一个事务里写草稿、发现项与任务状态；失败不留半成品。租约丢失或进程退出时什么都不写，由下一个实例接手。
3. **证据**：worker 要求每个专家至少 1 条证据且只能引用模型实际读过的片段；宿主 schema 允许空证据（人工新增的专家）。草稿只保存被引用的片段摘要（来源、位置、300 字摘录），编辑时只能引用已有片段。
4. 重新生成整体替换草稿内容与发现项。

### 7.4 审核与发布

1. **通过 / 驳回 / 发布仅 `system_admin`**；驳回可从「审核中」或「已通过」发起且必填说明，但**发布一旦开始（哪怕中途失败）就不能再驳回**，只能重试发布，避免已发布的专家失去归属；被驳回的草稿改完可直接重新提交，无需重新生成。本期没有双人复核与运营人员「撤回」。
2. **发布可重试、无中间状态**：方案与专家的目录 ID 由「草稿 + 模型 + 内容」确定性生成；先登记全部专家与方案，再逐个发布专家，最后发布方案；每一步先查目录，失败后原样重试即可，全部完成才把草稿置为已发布。
3. **目录补字段**：行业方案登记请求、目录内容与下发包新增可选的 `output_requirements`（纯增量）。
4. 归档允许在除「生成中」外的任何状态进行（含已发布），同时删除资料原件；目录项不受影响。**已通过 / 已发布（或已开始发布）的草稿只有 `system_admin` 能归档**（运营人员 403）。清理顺序为先删文件再删资料行：删文件失败时行仍在，重试归档会再清一遍，不留孤儿文件。
5. **前端按钮与后端规则对齐**（PR #191 复核后调整）：「归档」对运营人员只在草稿未通过、未发布且发布未开始时显示；「驳回」只在「审核中」或「已通过且发布未开始」时对管理员显示。发布中途失败时给管理员提示「上一次发布没有完成」，只能重试发布。
6. **草稿没有归属人限制（有意取舍）**：`system_admin` 与 `system_operator` 都能查看和操作全部草稿，不按创建人隔离。理由是运营团队人数少、草稿需要互相接手，且对外的动作（通过 / 驳回 / 发布、归档已审核草稿）已限定为管理员；每个动作的操作人都记在操作记录里。如果以后需要按人或按组隔离，要加归属字段与校验。

### 7.5 接口与运维

1. 不提供「修改草稿设置」与「可用模型列表」接口；前端复用现有平台模型接口（已发布且有价格）。
2. 运维要求：Operator 主机需 Node ≥ 22.19，并在 `server/solution_authoring_worker/` 执行一次 `pnpm install`；worker 从源码直接运行，没有构建步骤。
3. 模型目录读取放在本功能自己的模块里，没有改动 `platform_provider_service.py`。
3a. **请求体大小上限**（PR #191 评审后新增）：`shared/body_limit.BodySizeLimitMiddleware` 按路径前缀限制请求体，`/api/operation/solution-authoring/` 为单文件上限 + 1 MiB。声明的 Content-Length 超限直接 413；chunked 请求边读边计数，超限即中止并返回 413。它在表单解析与鉴权之前生效，未登录的超大上传不会被读完落盘。生产环境建议在反向代理再设一道 `client_max_body_size`。
3b. **草稿详情新增只读字段 `publish_started`**（布尔，PR #191 复核后新增，已确认）：发布是否已开始（含中途失败）。前端据此隐藏「驳回」并提示重试发布。对北向接口是纯增量，列表接口不含该字段。
4. **容器镜像尚未跟进（待办）**：`deploy/docker/Dockerfile.operation` 的运行时镜像目前只有 Python，也没有拷入 `server/solution_authoring_worker/`。在该镜像里发起生成会以 `worker_unavailable` 失败（界面提示「生成服务未就绪」），其余功能不受影响。需要在镜像里加入 Node ≥ 22.19、worker 源码及其依赖；本机没有 Docker，无法验证镜像构建，因此本期没有改这个文件。

### 7.7 评审遗留（第二期，需另行决策）

- 发布可见范围固定为全部企业（`visible_scope` 为空），没有选择器；分类是自由文本；同一方案重复发布会产生新的专家模板；没有版本管理；目录侧下架不回写草稿。
- 草稿所选模型被下架后草稿无法再生成，需要换模型入口。
- 资料原件与证据摘录明文保留，保留期与清理策略待定。
- 生成的系统提示词可能被资料里的指令注入，建议对网址、命令类内容做规则扫描并在审核界面高亮。
- 没有配额，用量未接入财务；模型凭据是长期内部 relay key，按任务签发短期 token 待做。
- 任务队列只在进程内，适合单实例；进程重启会消耗一次领取且要等租约过期（120 秒）。worker 崩溃时只看到退出码。
- worker 环境白名单不含 `HTTPS_PROXY` / `NO_PROXY`；tsx 冷启动较慢。
- 没有片段覆盖率输出（可在步骤 11 一并比较 map-reduce 方案）；图片识别结果可按 sha 缓存；前端模型列表按 provider 逐个请求。
- `.env.example` 与 `deploy/docker/README.md` 未登记 `SOLUTION_AUTHORING_*`；概要设计 02/04 未登记新接口与新表；新流程没有 Playwright 端到端用例。
- 前端复核（PR #191）留到后续的建议：
  - 标签上限、字段长度、20 MB / 20 份、扩展名白名单在前端硬编码，后端调整后会静默过期；应由后端下发或从 OpenAPI 生成。
  - 「已发布且有价格」的模型过滤在仓库里已有多份实现，本功能又加了一份；应抽成共享 hook。
  - `DraftDetailPage` 同时负责加载、轮询、动作编排和弹窗，应拆出 hook。
  - 轮询拉的是完整详情；后端已有轻量的任务状态接口，应改为轮询任务、状态变化后再拉详情。
  - 草稿创建后标题、模型、图片识别、补充说明都不能改；需要后端补元数据更新接口。
  - 「审核通过」固定提交空备注；操作记录显示原始 `actor_id` 而不是姓名。
