员工技能与 MCP：配置到使用的链路治理 2026-11-22 · 设计草案，未写代码

一句话：管理员配的技能不一定到得了员工、被删后留着悬空引用、用户端又把「声明」当「能力」展示 → 技能和 MCP 共用一个「能力引用」机制，让每一项状态看得见、改动能联动 → 配了就能用，用不了也说得清。

一个读取入口

员工的技能 / MCP 清单只认一个来源，快照、同步、就绪检查、选择器都从同一个入口读，返回每一项的状态。

技能与 MCP 共用

知识库因为有三态、撤销记录才用绑定表；技能和 MCP 只有「有 / 没有」，用员工清单加统一服务，不照搬。

看得见，也改得动

选择器标出哪些用不了；删除技能时列出受影响员工；用户端分「可用 / 企业已移除 / 暂时不可用」。

阅读提示：工作量用 S / M / L 粗估，只表示相对大小，不是排期承诺；UI 为示意图，不是最终视觉稿；表格里标「新」的是仓库里目前没有的东西。配套设计文档：2026-11-22-员工技能与MCP配置到使用链路治理-需求与设计.md（现状带文件:行号）。

1 解决什么问题

现在的问题本方案怎么解决谁受益
选择器里什么都能选，草稿、无效、已停用的技能也能配上，保存成功却永远到不了员工选择器按状态置灰并写明原因；保存时校验新增项，不可用的直接拒绝并说明企业管理员
技能被删后，员工配置里还留着它；用户端静默跳过，谁也看不出删除前反查受影响员工，确认后在同一事务里从员工身上去掉并留审计；员工里已失效的项标「已失效」，一键去掉企业管理员
技能库加载失败时显示「暂无技能，请先新增」，没有重试失败就说「技能库暂时没加载出来」并给重试企业管理员
角色设定里写了要用某技能，员工却没有，模型就去找、找不到、把探测过程讲给用户（招聘专员事故）运行时兜底：先直接回答，缺什么放末尾「注意：」；保存时人话提示「角色设定里提到了 X，但员工还没有这项技能」用户 管理员
用户端展示的是「声明了什么」，不是「实际能用什么」同步带回被跳过的引用与原因，桌面端分类展示用户
仓库里有两张没人读的绑定表和整套接口，改了也不生效员工清单为唯一来源；旁路接口先标废弃，确认生产表为空后删除开发 / 运维
技能和 MCP 结构相同却各管各的；管理端还没有任何 MCP 选择入口共用同一个能力引用服务；MCP 选择入口是否做列入待决策企业管理员
不能保证的事（对外口径一致）：
① 提示词兜底只能降低弱模型「先叙述探测过程」的概率，不能保证每次遵守；
② persona 提示只识别目录里已存在的技能名，角色设定里写了从未入库的名字（如招聘专员的 recruitment-dispatch）发现不了；
③ 不会自动补上缺失的技能，缺什么由管理员决定；
④ 删除联动不中断正在运行的对话，离线用户重新同步前仍按旧清单工作；
⑤ employee_prompt_version 是否也是旁路、知识空间删除后绑定是否清理，尚未验证，在 P0 核实。

3 数据流

边界：不向用户机器入站（Agent 周期 / 触发式主动同步）；会话内容不上传（跨端只流转引用 ID 与原因）；员工清单由 Manager 单写；Manager 租户数据经 TenantContext / RLS。

3.1 总图：谁在哪一端做什么

实线 = 同端流程；虚线 = 跨端调用。方向只有：运营端→企业端服务间调用、Agent 主动访问 Manager、Agent 本机内部；没有入站到用户机器。

3.2 主流程

① 配置选择器取目录与状态，置灰不可用项

② 保存只校验新增项；返回 warnings
→
③ 同步统一入口出快照；带跳过的引用
→
④ 装载提示词只列已装载技能
→
⑤ 展示分类显示实际能力
删除目录项反查受影响员工

弹窗二选一列出员工；去掉 / 仅删除 / 取消
