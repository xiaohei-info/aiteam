行业文档导入 → 自动生成解决方案 → 装载给 AI 员工 2026-11-10 · 设计草案，未写代码

一句话：上传行业文档，AI 生成一份「专家组成 + 协作说明 + Skill + 知识种子 + 可运行制品」的方案，人工审核后发布；员工装载后，在客户电脑上缺环境能自己补、补不了就降级，不会卡死。

两端同期

运营端生成公共池方案；企业端生成企业私有方案；共用一个生成核心。

两层方案池

公共池（运营持有）+ 私有池（企业持有）。企业脱敏确认后，运营可读、提炼、复制进公共池。

拆箱即用

本机体检 → 私有目录自装运行时（用户确认）→ 分步引导 → 降级。运营端有镜像管理页。

服务端 AI Agent 生成内核新

理解 / 综合 / 分类 / 标注由部署在服务端的 AI Agent 承担；模型配置由宿主服务（Operator 平台模型 / Manager 企业授权模型）解析注入，两端共用同一个 Agent。Agent 不持有密钥、不写业务库、不触达用户机器。

阅读提示：工作量用 S / M / L 粗估，只表示相对大小，不是排期承诺；UI 为示意图，不是最终视觉稿；表格里标「新」的是仓库里目前没有的东西。

1 解决什么问题

现在的问题本方案怎么解决谁受益
方案只能运营手工注册，行业资料多时做不过来上传 Excel / PPT / Word / MD / HTML / TXT / 旧格式 / 网页 / 扫描件，AI 分析并生成方案草稿，附证据出处，人工审核后发布运营、企业管理员
企业只能「应用」平台方案，不能有自己的方案企业用自己的文档生成私有方案；也可把平台方案复制成私有副本再改（平台模板始终只读）企业管理员
企业好的实践留在租户里，公共池得不到沉淀企业确认脱敏并允许平台使用后，运营端读脱敏正文、提炼优化，审核后进入公共池，全程双侧审计平台、其他企业
方案只有文本（专家 + Prompt），拿到手还要自己配 Skill、知识、脚本方案包新增部件清单：Skill、知识种子、连接器依赖、Web / 脚本制品，一起签名分发企业成员
客户电脑没有 Python 等环境，脚本跑不起来，现在只会失败本机体检 + B/C/D 补救；运营端镜像页保证有可下载的运行时；覆盖缺口的方案不能发布企业成员、客服
文档含公司名、人名、金额，生成方案有泄密风险自动扫描敏感项，未处理不能提交审核；企业端先脱敏再给运营看；进公共池需 system_admin 逐项确认企业、平台
不能保证的事（需要对外口径一致）：用户完全断网且无离线包、磁盘已满、被企业安全软件拦截下载时，仍会落到 C（分步引导）或 D（只用文本部件）。我们保证「不死路」，不保证「所有电脑都能跑脚本」。

实线 = 同端流程；虚线 = 跨端调用。方向只有三种：Operator↔Manager 服务间调用、Agent 主动访问 Manager、Agent 本机内部。没有任何入站到用户机器。

3.6 图片识别：OCR 与多模态两种方案

独立图片、扫描 PDF、docx / pptx 内嵌图片，都先抽成图片，再经统一的 ImageRecognizer 接口识别，输出同构的 RecognizedText（文本块 + 来源定位 + 置信度 + 类型：文字 / 表格 / 图表）。分块、证据、敏感扫描、Agent 下游完全不感知用了哪种方案。识别放在「解析」阶段统一预处理，Agent 只读识别后的分块，工具 recognize_image 仅用于对低置信度图片按需补识别。

方案 A：专用 OCR 服务 不依赖模型视觉能力
预处理纠偏 / 去噪 / 限尺寸
→
OCR 引擎文本块 + 坐标 + 置信度
→
版面还原段落 / 表格
→
分块进入证据库

怎么部署：自部署开源引擎（如 PaddleOCR / Tesseract），放在与文件转换同级的隔离 worker 或独立容器；也可接云 OCR（图片会出内网，等同方案 B 的保密约束）。

优点：单页成本低且稳定；可私有化，图片不出内网；输出确定、可复现；Agent 用任何文本模型即可。

缺点：只出文字，不理解图表 / 流程图 / 架构图的含义；表格与版面要额外还原；多一个服务要运维和扩容；手写、低质量扫描依赖引擎。

适合：扫描件、合同表格、文字为主的截图，保密要求高的企业。

方案 B：多模态模型识别 依赖模型视觉能力
预处理分页 / 缩放 / 切图
→
视觉模型宿主注入，转写 + 图表描述
→
结构化输出 RecognizedText
→
分块进入证据库

怎么实现：复用 4.1 的模型配置注入，不新增服务。所选模型须在 capabilities 中声明 supports_vision（并在已授权、已付费范围内），宿主在创建任务时校验；不满足则此方案不可选。

优点：零新增运维；能读懂图表、流程图、架构图并输出语义描述；复杂版面和表格还原较好。

缺点：按图计 token，成本高；可能漏字或幻觉，须配置信度与抽检；速度慢，受模型限流；图片内容经 Relay 发往模型上游。

适合：流程图、架构图、统计图表、版面复杂的资料。

对比项A 专用 OCR 服务B 多模态模型
新增部署需要（OCR worker / 容器 + 容量监控）不需要
文字准确率印刷体高、稳定；手写依赖引擎较高，但偶有漏字 / 幻觉
图表 / 流程图语义不支持，只得到零散文字支持，输出结构与含义描述
单页成本低、可预估（自有算力）较高，随图片大小与模型价格变化
保密私有化时图片不出内网；云 OCR 则出网图片经 Relay 发往模型上游；企业端使用企业授权模型
可复现高较低（温度、模型版本影响）
对模型的要求无所选模型须支持视觉
额度计入自有算力，不计模型额度运营端计平台额度；企业端计企业额度
两种方案共同遵守：
  • 识别结果和文档一样是数据而非指令：图片里的文字可能带「忽略以上规则」之类内容，进入 Agent 前按同一套注入防护处理。
  • 识别出的文本必须再过敏感扫描与脱敏：图片里的公司名、人名、金额同样适用 D-D / D-I 的审核规则。
  • 置信度低于阈值的文本块标记 low_confidence，在审核页提示人工核对，不静默采用（即上文界面中的「识别 32%」）。
  • 单图识别失败不丢弃：记一条 image_unrecognized 发现项，由审核人处理；失败比例超过阈值则整个任务置 failed。
  • 限制：每任务图片数、单图像素与大小、PDF 页数；超限截断并记录。页数 / token 计入任务预算。

怎么选

选择方式

宿主服务配置默认方案 image_recognizer = ocr | vision；创建任务时使用者可在「可用集合」内改选。方案 B 仅当所选模型支持视觉时才出现；方案 A 仅当宿主已部署 OCR 服务时才出现。

建议

接口统一、两种实现都做成可插拔；P0 用同一批真实资料对比准确率、成本、耗时后定默认。倾向：文字为主的扫描件走 A，图表类走 B；两者组合（按图片类型自动路由）作为后续优化，本期先做「二选一」。

保密建议：企业端若标记保密级别较高，方案 B（及云 OCR）默认需要企业管理员显式允许「图片发送到所选模型 / 外部服务」，否则只能用私有化 OCR。

4 服务端 AI Agent 生成内核 同一 Agent，模型配置由宿主服务注入

生成核心里「分段摘要 → 行业综合 → 部件分类 → 敏感标注」这些需要理解与判断的环节，由部署在服务端的 AI Agent 承担。Agent 是控制面内部的生成执行体，不是第四个端：不承载会话、不向用户机器入站、不持有跨租户真相、不接触用户本地数据。

部署形态：Pi SDK，每任务一个 Node 子进程

Agent 基于 Pi SDK（server/solution_authoring_worker）。宿主 operation_service / manager_service 的任务 worker 为每个任务起一个子进程：stdin 传任务与模型配置，stdout 收结果。不是独立服务，不监听端口，不新增跨系统通信面；只注册受控工具，不启用 bash / 文件工具。

模型配置：宿主服务注入

Operator 用平台模型目录 + 内部额度；Manager 用企业授权模型 + 企业额度。Agent 不发现、不持有密钥。

两端共用

同一 system prompt、工具集、输出 schema、预算策略；差别只在宿主注入与草稿落库位置。

4.1 模型配置来源与注入

宿主模型来源额度注入内容
operation_service平台 Provider / 模型目录（platform_provider / platform_model）+ 内部 NewAPI Relay平台内部额度base_url、api_protocol、model_id、短期 relay token、能力参数、预算
manager_serviceOperator 平台目录只读投影 + 企业授权（TenantProviderAccess / resolve_tenant_access）计入企业同上，另带 tenant_id 与 allowed_model_ids 约束

使用者在前端选择的模型，只是「从宿主可用集合中指定一个」；宿主校验通过后注入。relay token 短期、限定 model/tenant、最小权限；日志与审计只记 model_id / provider_code，不记 token；密钥不下发到用户端 Agent，不写入草稿或方案包。

4.2 Agent 运行模型与边界

实线 = 进程内调用 / 数据流。Agent 只返回结构化结果与证据，由宿主服务落库、记录审计；不写业务库、不触达用户机器、会话内容不上传。

4.3 工具集与预算

工具集（最小权限）

文档分块读取、证据检索与定位、受控网页抓取（防 SSRF）、图片识别补识别（按配置走 OCR 或多模态，见 3.6）、知识库检索（可选，限企业授权范围）、schema 校验器、敏感扫描器、部件分类器、预算查询。文档内容一律视为数据而非指令（防 prompt injection）。

预算与失败

单次任务最大步数、token 预算、超时；超限终止并标记 failed，不落半成品。输出必须通过 SolutionPackage（含 components / requirements）schema 校验，失败自动修复重试，仍失败进入死信与告警。
