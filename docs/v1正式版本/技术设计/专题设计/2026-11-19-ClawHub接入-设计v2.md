## 2. 文件过滤规则

实测 `self-improving-agent` 包 17 个文件：

| 文件 | 判定 | 处理 |
|---|---|---|
| `SKILL.md`、`assets/*`、`references/*` | 技能本体 | 保留 |
| `hooks/openclaw/{handler.js,handler.ts,handler.test.js,HOOK.md}` | OpenClaw hook 机制，Pi 无此概念 | **跳过** |
| `scripts/extract-skill.sh` | 技能自带辅助脚本，SKILL.md 有「Skill Extraction」章节 | 保留 |
| `CHANGELOG.md`、`skill-card.md`、`_meta.json` | 作者元数据 | 保留 |

**规则：只跳过 `hooks/<平台标识>/` 这类平台钩子目录；其余全部保留。**
预览里写明「已跳过 N 个 OpenClaw 专用文件」，不静默丢弃。

> 说明：不能按「SKILL.md 是否引用」来判定——ClawHub 的 SKILL.md 用平台 API 绝对地址引用文件，
> 且像 `extract-skill.sh` 这种辅助脚本本来就不在正文里出现。

## 3. 安全提示（显示但不拦截）

预览区显示（`/api/v1/skills/{slug}/scan`）：

```
ClawHub 安全提示
规则扫描：可疑 · 严重 · 不建议安装（18 项）
模型复核：无异常 · 高置信
这是第三方未签名内容，装之前请确认你信任它。
```

两个扫描器结论冲突时**并列显示**，不合并成一个词。理由：这是成员自己从市场导入、本机生效，
拦截会违背「自定义技能」语义；但隐瞒风险不行。

## 4. 候选列表（同名多作者）

`GET /api/v1/skills/{slug}` 不带 owner 时返回 409 `AMBIGUOUS_SKILL_SLUG`，`matches[]` 给候选。
桌面端 preview 返回 `candidates`，界面弹列表：

```
这个地址没有写作者，ClawHub 上有 5 个同名技能，请选一个：
  ○ self-improving agent · pskoett · 493,957 次下载   [打开页面]
  ○ self-improving agent · thcjp · 601 次下载          [打开页面]
  ...
```

- 每项可点「打开页面」→ 系统浏览器打开该技能页面。
- 选中后用该 `ownerHandle` 重新 preview/install。
- 只有 1 个候选时直接用，不弹列表。

**唯一候选也走同一接口**，只是 `candidates.length === 1` 时界面直接选中。

## 5. 来源显示与「在 Finder 中显示」

### 5.1 来源

| 导入方式 | 能力页来源显示 |
|---|---|
| 文件夹 / zip / 单个 .md / 粘贴 | **自定义** |
| ClawHub 网址 | **ClawHub** |
| GitHub / 其它网址 | 网址（待定，本期可显示「网址」） |

Agent 侧 `local_capability.source` 需要新增一个取值（如 `clawhub_catalog`），
`capabilitySourceLabel()` 增加对应分支；本地来源的 `origin.label` 统一为「自定义」。

> ⚠️ `local_capability.source` 是 SQLite CHECK 约束 + 北向契约字段，属共享口径变更，需你确认。

### 5.2 在 Finder 中显示

- 只对**本机存储**的能力（`user_import` 技能）显示该按钮；MCP、企业/平台来源没有本地目录，不显示。
- 链路：Agent 返回该技能的本机目录绝对路径 → 桌面端调 Rust `reveal_in_finder`。
- **路径不直接进北向契约**：新增一条受限路由 `GET /api/agent/capabilities/skills/{ref}/local-path`，
  仅返回当前成员自己 `user_import` 技能的真实目录，其它情况 404。
- Rust `reveal_in_finder(path)`：**校验路径位于 Agent 数据目录内**才执行 `open -R`，否则报错。
  与现有 `open_portal_in_browser` 的「白名单 + 不信任前端传值」风格一致。

## 6. 打开浏览器（候选链接）

现有 `open_portal_in_browser` 只放行三个固定门户。ClawHub 链接是用户主动要求打开的外部地址，
但**不能放开成任意 URL**。方案：

- 新增 Rust 命令 `open_external_url(url)`，只放行 **精确主机 `clawhub.ai` 的 https 地址**
  （可选：同时放行其 CDN/头像域名，本期不需要）。
- 非白名单主机直接报错，不执行。
- 前端 `openClawHubPage(url)` 包一层，非 Tauri 环境（浏览器预览）退回 `window.open` 并做同样的主机校验。
