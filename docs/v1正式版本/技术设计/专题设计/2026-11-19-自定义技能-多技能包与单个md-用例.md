# 自定义技能：多技能包与单个 .md 文件 —— 用例与验收

日期：2026-11-19
范围：在 `2026-11-18-自定义技能导入-需求与设计.md` 之上追加两种来源形态：
- **一个文件夹 / 一个 zip 下有多个技能**（原设计只按「一个包一个技能」描述，实际实现已支持多技能，这里补齐用例）。
- **选择单个 .md 文件**（新增来源 `file`）。

---

## 1. 背景与现状

「添加技能 → 自定义」现有 5 种来源，一次只显示一种：

| 来源 | 界面文案 | 说明 |
|---|---|---|
| `folder` | 文件夹 | 选一个含 `SKILL.md` 的文件夹（可带模板、脚本、参考资料） |
| `zip` | zip | 选一个技能压缩包 |
| `file` | 单个 .md | **本次新增**：选一个 `SKILL.md` 文件 |
| `text` | 粘贴 SKILL.md | 直接粘贴全文 |
| `url` | 网址 | 公开 https：GitHub 仓库/子目录、单个 .md、zip |

多技能包的处理在 Agent 侧已实现（`scanSkillRoots` 扫出所有含 `SKILL.md` 的目录，`preview` 返回清单，
`roots` 指定要装哪些，支持一次批量安装）。本次补齐的是**用例、测试与文档**。

## 2. 用例：一个文件夹下多个技能

### 2.1 用例数据

用 `~/Downloads/aiteam-skills-demo/`（已准备）：

```
aiteam-skills-demo/
├── 01-weekly-report/SKILL.md          ← 技能一
├── 02-ppt-outline/SKILL.md            ← 技能二
│   └── templates/page-types.md
├── 03-csv-summary/SKILL.md            ← 技能三
├── 04-bad-name/SKILL.md               ← 故意写错 name，校验不通过
└── 05-report-builder/SKILL.md         ← 技能四
```

预期：扫描出 **5** 条，其中 4 条 `ok=true`、`04-bad-name` 一条 `ok=false`（name 含下划线，Pi 只给 warning 但仍加载，这里直接拒绝）并给出中文原因。

`05-report-builder` 的 frontmatter `name` 也是 `weekly-report`（**故意**），用来验证同名处理。

### 2.2 用例表

| # | 操作 | 预期 |
|---|---|---|
| F1 | 添加技能 → 自定义 → 文件夹 → 选 `aiteam-skills-demo` → 检查 | 出清单「这个包里有 5 个技能，勾选要安装的」；4 条可选、`04-bad-name` 置灰不可勾并显示原因 |
| F2 | 直接点「安装所选 4 个」 | 校验通过的 4 个进安装清单；`04-bad-name` 已被排除（不在清单里，也不会报失败）。因 `05` 与 `01` 同名，实际只会得到 3 条技能记录，`weekly-report` 按已装版本覆盖 |
| F2b | 勾「替换」再装 | 4 条全部 `ok`，技能记录 3 条（同上，同名合并） |
| F3 | 重新选同一文件夹 → 检查 → 只勾 `02-ppt-outline` → 安装所选 | 因同名已存在返回 409，提示需「替换」；不误装其余（批量时该条 `ok=false`，其余照常装） |
| F4 | 同上但勾「替换」 | 覆盖 `02-ppt-outline`，其余不受影响 |
| F5 | 装完后让员工用一次（如「按 01-weekly-report 的模板写周报」） | 员工读 `SKILL.md` 并照做；该轮不进用量上报 |
| F6 | 选一个空文件夹 / 没有 `SKILL.md` 的文件夹 → 检查 | 422「这个包里找不到任何 SKILL.md。」 |
| F7 | 选一个总大小 > 10 MiB 或单文件 > 5 MiB 的文件夹 | 413，提示超限 |

### 2.3 自动化覆盖（已通过）

`server/agent_service/src/custom-skill-import.test.ts`
- 「文件夹里多个技能：preview 出清单，批量安装所选」：preview 返回 2 条、批量装 2 个、指定 `roots` 只装 1 个。
- 「批量安装默认只装校验通过的，坏条目不进安装清单」：2 条扫描结果里 1 条 name 不合规时，只装合规那条，且不再把坏条目算作失败。

`clients/desktop/tests/skillScanSelection.test.ts`
- 默认全选校验通过项、剔除不通过项、空串 root（包根本身是技能）可选、勾选切换、按钮文案与禁用、批量失败汇总。

## 4. 用例：选择单个 .md 文件

### 4.1 设计要点

- Pi 只从 `SKILL.md` 加载技能，所以磁盘上任何 `.md` 都归一到包内路径 `SKILL.md`。
- **技能名取自文件 frontmatter 的 `name`，与文件名无关**——文件叫 `我的说明.md`，技能名仍是 `weekly-report`。
- 只接受 `.md`（大小写不敏感）；目录、`.txt`、不存在的路径各自给出中文原因。
- 大小上限沿用单文件 5 MiB。

### 4.2 用例表

| # | 操作 | 预期 |
|---|---|---|
| M1 | 添加技能 → 自定义 → 单个 .md → 选 `SKILL.md` → 检查 | 预览显示 frontmatter 里的名称与说明；「文件 1 个」 |
| M2 | 选一个不叫 `SKILL.md` 的文件（如 `我的说明.md`）→ 检查 | 同样识别成功，技能名取自内容 |
| M3 | 点「安装」 | 装成一个技能，能力页来源显示「本机 .md 文件」 |
| M4 | 选一个 `.txt` / `.docx` | 422「只支持 .md 文件（技能说明）。」 |
| M5 | 选一个目录（而不是文件） | 422「不是文件：…」 |
| M6 | 选一个超过 5 MiB 的 `.md` | 413，提示超限 |
| M7 | 选的 `.md` 没有合法 frontmatter | 422，提示校验失败原因 |
| M8 | 装完后让员工用一次 | 员工读该文件并照做；该轮不进用量上报 |

### 4.3 自动化覆盖（已通过）

`server/agent_service/src/custom-skills.test.ts`
- 「readSkillFile 把单个 .md 当作单文件技能」：文件名与技能名解耦。
- 「readSkillFile 接受 file:// 地址」。
- 「readSkillFile 拒绝非 .md、目录和不存在的路径」。

`server/agent_service/src/custom-skill-import.test.ts`
- 「单个 .md 文件：装成一个技能，名字取自 frontmatter 而非文件名」：preview + 安装 + 来源为 `file`。
- 「单个 .md 只接受 .md；文件夹/zip 里没有 SKILL.md 时报错」。

## 6. 文案：已安装不是失败

安装技能 / MCP 撞同名时，服务端返回 409（`skill_exists` / `mcp_exists`）。以前界面当红字错误显示，语气生硬。
现在统一按**状态**处理：

| 场景 | 以前 | 现在 |
|---|---|---|
| 自定义技能同名 | 红字「已安装自定义技能「X」a1e01e86d8406748 版；确认后覆盖。」 | 中性提示「「X」已经装好了（a1e01e86d8406748 版），现在就能用；需要换成这次选的内容才点替换安装。」 |
| 企业技能同名 | 红字「已安装「X」版；确认后换成 版。」 | 中性提示「「X」已经装好了（版）；需要换成目录里的 版才点替换安装。」 |
| MCP 同名 | 红字「已安装同名 MCP xxx。」+ 覆盖勾选 | 中性提示「「xxx」已经装好了，无需重复添加；需要换成这次填的配置才点替换。」+ 「用这个配置替换已装的那个（连它的凭据一起换）」 |
| 批量安装里同名 | 计入失败项，文案同单技能 | 不计入失败；汇总为「「X」已经装好了，无需重复安装。」 |

实现：`clients/desktop/src/lib/alreadyInstalled.ts` 识别 409 + `skill_exists`/`mcp_exists`，
`partitionInstallResults` 把批量结果分成「装成功 / 已装 / 真失败」三组。

用例（`clients/desktop/tests/alreadyInstalled.test.ts`）：
- 同名 409 识别为状态，返回服务端原文。
- 其它 409（如文件冲突）与非 409 仍按错误处理。
- message 缺失 / 空白时给出兜底文案，不显示空白。
- 批量结果里「已装」不进 failed。
