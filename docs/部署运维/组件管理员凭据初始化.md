# 三个原生组件的本机管理员凭据初始化

## 目的

每台部署机首次初始化时生成一组本机固定的管理员凭据；后续重启、升级和重复部署都复用同一份凭据文件。不同机器不共享密码或 Token。

凭据文件只保存在部署机本地，必须为 `0600`，不要提交 Git，不放入前端 bundle，不写入 URL 或普通日志。

## 初始化顺序

先启动 NewAPI，再执行一次 bootstrap：

```bash
./scripts/ctl.sh start --env prod --deploy docker --server newapi
scripts/bootstrap-console-credentials.sh \
  --env-file .env.prod \
  --newapi-url http://127.0.0.1:9300
# 生产控制面使用本机/systemd，Docker Compose 控制面仅支持 dev/test。
./scripts/ctl.sh start --env prod --deploy local --server manager
./scripts/ctl.sh start --env prod --deploy local --server operation
```

测试环境将 `prod` 替换为 `test`，并可将控制面改为 `--deploy docker`。如果原生组件使用独立容器，LightRAG/Hindsight 也使用同一份凭据文件作为 `--env-file`；文件同时提供 LightRAG 原生所需的 `AUTH_ACCOUNTS`/`TOKEN_SECRET` 别名。

脚本行为：

- 凭据文件不存在：生成随机的 NewAPI 密码、LightRAG 密码、LightRAG JWT secret 和 Hindsight access key；
- NewAPI 可达且尚未初始化：使用生成的账号密码完成 `/api/setup`，登录并生成 `NEWAPI_ADMIN_TOKEN`；
- NewAPI 已初始化：使用凭据文件中的账号密码登录；已有 `NEWAPI_ADMIN_TOKEN` 保持不变；
- 凭据文件已存在：不重新生成，不覆盖现有凭据；
- `.env.<env>` 只记录 `AITEAM_CONSOLE_CREDENTIALS_FILE` 指针，`scripts/ctl.sh` 启动时加载本机文件。

## 本机文件

默认文件：

```text
/etc/aiteam/aiteam-console.env       # shell env，0600
/etc/aiteam/aiteam-console.md        # 人工登录记录，0600
```

可通过 `--credentials-file` 和 `--document-file` 覆盖。查看本机登录信息：

```bash
sudo cat /etc/aiteam/aiteam-console.md
```

## 登录地址

| 组件 | 默认地址 | 登录方式 |
|---|---|---|
| NewAPI | `http://<host>:9300/` | NewAPI 管理账号/密码 |
| LightRAG | `http://<host>:9621/webui/` | `aiteam-admin` 账号/密码 |
| Hindsight Control Plane | `http://<host>:9999/dashboard` | Access Key |

远程浏览器访问前必须将组件端口放在 TLS、防火墙或等价的受控边界之后。

## 轮换

正常部署不会轮换凭据。需要轮换时先备份 NewAPI 数据库和本机凭据文件，再删除/移动本机凭据文件，使用 `bootstrap-console-credentials.sh` 重新初始化，并在维护窗口完成三端登录 smoke。旧凭据应从备份和 secret store 中撤销或销毁。

## 安全边界

- `NEWAPI_ADMIN_TOKEN` 只注入 Operation；不注入 Manager/Agent；
- `HINDSIGHT_CP_ACCESS_KEY` 只供 Hindsight Control Plane 使用；
- LightRAG 的 API key、数据库密码和 JWT secret 不下发 Agent；
- 明文登录记录只用于部署管理员人工登录，不应复制到源码、截图、工单或聊天记录。
