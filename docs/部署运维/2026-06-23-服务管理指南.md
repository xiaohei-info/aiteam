# AITeam 服务管理指南

## 快速开始

### 统一管理脚本

AITeam 提供了统一的服务管理脚本 `scripts/ctl.sh`，支持 **本地 (local)** 和 **Docker** 两种环境。

```bash
# 查看帮助
./scripts/ctl.sh --help

# 启动所有服务（默认 local 模式）
./scripts/ctl.sh start

# 查看服务状态
./scripts/ctl.sh status

# 查看日志
./scripts/ctl.sh logs --server manager --follow

# 停止所有服务
./scripts/ctl.sh stop
```

---

## 环境配置

### 配置文件：`.env.dev`

首次运行 `ctl.sh` 时会自动创建 `.env.dev`，包含所有配置：

```bash
# 服务端口（local 和 docker 统一使用）
OPERATION_PORT=8781
MANAGER_PORT=8782
AGENT_PORT=8783
POSTGRES_PORT=5433

# 数据库配置
POSTGRES_USER=aiteam
POSTGRES_PASSWORD=aiteam_test
POSTGRES_DB=aiteam_v1

# 服务间认证
SERVICE_TOKEN=dev-service-token-placeholder

# 日志级别
LOG_LEVEL=INFO
```

**重要**：无论使用 local 还是 docker 模式，端口配置都是统一的！

## 使用方式

### 1. Local 模式（推荐开发使用）

**特点**：
- ✅ 快速启动，无需构建镜像
- ✅ 直接运行 Python 代码，方便调试
- ✅ 代码修改后立即生效
- ✅ 自动管理 PID 文件和日志

**启动服务**：
```bash
# 启动所有服务
./scripts/ctl.sh start

# 启动单个服务
./scripts/ctl.sh start --server manager
./scripts/ctl.sh start --server operation
./scripts/ctl.sh start --server agent
```

**查看状态**：
```bash
./scripts/ctl.sh status
```

输出示例：
```
AITeam Services Status (local mode)
====================================
● postgres — running (docker)
  Port:    5433

● manager — running
  PID:     12345
  Uptime:  01:23
  Port:    8782
  Log:     /path/to/aiteam/logs/manager.log

● operation — running
  PID:     12346
  Uptime:  01:23
  Port:    8781
  Log:     /path/to/aiteam/logs/operation.log

● agent — running
  PID:     12347
  Uptime:  01:23
  Port:    8783
  Log:     /path/to/aiteam/logs/agent.log
```

**查看日志**：
```bash
# 查看最近 100 行日志
./scripts/ctl.sh logs --server manager

# 实时跟踪日志
./scripts/ctl.sh logs --server operation --follow

# 直接查看日志文件
tail -f logs/manager.log
```

**停止服务**：
```bash
# 停止所有服务
./scripts/ctl.sh stop

# 停止单个服务
./scripts/ctl.sh stop --server manager
```

**重启服务**：
```bash
# 重启所有服务
./scripts/ctl.sh restart

# 重启单个服务
./scripts/ctl.sh restart --server manager
```

---

### 2. Docker 模式

**特点**：
- ✅ 完整的容器化环境
- ✅ 包含所有依赖（PostgreSQL + 三端服务）
- ✅ 更接近生产环境
- ❌ 代码修改需要重新构建镜像

**首次使用需要构建镜像**：
```bash
cd deploy
docker-compose build
```

**启动服务**：
```bash
# 启动所有服务
./scripts/ctl.sh start --env docker

# 启动单个服务
./scripts/ctl.sh start --env docker --server manager
```

**查看状态**：
```bash
./scripts/ctl.sh status --env docker
```

**查看日志**：
```bash
# 查看所有服务日志
./scripts/ctl.sh logs --env docker

# 查看单个服务日志
./scripts/ctl.sh logs --env docker --server manager

# 实时跟踪日志
./scripts/ctl.sh logs --env docker --server operation --follow
```

**停止服务**：
```bash
# 停止所有服务
./scripts/ctl.sh stop --env docker

# 停止单个服务
./scripts/ctl.sh stop --env docker --server manager
```

## 服务访问

### 服务端点（统一端口）

无论使用 local 还是 docker 模式，访问端点都是一致的：

| 服务 | 端口 | API 文档 | 健康检查 |
|------|------|---------|---------|
| **Operation** | 8781 | http://localhost:8781/docs | http://localhost:8781/healthz |
| **Manager** | 8782 | http://localhost:8782/docs | http://localhost:8782/healthz |
| **Agent** | 8783 | http://localhost:8783/docs | http://localhost:8783/healthz |
| **PostgreSQL** | 5433 | - | - |

### 测试服务

```bash
# 检查服务健康
curl http://localhost:8782/healthz  # Manager
curl http://localhost:8781/healthz  # Operation

# 访问 API 文档
open http://localhost:8782/docs     # Manager API
open http://localhost:8781/docs     # Operation API
```

## 常见任务

### 完整开发流程

```bash
# 1. 启动所有服务
./scripts/ctl.sh start

# 2. 查看服务状态（确保都在运行）
./scripts/ctl.sh status

# 3. 运行 E2E 测试
# (参考 docs/验收测试/E2E_验收报告_v1.0.0_20260623.md)

# 4. 修改代码后重启相关服务
./scripts/ctl.sh restart --server manager

# 5. 查看日志排查问题
./scripts/ctl.sh logs --server manager --follow

# 6. 完成后停止所有服务
./scripts/ctl.sh stop
```

### 切换环境

```bash
# 从 local 切换到 docker
./scripts/ctl.sh stop                    # 停止 local 服务
./scripts/ctl.sh start --env docker      # 启动 docker 服务

# 从 docker 切换到 local
./scripts/ctl.sh stop --env docker       # 停止 docker 服务
./scripts/ctl.sh start                   # 启动 local 服务
```

### 只启动数据库

```bash
# Local 模式：只启动 postgres（docker 容器）
./scripts/ctl.sh start --server postgres

# Docker 模式：只启动 postgres
./scripts/ctl.sh start --env docker --server postgres
```

### 重启单个服务（开发中常用）

```bash
# 修改 Manager 代码后
./scripts/ctl.sh restart --server manager

# 修改 Operation 代码后
./scripts/ctl.sh restart --server operation
```

## 故障排查

### 服务启动失败

1. **查看日志**：
   ```bash
   ./scripts/ctl.sh logs --server manager
   ```

2. **常见问题**：
   - 端口被占用：修改 `.env.dev` 中的端口配置
   - 数据库连接失败：确保 postgres 在运行
   - 依赖缺失：运行 `pip install psycopg psycopg-binary 'httpx[socks]'`

### 端口冲突

编辑 `.env.dev` 修改端口：
```bash
OPERATION_PORT=8881  # 改为其他端口
MANAGER_PORT=8882
AGENT_PORT=8883
```

### 清理环境

```bash
# Local 模式
./scripts/ctl.sh stop
rm -rf .state logs

# Docker 模式
./scripts/ctl.sh stop --env docker
docker-compose down -v  # 删除数据卷
```

## 对比：旧方式 vs 新方式

### 旧方式（不推荐）

```bash
# 需要手动设置一堆环境变量
env DB_URL=... ADMIN_DB_URL=... APP_RW_PASSWORD=... SERVICE_TOKEN=... \
  python server/run.py --tier=manager --port=8782 > /tmp/manager.log 2>&1 &

# 需要记住 PID
ps aux | grep "python server/run.py"

# 停止需要手动 kill
pkill -f "tier=manager"

# 日志在 /tmp 目录
tail -f /tmp/manager.log
```

### 新方式（推荐）

```bash
# 一键启动
./scripts/ctl.sh start

# 统一管理
./scripts/ctl.sh status
./scripts/ctl.sh logs --server manager --follow
./scripts/ctl.sh restart --server manager

# 一键停止
./scripts/ctl.sh stop
```

---

## 最佳实践

1. **开发时使用 local 模式**：快速迭代，方便调试
2. **测试时使用 docker 模式**：验证容器化环境
3. **修改 `.env.dev` 而不是命令行参数**：配置集中管理
4. **定期查看日志**：及时发现问题
5. **重启而不是停止后启动**：避免漏掉某个服务
