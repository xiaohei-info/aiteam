# 办公室地图设计要点与规范

版本：1.1 · 记录日期：2026-10-01  
适用范围：`office-map-edit-tool` 的 `topdown-soft` 素材库与10人办公室样板。

## 1. 核心设计结论

> **俯视为主，带一点点立体；不是严格2.5D或等距视角。空间由独立组件拼装，不使用整张办公室底图。**

- 自设计环境与家具顶面必须占主导，地面不倾斜，使用统一俯视视角。
- **工位和员工是明确例外**：按用户最新要求复用AIFred前端原有桌椅/电脑PNG和Spine员工，保留原资源视角，不再重设计。具体锚点、皮肤、动态预览与许可见 [AIFred资源复用](aifred-resources.md)。
- 用窄侧边、克制的高光和短而柔和的接触阴影表达体积。
- 墙和玻璃必须连续无缝；门洞、阴影、叶片不能被误当成完整实体占地。
- 地面、墙、连接件、门、家具和设施分别可编辑、可导出、可复用。
- 本规范是当前视觉方向。旧 `isometric-3d` 素材及早期2.5D方案仅作历史保留，不作为新素材默认参考。

## 2. 视觉与材质

### 2.1 允许与禁止

| 应采用 | 应避免 |
| --- | --- |
| 平直俯视地面和统一顶面 | 倾斜地面、等距投影或不同家具混用视角 |
| 2–3px窄边、轻微厚度 | 大面积正面立面、明显桌腿高度 |
| 短软接触阴影、少量高光 | 大范围投影、重阴影、夸张高光 |
| 接触端紧贴、纹理连续 | 多余透明inset、重复端盖和重复玻璃柱 |
| 独立地面区域与家具组件 | 把整间办公室渲染图当成可编辑布局 |

实体墙可见侧边为3px，玻璃主侧轨为2px。这是图元视觉参数，不代表真实建筑墙高。

### 3.1 扩充图元（绿植、家具、摆件）

原35款来自 Sketch 导出；后加的17款**没有 Sketch 源**，由 `scripts/topdown-extras/items.mjs` 用代码描述 SVG，`npm run extras:topdown`（`scripts/build-topdown-extras.mjs`，需本机 Chrome，可用 `CHROME_PATH` 指定）统一生成 `<id>.svg`、`<id>.png`、`<id>@2x.png` 并把元数据并入 `style.json`。叶片等重复形状用固定种子伪随机，重跑结果逐字节一致；`tests/topdown-assets.test.mjs` 会校验已提交的 SVG 和 `style.json` 与脚本一致，所以**不要手改这些文件，改 `items.mjs` 后重新生成**。新增一款：在 `items.mjs` 的 `ITEMS` 里加一项（id 以 `-top` 结尾、给出 `width/height/blocksMovement/footprints`），重新生成，再把 `tests/topdown-assets.test.mjs` 与 `tests/browser-smoke.mjs` 里的数量加一。

沿用原图元的视觉语言：俯视顶面为主、2–3px窄侧边、顶部1px高光、短接触阴影，颜色取自盆栽叶色、沙发鼠尾草灰绿、橡木和象牙白。放置约定：

- **阻挡行走的图元必须带 `footprints`**；绿植按花盆（灌木按树冠内圈）占地，叶片外沿不扩大占地，落地灯按灯杆底座占地。
- **地毯**是地面装饰：`zIndex: -90`（地面 `-100` 之上、家具 `0` 之下），不阻挡行走，不带占地。
- **桌面小摆件**（多肉、仙人掌）：`zIndex: 7`，盖在桌面（`0`）和电脑（`6`）之上、办公椅（`12`）之下，不阻挡行走。
- 绿篱花槽、矮柜、长凳都是横向素材，旋转90°作纵向使用。
- 「绿植」分类还包含原有的 `plant-top`（原来归在「家具」，现已移入，素材本身未变）。

### 导出要求

- 保留逻辑画布尺寸，2×文件宽高应恰为1×的两倍，不做自动透明裁切。
- 墙和玻璃连接端不得含多余透明边距；打开门的透明空间则必须保留。
- SVG保留矢量内容，用于设计交付；编辑器运行素材采用1× PNG。
- `design-board.png` 和 `assembly-preview.png` 仅用于规范展示/组合检查，禁止替代组件布局。
- 风格索引为 `assets/styles/styles.json`，登记 `id/name/path`；当前默认项为 `topdown-soft`。仅新建素材目录不会自动完成注册。

## 4. 地面、墙和连接规则

### 4.1 地面

- 地毯、木地板、矿物砖按128×128原生尺寸平铺，不拉伸纹理适配整个房间。
- 地面元素可以扩大区域宽高，渲染时重复纹理并裁切到区域边界。
- 当前平铺从每个元素局部左上角起铺；不同区域不会自动共享世界坐标纹理相位。需要连续拼接时应对齐起铺位置。
- 地面默认不阻挡移动。示例地面初始锁定，需在图层中解锁后编辑。

### 4.2 四向不是墙的房间位置

`up/down/left/right` 表示**窄侧边或侧轨的可见朝向**，不是墙所在的上下左右位置，也不表示改变相机角度。

例如：房间上沿向室内显示侧边时用 `wall-down`，左沿通常用 `wall-right`。其余方向按室内可见侧选择；不要仅按文件名与房间位置一一对应。

### 4.3 固定厚度与精确接触

- 实体墙固定16px厚，玻璃固定8px厚；仅沿 `stretchAxis` 延伸长度，不缩放短轴。
- 横墙端点为 `(0,8)` / `(160,8)`，纵墙为 `(8,0)` / `(8,160)`。
- 横玻璃端点为 `(0,4)` / `(160,4)`，纵玻璃为 `(4,0)` / `(4,160)`。
- 旋转、延伸后使用变换后的连接点拼接，不只依赖元素中心网格。
- 启用吸附后，邻近且朝向相反的端点可精确接触，当前容差为12屏幕像素。
- L形转角使用一个共用墙角；T/十字使用一个共用顶盖；玻璃转角只放一个共用立柱。
- 接触端不得出现重复端盖、重复侧边阴影或重复玻璃立柱。复杂的墙/玻璃混合接头需按实际厚度设计。

**关键经验：不同厚度必须按中心线对齐，不能按图片上沿对齐。** 茶水间门框厚16px、玻璃厚8px：门起始 `y=552` 时连接线在 `y=560`，玻璃起始必须是 `y=556` 才能同线。原来同设 `y=552` 会错开4px，已修正并通过连接测试。

连续墙统一地面阴影是后续建议，当前不宣称已实现整组阴影生成或连接拓扑。L/T/十字连接件仍手工放置，吸附不会建立持久连接关系，也不会带动整组墙移动。

## 5. 门、占地与操作净空

必须区分四种几何，禁止混为整张图片矩形：

| 几何 | 含义 | 当前处理 |
| --- | --- | --- |
| 视觉边界 | 含阴影、叶片和门扇活动区域的图像范围 | 用于绘制、选择命中和缩放角点 |
| 物理地面占地 | 实际阻挡行走的局部矩形集合 | `geometry.footprints`转换后用于碰撞/寻路 |
| 连接点 | 与相邻墙、门或连接件的接触位置 | `geometry.connectors`用于放置/拖动吸附 |
| 操作净空 | 椅后活动、门扇摆动、使用设施的空间 | 设计检查要求；尚无通用自动净空验证器 |

- 木门两端门框各8px，净开口72px；打开态画布88×88。
- 打开门分别记录两块门框和一块门扇占地，透明门洞不阻挡行走；禁止把整个88×88当成障碍。
- 关闭态门扇横跨开口并阻挡。开/关是独立素材，不是动画或一键状态切换。
- 盆栽视觉56×56，但实际花盆占地为局部 `(11,11,34,34)`；叶片与阴影不扩大障碍。
- 桌、柜、沙发等以素材清单占地为准。办公椅默认不阻挡移动；这不代表没有使用净空需求。
- 不要用PNG padding表达净空；也不要裁掉打开门的必要透明空间。
- 隐藏图层不会关闭碰撞；元素需关闭 `blocksMovement`，区域需关闭 `enabled` 才停用相应规则。

## 6. 10人办公室样板

### 6.1 布局与数量

画布1600×1200，背景 `null`，网格16px，共135个独立组件。图示仅表达分区关系，精确坐标以JSON为准：

```text
┌──────────────┬──────────────────┬────────────────┐
│ 会议室A · 4座 │   会议室B · 6座   │ 会议室C · 4座   │
├──打开门───────┴──打开门───────────┴──打开门─────────┤
│                  主通道                           │
├─────────────────────────────────┬────────────────┤
│  01   02   03   04   05         │ 茶水间         │
│  06   07   08   09   10         ├────────────────┤
│  工位区 / 等候 / 资料柜           │ 单人厕所       │
└────────────────入口─────────────┴────────────────┘
```

- **10个常驻工位**：双排各5张AIFred原桌、10把原椅及现有Spine演示员工，标签01–10。原俯视桌椅仍作为备用资产保留，不再用于样板常驻工位。
- **3个会议室**：各有会议桌，容量4/6/4，合计14把会议椅；不计入常驻人数10。
- **1个茶水间**：咖啡与烧水台、饮水机、清洗台、储物柜。
- **1间单人厕所**：座便器、洗手台，门向室内打开。
- **6扇打开的门**：三个会议室、茶水间、厕所、办公室入口。
- **绿植与摆件（31件，扩充图元）**：会议室四角各放龟背竹/散尾葵/蕨类/灌木，会议桌上各一盆多肉和仙人掌（落在桌中线与桌端圆点之间）；主通道北侧玻璃隔断下3个绿篱花槽；工位区右侧阅读角（圆地毯、圆茶几、朝北单人沙发、边几台灯，北面是原有盆栽）；工位区左下落地灯，资料柜旁打印机与垃圾桶；入口大厅长凳；茶水间垃圾桶与靠墙长凳；厕所一盆散尾葵。全部避开门洞与门扇摆动区、会议室门口和既有通路；这些都排在生成器末尾，原有元素 id 不变。
- 主通道范围为 `(48,416,1504,136)`；保留工位南北侧走道、右侧通路及入口内侧出生候选区。
- 出生候选区仅是候选范围，不豁免障碍或禁区。

### 6.2 标签与工位行为

- `rooms`记录房间类型、容量、范围和接近点；房间标签不会随墙体编辑自动推断或重建。
- `seats`记录10个工位及桌元素引用；移动、旋转、缩放桌会更新工位坐标和接近点。
- 椅子是独立元素，未绑定时独立编辑；AIFred样板通过 `chairOffset`绑定，桌移动/旋转/缩放时椅及员工锚点跟随。复制工位会复制其引用椅子和员工配置，删除桌清除对应座位记录。
- `seats.employee`记录现有资源ID、皮肤、动画、姓名与显示状态；工位属性可调整，顶部可暂停，显式员工朝向不被桌旋转覆盖。
- 这些元数据不等于已创建员工代理、身份分配、门禁或会议预订能力。

## 7. 在编辑器展示与携带

1. 启动项目：在 `office-map-edit-tool/` 首次运行 `npm install`，再运行 `npm start`（先本地构建Pixi/Spine员工模块），打开 `http://127.0.0.1:4174`。
2. 刷新旧页面后点击顶部「10 人样例」，确认替换；有需要保留的草稿应先导出备份。
3. 或点击「导入配置」，选择项目中的 `examples/office-10-person.json`。
4. 点击「适应画布」和「预览」查看整体；退出预览后可继续编辑。
5. 携带到另一台电脑时，可勾选内嵌PNG后导出JSON；**员工骨架/atlas/运行时不内嵌**，目标编辑器需携带 `assets/aifred/` 并构建员工模块。取消内嵌时还需携带普通素材目录。

首次无草稿会加载示例；已有IndexedDB草稿优先恢复。切换左侧素材风格只改变素材库，不会自动摆出完整办公室。

## 8. 格式、源文件与维护

- 新地图格式为 `office-map/v1.1`，局部占地和连接点放在元素 `geometry` 中。
- 支持导入旧 `office-map/v1`，无局部占地时保持整张旋转矩形语义；不能让仅懂旧v1的消费端直接处理新门洞。
- 运行图像来源仅为项目 `assets/` 下PNG/JPEG/WebP或对应内嵌data URI；SVG为设计文件，不允许作为运行图像绕过导入策略。
- 可复现装配源码：[src/office-layout.js](../src/office-layout.js)。运行 `npm run generate:example` 更新示例。
- Sketch源为文档 `6FD5CAAA-9F91-4799-93D6-008B6A661B14` 的 `Office · 俯视轻立体 v2` 页；35个Symbol源在「控件」页，前缀 `Office v2 / `。
- 原29款规范板保留，新增4款设施不在旧规范板中。PNG/@2x/SVG已导出；Sketch源当时仍是未命名文档，尚未保存，不应把导出文件误认为已保存的Sketch工程。
- 新增或修改素材时同步更新资产清单、样板装配、本文及相关断言；保留历史风格，避免覆盖用户草稿。

## 9. 验收清单与已验证基线

### 必须检查

## 10. 范围边界

- 像素布局、72px门洞、136px通道、12px角色半径均是软件设计/测试参数，不能推导建筑、消防或无障碍合规。
- 椅后净空、门扇摆动净空和设施操作空间尚未有通用自动验证；连通测试不替代这些检查。
- 四方向采样寻路较保守，狭窄复杂可行路径可能被显示为不可达。
- AITeam运行场景消费端未接入新格式，本次完成的是独立编辑工具与可导入配置。
- AIFred员工为编辑器内演示动画，不接入真实员工账号或实时状态；新资源版本需额外验证动画、绑定和配置往返，不能仅沿用此前30项基线结论。
- 主动LSP探测未报告错误，但push-only服务器无法完整确认clean，辅助风格警告仍存在；功能测试通过不等于全量静态分析或安全审计通过。
