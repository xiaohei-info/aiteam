# 本地知识文件与员工检索：方案调整

状态：2026-10-11 撤下前端本机副本知识库；保留本地文档扫描与预览、NAS 和 Manager。员工受控目录检索尚未实现，不能将应用目录授权视为员工检索授权。

## 本次调整

`4d026782`、`18af64e9` 经 `35608715` 合入的 `source: device` 功能依赖 Agent 内另一套副本、绑定和全文索引服务。选取电脑文件本身不足以要求再维护一个持久知识库，因此当前前端移除该功能：

- 撤下本机建库、导入副本、全文检索、员工绑定和专用问答入口。
- 移除 `/api/agent/local-knowledge-bases*` 与 `/api/agent/local-knowledge-documents/{document_id}` 的客户端声明和契约记录，共 7 个路径、9 个操作；移除专用开发代理。
- 旧 `device:` 详情链接显示功能已移除并提供返回入口；服务层拒绝此命名空间，不向 NAS 或 Manager 转发。
- 本次只修改前端，不删除 Agent 中此前导入的副本、索引、授权记录或聊天历史，不执行数据迁移，也不自动上传任何本地文件。

这是前端功能范围调整，不表示后端 PR 已合并、关闭或完成替代实现。

## 保留的行为

- **本地文档**：从电脑选择目录后确认扫描，可查看列表、预览和打开源文件，无需服务 URL；应用级目录授权、权限恢复与设置内撤销保持不变。扫描和预览不等于员工已可检索。
- **NAS**：`source: local`、`localUrl` 保留原有含义，即独立 NAS HTTP 服务。新建知识库固定使用 NAS；未配置 NAS 时可填写草稿，提交需有效配置。写入失败不回退到 Manager。
- **Manager**：连接企业共享知识库，保留文档上传、入库状态、重试和真实员工实例绑定；写操作仍由服务端校验 owner / enterprise_admin 权限。前端不创建多个企业库。
- 本地文档只有在用户明确选择目标库并点击上传后，才上传到对应 NAS 或 Manager。
- 受保护头像通过文档化二进制客户端读取，保留 `?v=` 缓存键；契约检查保留 NAS/Manager 与 office 地图资源的独立传输登记。
- 创建弹窗与配置弹窗保持单一活动焦点，切换时保留草稿；扫描保留逐目录 scan ID 前缀匹配与卸载保护。

## 后续受控目录方案的边界

Tauri 的 `local-file-access.json` 当前约束桌面原生命令，不是 Node Agent 的目录授权契约。后续员工目录检索需要单独实现并验收：

1. 应用级目录授权与员工/会话级授权取交集，按真实租户、成员和员工身份校验。
2. 文件工具与 Bash 子进程统一执行读取范围限制，源文件目录只读，工作区按既有规则可写。
3. 明确路径规范化、符号链接、实时撤权及运行中子进程的处理；不能用 UI 隐藏入口代替执行层权限校验。
4. 未具备可靠隔离的平台应明确禁用相应能力；现有跨平台权限 UI 不代表 Windows Agent 已可分发。
5. 本地文件可进入员工配置模型的上下文，不能承诺离线推理。

不恢复旧 `/api/agent/knowledge-bases/*` 的 410 接口，不静默迁移本地文件到企业库。若未来确有规模或性能要求，再独立论证最小持久索引方案。
