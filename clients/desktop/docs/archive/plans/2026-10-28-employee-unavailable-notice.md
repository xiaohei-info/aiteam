# 员工不可用提示与执行限制

目标：确认过的不可用事件跨登录/重启不重复弹出；不可用员工保留资料及聊天历史，输入禁用并显示具体原因；服务端阻止新执行。

边界：仅更改现有 Manager 快照错误码、Agent 员工投影的可选可用性字段及前端消费，不新增 API 路径。不把所有 404/409 当成员工下架，不改授权撤销语义，不删除旧会话。

实施顺序：
1. Manager snapshot_service 为员工非 active、平台 Provider/模型/价格不可用提供稳定原因码；版本冲突仍为临时同步失败。
2. Agent manager-client 保留原因码；同步失败保留旧投影/快照，并在员工投影 JSON 持久化 availability_reason/availability_revision。连续同原因复用事件版本；成功同步清除不可用字段。不可用投影强制下次拉取，以支持恢复；首次失败也保留可展示的员工资料。
3. SessionHost 在统一执行授权点校验不可用状态及生命周期，覆盖私聊、群聊派发和后台执行；读取历史不受影响。
4. AITeam 通过员工投影消费状态；本机 localStorage 按 tenant/member/employee/availability_revision 持久化确认，只显示未确认事件。聊天输入和发送函数统一阻止不可用员工，禁用附件/语音/队列自动发送。
5. 测试覆盖错误分类、失败持久化与恢复、成员隔离、服务端执行阻止、跨组件重挂载确认不再弹、账号隔离、新事件再提示、输入禁用。

完成标准：有对应自动化回归测试，前端构建/定向 lint 与 Agent build、Manager 定向单测通过；不声称已完成桌面视觉验证。
