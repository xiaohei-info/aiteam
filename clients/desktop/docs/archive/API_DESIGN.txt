三、WebSocket 接口
==================

连接
----
ws://<host>/ws?token=<encoded_token>

- 单例连接，登录后自动建立，登出时断开
- 状态：disconnected → connecting → connected | error

消息帧结构
----------
服务端 → 客户端：

ServerMessage {
  id: string                // 服务端消息唯一 ID
  conv_id: string           // 对话 ID
  sender_id: string
  receiver_id: string
  msg_type: MsgType
  content: string           // 文本内容 或 JSON 字符串
  created_at: number        // ms 时间戳
  thinking?: string         // AI 推理过程（可选）
}

客户端 → 服务端：

MessageAck {
  type: 'ack'
  message_id: string
}

Ping {
  type: 'ping'
}

流式播放协议（当前 Mock，待服务端对齐）
----------------------------------------
当前客户端通过 setInterval(18ms, +3字符) 模拟流式打字效果。
建议服务端采用 SSE 或 WebSocket 分块推送：

StreamChunk {
  type: 'stream_chunk'
  conv_id: string
  message_id: string
  delta: string             // 本次增量内容
  done: boolean             // 是否结束
}

七、关键注意点
==============

1. local_id 回填
   发送消息前须生成 UUID 作为 local_id，服务端 ack 后通过 db_update_message_server_id 回填，
   避免重复消息。

2. 知识库进度轮询
   文档索引为异步任务，需轮询 GET /knowledge-bases/:id 或 WebSocket 推送 progress 事件。

3. AgentExtra 序列化
   Agent 扩展信息存为 users.extra JSON 字符串，读写时需 JSON.parse/stringify。

4. WebSocket 重连
   当前无自动重连逻辑，断线后需手动触发 connect()，建议增加指数退避重连。

5. 文件发送流程
   先 POST /files/upload 获取 CDN URL，再 POST /messages 携带 URL，
   两步原子性需客户端保证。
