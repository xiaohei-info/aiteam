# 本机文件访问授权

应用启动时，如果此设备尚未处理过授权，会显示本机文件访问提示。系统目录选择器默认定位磁盘根目录；只有用户确认选中的目录及子目录获得应用内读取授权。授权不会自动触发全盘扫描，也不会上传文件。

在对话中使用授权目录需要另外登记，规则不同：员工用检索工具读到的片段会随对话发送给模型服务，并保存在本机对话记录中，见[本地目录检索技术设计](plans/local-directory-knowledge-design.md)。

已授权目录保存在应用数据目录的 `local-file-access.json`，应用重启后恢复。选择“暂不授权”或在设置中取消授权后，后续启动不重复打扰；实际读取失败时仍可按需授权。

## macOS

1. 在授权窗口点击“选择根目录授权”。
2. 在系统选择器按 `⌘⇧G`，输入 `/` 并确认选择；也可以只选择所需文件夹。
3. 若桌面、文稿、下载或外置磁盘仍被系统拒绝，进入“系统设置 → 隐私与安全性 → 文件与文件夹”，检查 AIFred 对应权限。
4. 如果列表中没有 AIFred，进入“完全磁盘访问权限”，点击列表下方的“＋”，选择正在使用的 `AIFred.app`（通常在“应用程序”中），按系统提示验证身份并开启开关，然后完全退出并重新启动应用。若应用还在 DMG 中，请先拖入“应用程序”。

“文件与文件夹”列表由系统在应用访问受保护目录时生成，不能手动添加。应用内的根目录授权不会自动把 AIFred 加入“完全磁盘访问权限”列表。开发模式运行的进程也不等于已安装的 `AIFred.app`；应使用实际安装的应用验证系统权限。

应用内授权不能绕过 macOS TCC、文件权限或系统保护。当前应用并未使用 App Sandbox；如果未来启用 Sandbox，需要另外引入 security-scoped bookmarks，不能把路径记录当作系统授权凭据。

## Windows

1. 在系统选择器的“此电脑”中选择需要使用的磁盘根目录，例如 `C:\`、`D:\`，支持多选。Windows 没有覆盖所有盘符的单一根目录。
2. 也可以选择特定文件夹或有访问权限的网络共享。新挂载的磁盘需要另行授权。
3. 系统仍拒绝访问时，检查“设置 → 隐私和安全性 → 文件系统”（Windows 10 为“隐私 → 文件系统”）中的适用开关，以及文件夹“属性 → 安全”中当前用户的读取权限。
4. 网络共享还需有效的共享凭据与共享权限。目录选择不会修改 ACL，也不会提权。

## 权限不足时

知识库的扫描、预览、文件读取及系统打开入口会区分应用内授权缺失和系统拒绝访问，显示恢复弹窗。可重新选择所属目录、打开系统权限设置，或调整权限后点击重试。原生读取步骤最多重试一次，不重复上传业务请求；取消则保留原错误。

## 取消授权

进入“设置 → 本机文件访问权限”，可以取消单个目录或全部目录。取消会持久化，后续读取会重新检查授权，进行中的扫描在下一次目录检查时停止。已经读取进内存的内容、历史扫描列表、已导入的文件副本不会自动删除。

这组授权独立于 Tauri WebView asset scope，不会把磁盘根目录作为网页资源暴露。文件选择器单独选择的文件仍保留其单文件访问许可。应用内取消目录授权不会修改操作系统的隐私开关，如需撤销 macOS TCC 或 Windows 系统权限，应在系统设置中单独关闭。

## 分发给其他人的包

应用内授权记录在每台机器的应用数据目录里，不会随安装包携带。接收方首次打开会看到授权提示，需要自己选择目录；他们不会继承你的授权，也不会读到你的路径。

但**不能保证接收方“不报权限不足”**：

1. **系统权限仍需各自授权。** 无 App Sandbox 时，在系统选择器里选目录只影响应用内范围，不等于 macOS TCC 授权。读取桌面、文稿、下载、外置磁盘时，macOS 仍会弹自己的授权框；拒绝会进入“系统限制了文件访问”弹窗。这是预期行为，无法由应用自动代劳。
2. **未签名/未公证时授权不稳定。** 当前未配置 Developer ID 签名与公证（DMG 内附“修复应用无法打开.command”用于清除下载隔离属性），Gatekeeper 会拦截首次打开。而且系统按应用身份与可执行文件指纹记忆授权，重新构建后指纹变化，原来的系统授权通常失效，需要接收方重新授权。
3. **架构不通用。** arm64 与 x86_64 分别构建，arm64 包无法在 Intel Mac 上运行。
4. **Windows 暂不可用。** 内嵌 Agent 目前仅支持 Apple Silicon macOS，非 macOS 下启动本地 Agent 会直接失败，因此权限模块的 Windows 分支在可分发安装包中走不到。
5. **扫描记录是绝对路径。** 若缓存中带有其他机器或账号的路径（例如 `/Users/别人/...`），会显示文件但读取失败，此时走恢复弹窗提示重新授权。正常分发新包不会带入这类记录。

要做到“发给别人也能顺利使用”，需要：用 Developer ID Application 证书签名、用 `notarytool` 公证并 staple、保持 bundle identifier 与签名身份稳定（specifier 不变才能延续系统授权），并保留现有的权限引导。macOS 不允许应用静默取得全盘权限，因此不存在“无需用户授权即可访问任意目录”的分发包。另外当前启用 `macOSPrivateApi`，无法上架 Mac App Store。

当用户授权一个宽范围目录（例如 `/`）时，系统保护子目录会被跳过，只有用户显式选中的根目录读取失败才会使该目录的扫描报错；跳过的子目录数量目前不单独计数上报。

## 验证

- `node --experimental-strip-types --test tests/fileAccessPolicy.test.ts tests/knowledgeLocalScan.test.ts`
- `cargo test --manifest-path src-tauri/Cargo.toml --lib`
- `node scripts/check-tauri-security.mjs`
- `node tests/file-access-browser-smoke.mjs`：启动独立 Vite / Chrome，模拟原生 IPC，检查首次授权、重启、撤销、恢复、系统错误、Windows 多盘符、深浅主题与窄屏布局。Chrome 默认使用 macOS 安装位置，可通过 `CHROME_BINARY` 指定；不代表原生系统选择器或 TCC / ACL 的实机验证。

界面沿用现有黑金毛玻璃设计令牌（`--brand-gradient`、`--surface-1-glass`、`--radius-xl`、`--duration-panel` 等），弹窗出场为淡入加缩放位移，并响应 `prefers-reduced-motion`。弹窗与遮罩显式使用 `box-sizing: border-box`，因为项目未设置全局边框包含，否则 1px 边框会在窄窗口产生溢出。截图：`output/file-access-smoke/`。

Windows 完整客户端另受现有内嵌 Agent 平台支持限制；权限模块的 Windows 路径与系统设置分支不能替代完整 Windows 安装包验收。
