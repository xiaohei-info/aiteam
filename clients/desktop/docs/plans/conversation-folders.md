# 会话目录：检索目录与工作目录合并展示、按权限档读写

## 目标（2026-11-09 用户决定）

1. 检索目录和工作目录合在一起展示：权限面板的「本会话的目录」区，第一行是工作目录，下面是本会话添加的目录。
2. 添加的目录：员工照常能用检索工具 `local_dir_search` / `local_dir_read` 查资料，同时可以像工作目录一样用 bash/read/write/edit 直接操作，读写按本会话权限档。
3. 同一员工的不同会话，目录列表完全分开：A 会话添加的目录 B 会话看不到，移除只影响本会话。
4. 旧绑定按之前的方案 A（已迁移到各会话）。
5. 群聊里的员工共用同一个工作目录和同一份添加的目录（见下面「群聊共用」）。

## 设计

### 数据与接口（Agent）

- 不新建表。目录登记仍按成员保存（`local_directory_resource`，用户看不到），会话的目录列表 = 本会话里开着的绑定（`local_directory_conversation_binding`）。
- `GET /api/agent/local-directories?conversation_id=` 只返回本会话有开着绑定的目录；不带会话时返回全部登记（绑定为空）。
- 添加 = 宿主票据登记（同一路径复用登记）+ 本会话开启绑定；移除 = 本会话关闭绑定。不新增路由。

### 沙箱（Agent）

- `LocalSandbox.operations/assertAvailable` 接收额外根目录。路径检查对任一根目录内的路径放行，bash 的 cwd 也可以在任一根目录内。
- macOS Seatbelt 规则在原有禁网和读取边界后，追加额外目录的读取许可；「工作区可写」档再追加写入许可。已用 `sandbox-exec` 实测：额外目录可读可写，其他目录和用户主目录读写都被拒。
- Linux 沙箱不能追加规则：有额外目录时拒绝执行（不放宽）。本地目录只有 macOS 宿主能签票据。
- 「完全访问」档本来不受限，不变。
- 额外目录列表进入会话能力签名（变化后下一轮重建 Pi 会话）和审批的 `permissionRevision`（变化后之前的批准作废）。磁盘上已不存在的目录不加入。
- 系统提示列出额外目录的路径。

### 前端（桌面）

- 「本会话的目录」区：工作目录（项目对话显示路径和「更换目录」；普通会话显示「本会话的文件夹，由 AIFred 管理」），下面是添加的目录（可移除），底部「添加目录」。
- 「本会话的权限」三档放在目录区下面，说明对上面所有目录生效。
- 草稿会话添加目录时先创建会话。

### 群聊共用（2026-11-09 用户决定）

- 工作目录：群聊所有员工共用 `workspaces/<会话名>-<短 ID>/`。老群不搬文件，原来的员工文件夹留作普通子文件夹，每位员工都能看到和修改。启动时的迁移（`shareGroupFolders`）只改数据库里的路径，可重复执行。
- 添加的目录：绑定只按会话（表 `local_directory_conversation_folder`，路由 `PUT /api/agent/conversations/{id}/local-directories/{directory_id}`），新加入的成员也能用。迁移时只要有一位员工开着，会话就保留这个目录。
- 同时改文件：bash、write、edit 按会话排队（`ConversationWriteQueue`），一次只有一位员工执行。排队发生在用户批准之后，等待批准的请求不挡别人；读文件不排队。项目对话不进这个队列。
- 记忆：记忆库仍是员工自己的。插件状态和 retain 游标按「会话 + 员工」放在 Agent 数据目录，不写进共用目录。插件按 cwd 文件夹名打标签并过滤召回，所以老群成员把原文件夹名固定成项目标签（`member-project-id`），旧记忆还能召回；之后加入的成员用状态目录名。
- 产物：路径不再加员工前缀，老文件夹作为路径的一部分自然出现；长回复放 `回复/`，文件名带员工名。
- 工作台：共用一个目录的群显示一部分，不分员工；还没合并的老群仍按员工分部分。

## 风险

- 员工可以改写添加的文件夹。「工作区可写」档每次 bash/write/edit 都要用户确认；「完全访问」不确认。
- macOS 受保护位置（桌面、文稿等）可能被系统拦截，需要给 AIFred 开「完全磁盘访问权限」。真实应用里要验证。
- 改动沙箱边界和列表接口语义，属于 AGENTS.md §8 高风险项，已经用户确认方向。

## 验证

- 沙箱单测：多根目录路径检查、符号链接逃逸、Seatbelt 规则内容；macOS 上真实 `sandbox-exec` 测试（额外目录可写、其他目录被拒、只读档额外目录不可写）。
- Agent：列表按会话过滤、额外目录随绑定变化、审批作废。
- 前端：面板结构、契约检查。
- 全量测试后重建随包 Agent，用户在真实应用验收。
