# 4. 员工记忆查看

## 4.1 现状

| 项 | 现状 | 依据 |
|---|---|---|
| 入口 | 员工详情「记忆摘要」卡片：一段摘要文字 +「查看详情 →」 | `AgentDetailPanel.tsx` |
| 「查看详情」 | 跳 `/memory?employee=…`，但**路由不存在**，被兜底重定向到 `/chat`，看起来点了没反应 | `src/App.tsx` 路由表 |
| 摘要来源 | 员工投影里的 `memory_summary` 或 `memory_policy.summary` | `stores/chat.ts` |
| 记忆存储 | Manager 侧 Hindsight。存储范围是「企业 + 员工」：**同一个员工的所有成员共享一份记忆** | FredServer `hindsight_credentials.py` `derive_hindsight_bank_id` |
| 列表接口 | `GET /api/manager/memories?employee_id=&keyword=&limit=&offset=`，返回 `memory_id、content、category、importance、source、created_at、last_used_at、state` | `routes_memory_items.py` |
| 编辑、删除 | `PATCH /api/manager/memories/{id}`（改文本、改状态 valid/invalidated）、`DELETE` | 同上 |
| 统计 | `GET /api/manager/memories/analytics`：数量、分类、重要度、新鲜度 | 同上 |
| 权限 | 列表、统计、编辑、删除都是 `management=True`，**只有企业 owner 和企业管理员**能调 | `memory_service.py` `_authorize` |
| 写入来源 | 「开启新上下文」时保存，元数据有 `source: context_reset`、`conversation_id`、`context_id`，**没有成员 ID** | `session-host.ts` |

要点：
1. 普通成员现在**读不到**任何记忆条目，只能看到一段摘要。
2. 因为记忆是成员共享的，如果直接把列表权限开放给普通成员，成员 A 能看到成员 B 对话里沉淀下来的内容。**这是隐私问题，不能只改权限。**

## 4.2 谁能看什么（需要你决定）

| 方案 | 普通成员 | 企业管理员 | 需要的后端改动 |
|---|---|---|---|
| **A（推荐）只看自己贡献的** | 能看由**自己的对话**产生的记忆；能删除自己贡献的记忆；看到其他记忆的数量（「另有 32 条来自其他同事」），看不到内容 | 看全部，可编辑、标记失效、删除 | ① 保存时记录贡献者：Manager 在 retain 时根据登录身份写入 `contributor_member_id`（服务端写入，不信任客户端）；② 列表支持 `scope=mine`，普通成员只能用 `mine` |
| B 只有管理员能看 | 只看摘要（现状） | 看全部 | 只需要前端做页面 |
| C 全员可看 | 看全部，只读 | 看全部，可编辑 | 放开列表权限；需要企业明确告知成员「你和员工的对话会被同事看到」 |

推荐 **A**：符合「谁的数据谁可见」；用户能核对员工记住了自己什么，并删掉不想被记住的内容。

已有的历史记忆没有贡献者字段：A 方案下这部分对普通成员显示为「来源未知（N 条）」，只给管理员看。

## 4.3 入口形态

### 方案 A（推荐）：员工详情里的二级视图

点「记忆摘要」卡片的「查看全部」，在员工详情面板内滑入一个二级视图，和现有「自动化任务」二级视图是同一种交互（顶部「‹ 返回」）。

- 优点：不离开对话；和自动化任务一致；不新增路由。
- 缺点：面板宽度有限（约 360px），长记忆要折叠。

### 方案 B：独立页面

新增 `/employees/:id/memory`，左边是员工列表，右边是记忆时间线。适合管理员批量整理记忆。

推荐：**普通成员用 A**；管理员在 A 的二级视图顶部多一个「在完整页面中管理」入口，进入 B（B 可以放到第二阶段）。

## 4.4 二级视图内容

```
‹ 返回   小李的记忆                         [只看我的 ▾]
┌──────────────────────────────────────────────────────┐
│ 42 条 · 本周新增 6 · 最近一次被用到 今天 10:21          │
│ 🔍 搜索记忆                                            │
│ [全部] [事实] [偏好] [经验] [已解决] [未解决]            │
├ 今天 ────────────────────────────────────────────────┤
│ 用户偏好周报用表格形式，按项目分组。                      │
│ 偏好 · ★★★☆ · 来自对话「周报整理」 · 10:21 被用到   ⋯   │
├ 本周 ────────────────────────────────────────────────┤
│ 「采购审批」流程需要先抄送财务，再提交总监。               │
│ 事实 · ★★☆☆ · 来自对话「采购流程」 · ✓ 已解决       ⋯   │
│ ……                                                    │
├ 更早 ────────────────────────────────────────────────┤
│ ……                         [加载更多]                  │
│ ⓘ 另有 32 条来自其他同事的对话，仅管理员可见              │
└──────────────────────────────────────────────────────┘
```

| 元素 | 说明 |
|---|---|
| 顶部统计 | 条数、本周新增、最近被用到的时间；来自 `analytics`，接口不可用时只显示条数 |
| 搜索 | 走列表接口的 `keyword` 参数，300ms 防抖 |
| 分类标签 | 按服务端返回的 `category` 原值生成；中文名映射表需要服务端给出枚举，前端不猜。「已解决 / 未解决」来自议题 1 写入的结果标签 |
| 分组 | 按 `created_at` 分为今天 / 本周 / 更早 |
| 单条 | 正文（超过 3 行折叠，可展开）；分类、重要度（4 档星，由 `importance` 0–1 换算）、来源对话（可点击，跳到该对话对应的「新上下文」分隔线）、最后被用到的时间 |
| ⋯ 菜单 | 普通成员：「删除这条记忆」（仅自己贡献的）。管理员：「编辑」「标记失效」「删除」 |
| 已失效的记忆 | 默认不显示；管理员可以切换「显示已失效」，失效条目置灰并带删除线 |

## 4.5 状态

| 状态 | 显示 |
|---|---|
| Hindsight 未配置（`not_configured`） | 「企业还没有开通记忆服务」 |
| 员工记忆策略不允许 | 「这位员工没有开启记忆」 |
| 服务暂不可用 | 「记忆服务暂不可用 · 重试」 |
| 没有记忆 | 「还没有记忆。点「问题已解决 / 问题未解决」结束一段对话后，关键内容会保存在这里」（与议题 1 呼应） |
| 删除 | 二次确认「删除后员工将不再记得这条内容，不可恢复」；删除后从列表移除，并显示 5 秒提示 |

## 4.6 摘要卡片调整

- 文字「查看详情 →」改为「查看全部 42 条 →」，条数加载失败时只显示「查看全部 →」。
- 修掉 `/memory` 死链：改为打开二级视图。

## 4.7 视觉规范

- 二级视图沿用 `.adp-nested-view`。
- 单条记忆是一张卡片：`--glass-card-bg`、`--radius-lg`、内边距 12px；元信息行 12px `--text-muted`；分类标签用药丸样式。
- 重要度星用 `--brand`，未亮的星用 `--surface-4`。
- 结果标签：已解决 `--success-bg` + `--success`，未解决 `--warning-bg` + `--warning`。

## 4.8 数据与接口

经由本机 Agent 转发，前端不直接连 Manager：

```
GET    /api/agent/employees/:id/memories?scope=mine|all&keyword=&category=&cursor=&limit=
GET    /api/agent/employees/:id/memories/summary          条数、本周新增、最近被用到、仅他人可见数
DELETE /api/agent/employees/:id/memories/:memory_id
PATCH  /api/agent/employees/:id/memories/:memory_id       管理员：改文本、改状态
```

Manager 侧：
1. retain 时写入 `contributor_member_id`（取登录身份）。
2. 列表增加 `scope=mine`；普通成员调用时强制 `mine`，管理员可以用 `all`。
3. 列表返回 `conversation_id`、`outcome`（来自元数据的白名单字段），用于来源跳转和结果标签。
4. 普通成员只能删除 `contributor_member_id` 是自己的条目。

## 4.9 验收标准

1. `/memory` 死链消失。
2. 普通成员看不到其他成员贡献的记忆内容（需要接口级测试，不能只靠前端过滤）。
3. 管理员能看到全部，编辑和标记失效后列表即时更新。
4. 点来源对话能跳到对应的分隔线。
5. 五种状态（未开通、员工未开启、不可用、空、删除）显示正确。
