# 7. 人才市场字段细化

## 7.1 现状

### 服务端实际返回的字段（`MarketplaceTemplate`）

`template_id`、`display_name`、`category`、`description`、`model_name`（可能为空字符串）、`skills_count`、`recruit_count`（可能为 null）、`is_recruited`、`tags`、`avatar_url`、`platform_skill_refs[]`（技能 ID、版本、内容哈希、展示名）。

### 界面上预留了但拿不到数据的字段

| 位置 | 字段 | 现在显示 |
|---|---|---|
| 卡片 | 单次价格、累计费用 | 没有数据时隐藏（1d406e09 改的） |
| 详情 · 基础 | 计费方式、单次价格、月度套餐 | 「数据未提供」+ 一行说明「人才目录尚未提供……」 |
| 详情 · 基础 | 典型工作案例 | 空态「暂无可核验历史案例」 |
| 详情 · 基础 | 累计费用 | 「数据未提供」 |
| 详情 · 技能 | 每个技能的说明 | 固定文案「可在企业后台继续调整技能策略」 |
| 详情 · 知识 / 外部系统 / 入职上下文 | 推荐资料、推荐系统、带入的上下文 | 大多为空态 |
| 筛选 | 价格区间、职级 | 没有数据源 |

问题：字段是「先画出来再等数据」，导致详情页大部分是空态；同时缺少用户做招募决策真正需要的信息，例如「适合做什么、不适合做什么」「需要我提供什么」「效果怎么样」。

## 7.2 用户招募时要回答的问题 → 字段

| 用户问题 | 字段 | 放在哪 |
|---|---|---|
| 它是做什么的？ | 一句话定位、岗位类别、能力标签 | 卡片 |
| 适合我的场景吗？ | 适用场景、不适用场景、示例问题 | 详情 · 概览 |
| 它能交付什么？ | 产出类型（文档、表格、代码、PPT、操作外部系统）、示例产出 | 卡片（图标）、详情 · 概览 |
| 需要我准备什么？ | 需要的外部系统（MCP/连接器）、推荐的知识、需要的权限（是否需要完全访问、本机目录） | 详情 · 接入要求 |
| 效果好不好？ | 解决率（议题 1）、招募数、平均响应时长 | 卡片（1 项）、详情 · 数据 |
| 要花多少钱？ | 计价方式、参考单价、平均每次任务的 Token | 卡片（1 项）、详情 · 成本 |
| 谁做的、可靠吗？ | 发布者、版本、更新时间、更新说明 | 详情 · 底部 |
| 我的数据去哪？ | 使用的模型和服务商、记忆策略（是否保存对话记忆）、数据是否外发 | 详情 · 数据与隐私 |

## 7.3 字段字典

「来源」列：**现有** = 服务端已返回；**新增** = 需要 Manager 模板增加；**派生** = 由统计计算得出。

### 卡片（列表扫读，控制在 3 秒内能判断要不要点开）

| 字段 | 来源 | 规则 |
|---|---|---|
| 头像 | 现有 `avatar_url` | 没有时用名字首字 |
| 名称 | 现有 `display_name` | 1 行，超出省略 |
| 岗位类别 | 现有 `category` | |
| 一句话定位 | **新增** `tagline` | ≤ 40 字；缺失时取 `description` 前 40 字 |
| 能力标签 | 现有 `tags` | 最多 3 个，多出显示「+N」 |
| 产出类型图标 | **新增** `output_types[]` | 最多 4 个小图标：文档 / 表格 / 代码 / 演示 / 操作系统 |
| 关键指标 | 见下 | **最多 3 项**，没有数据的不显示，不显示「数据未提供」 |
| 状态 | 现有 `is_recruited` + 本机可用性 | 已招募 / 可招募 / 需管理员招募 / 暂不可对话 |

关键指标候选（按优先级取前 3 个有数据的）：

| 指标 | 来源 | 显示条件 |
|---|---|---|
| 解决率 | 派生（议题 1 汇总到 Manager） | 全企业已评估 ≥ 20 段 |
| 招募数 | 现有 `recruit_count` | 不为 null |
| 计价 | **新增** `pricing` | 有计价信息 |
| 技能数 | 现有 `skills_count` | 前三项不足时补位 |
| 默认模型 | 现有 `model_name` | 前三项不足时补位 |

### 详情（决策和准备）

把现在的标签页调整为 4 个：

| 标签页 | 区块 | 字段 | 来源 |
|---|---|---|---|
| **概览** | 定位 | 一句话定位、完整描述 | 新增 / 现有 |
| | 适用场景 | `use_cases[]`（每条 ≤ 30 字，3–6 条） | 新增 |
| | 不适用 | `limitations[]`（1–3 条） | 新增 |
| | 示例问题 | `example_prompts[]`（3 条）；已招募时点击直接带入对话输入框 | 新增 |
| | 示例产出 | `sample_outputs[]`（标题 + 类型 + 预览链接） | 新增；替代现在的「典型工作案例」空态 |
| **能力** | 技能清单 | 每个技能：展示名（现有）、一句说明（**新增** `platform_skill_refs[].summary`）、版本（现有） | 现有 + 新增 |
| | 产出类型 | `output_types[]` | 新增 |
| **接入要求** | 外部系统 | `required_connectors[]`（必需）、`optional_connectors[]`（可选）；显示本企业是否已开通 | 新增 + 本地判断 |
| | 推荐知识 | `recommended_knowledge[]`（类别描述，例如「产品手册」），不是具体知识库 | 新增 |
| | 需要的权限 | `required_permissions`：是否需要完全访问、是否需要本机目录（与议题 2 对应） | 新增 |
| | 入职上下文 | 现有「新员工入职时带入的上下文」 | 现有 |
| **数据与成本** | 质量 | 解决率、已评估段数、平均响应时长、常见未解决原因前 2 个（议题 1 的原因标签） | 派生 |
| | 规模 | 招募数、活跃企业数（近 30 天） | 现有 + 派生 |
| | 成本 | 计价方式（按次 / 按 Token / 套餐）、参考单价、平均每次任务 Token | 新增 + 派生 |
| | 数据与隐私 | 模型和服务商、是否保存对话记忆、数据是否发往第三方 | 现有 + 新增 |
| 底部 | 发布信息 | 发布者、版本、更新时间、更新说明链接 | 新增 |

### 字段缺失时的规则

- 整个区块没有数据：**整个区块隐藏**，不显示空态说明。（例外：「接入要求」即使为空也显示一句「无需额外配置」，因为这是有意义的信息。）
- 单个字段没有数据：该行隐藏。
- 不显示「数据未提供」「待服务端提供」这类开发阶段的文案。

## 7.4 筛选与排序

| 筛选 | 来源 | 说明 |
|---|---|---|
| 岗位类别 | 现有 | 保留 |
| 能力标签 | 现有 | 保留 |
| 产出类型 | 新增 | 新加 |
| 无需外部系统 | 新增 | 开关：只看开箱即用的 |
| 价格 | 新增 | 有计价数据后才显示，否则隐藏 |
| 职级 | — | **建议删除**：没有数据源，也不是招募决策的关键因素 |

排序：推荐（默认）/ 招募最多 / 解决率最高（样本不足的排后）/ 最近更新。

## 7.5 视觉规范

- 卡片高度固定，指标区固定 3 格，缺数据时剩下的格子留空，而不是让卡片忽高忽低。
- 解决率：≥ 80% 用 `--success`，60%–80% 用 `--text-primary`，< 60% 用 `--warning`。
- 产出类型图标 14px，`--text-secondary`，悬停显示名称。
- 示例问题做成可点击的药丸，已招募时有金色悬停态，未招募时为纯展示。

## 7.6 接口

Manager 模板（`MarketplaceTemplate`）增加：

```
tagline, use_cases[], limitations[], example_prompts[], sample_outputs[],
output_types[], required_connectors[], optional_connectors[], recommended_knowledge[],
required_permissions { full_access: bool, local_directories: bool },
pricing { mode: 'per_call' | 'per_token' | 'subscription', unit_price, currency },
memory_policy_summary, publisher, version, updated_at, changelog_url,
stats { resolution_rate, evaluated_segments, avg_latency_ms, active_tenants_30d, top_unresolved_reasons[] }
```

`stats` 由 Manager 根据议题 1 上报的段落评估汇总，按天更新。

## 7.7 验收标准

1. 详情页不再出现开发阶段文案（「待服务端提供」「数据未提供」）。
2. 卡片高度一致，指标最多 3 项。
3. 已招募时点击示例问题，能直接打开对话并填入输入框（不自动发送）。
4. 「需要的外部系统」能正确显示本企业是否已开通。
