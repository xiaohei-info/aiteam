# 1. 开启新上下文 → 「问题已解决 / 问题未解决」

## 1.1 现状

| 项 | 现状 | 依据 |
|---|---|---|
| 入口 | 消息列表右上角一个金色描边的药丸按钮「开启新上下文」 | `src/components/Chat/ContextResetButton.tsx`、`Chat.css` `.chat-context-reset` |
| 行为 | `POST /api/agent/conversations/:id/context/reset`；清空模型上下文、把旧上下文交给 Manager 记忆、保留历史消息 | `src/api/agent/conversations.ts` |
| 禁用 | 本轮回复生成中（含排队消息）禁用 | `generating` |
| 记忆失败 | 临时失败时后端默认不重置，弹窗让用户选「不保存记忆，继续开启」（`on_memory_failure: 'proceed'`） | `contextResetMemory.ts` |
| 分隔线 | 消息流里出现「— 新上下文 · 记忆已保存 —」 | `ContextResetDivider` |
| 群聊 | 所有参与员工一起重置，共用一条分隔线 | 同上 |

问题：开启新上下文时，用户其实已经对上一段对话的结果有了判断（解决了，或者没解决只好换个问法重来），但这个判断没被记录。员工质量、人才市场和工作台都缺少「结果」这一信号。

## 1.2 目标

1. 一次点击同时完成两件事：**结束当前这段上下文** + **记录这段的结果**。
2. 结果数据可以被员工详情（解决率）、人才市场（质量指标）、工作台（存为解决方案）、记忆（带结果标签）复用。
3. 不增加负担：评估一键完成，原因和备注都可选。

## 1.3 概念定义

| 术语 | 定义 |
|---|---|
| 上下文段（segment） | 同一会话里，两次重置之间的那段对话。会话第一段从会话创建开始 |
| 结果评估（outcome） | 用户对一个上下文段给出的结果：`resolved` 已解决 / `unresolved` 未解决。没点按钮就离开的段为「未评估」，不算进统计 |
| 解决率 | 已解决段数 ÷（已解决 + 未解决段数）。未评估不进分母；样本少于 10 段时不显示百分比 |

## 1.4 方案

### 方案 A（推荐）：分段双按钮

右上角原位置换成一个**分段按钮**：

```
┌──────────────────────────────┐
│ ✓ 问题已解决 │ ↻ 问题未解决   │   ← 悬停提示：结束本段对话并开启新上下文
└──────────────────────────────┘
```

- 左边「问题已解决」：金色实心（主操作）；右边「问题未解决」：描边（次操作）。
- 点「已解决」：立即重置并记为已解决，顶部提示「已记为已解决，已开启新上下文 · 撤销」（5 秒）。如果本段生成过文档，提示里多一个「存为解决方案」按钮，与议题 8 衔接。
- 点「未解决」：先弹出一个小浮层（不是全屏弹窗），可选原因标签，也可以直接跳过：

```
这段对话哪里没解决？（可跳过）
[答非所问] [信息不够] [执行失败] [结果不对] [太慢] [其他]
备注（选填）______________________
□ 保留为待跟进事项
                     [跳过]  [记为未解决并开启]
```

- 分隔线增加结果：`— 新上下文 · ✓ 已解决 · 记忆已保存 —` / `— 新上下文 · ↻ 未解决：信息不够 · 记忆已保存 —`。

优点：一眼可见，一次点击完成，和原按钮位置一致，学习成本低。
缺点：占用宽度比原来大（约 220px 对比 120px），窄窗口要降级（见 1.6）。

### 方案 B：回复结束后的提示条

员工回复结束、并且距上次重置已有 ≥2 轮对话时，在输入框上方出现一条可关闭的提示：

```
这个问题解决了吗？   [✓ 已解决，开新话题]   [↻ 没解决，换个思路]   ×
```

优点：时机好，更容易被注意到，评估覆盖率更高。
缺点：会打扰继续追问的用户；群聊里节奏快，容易反复出现；不适合作为唯一入口。

### 方案 C：保留单按钮 + 二次选择

按钮仍叫「开启新上下文」，点击后弹窗二选一。

优点：改动最小。缺点：多一次点击；用户会习惯性跳过选择，数据质量差。

### 推荐

**A 作为主入口**。B 作为可选增强：只在**单聊**、回复里**生成了文档**时出现（这时「是否解决」最有价值，也和工作台衔接），每段最多出现一次，关掉后本段不再出现。

## 1.5 交互规则

| 场景 | 规则 |
|---|---|
| 生成中 | 两个按钮都禁用，提示「本轮回复结束后才能结束本段」（沿用现有逻辑） |
| 本段还没有任何消息 | 两个按钮都禁用，提示「当前已是新上下文」，替代现在点了再提示 `already_reset` 的做法 |
| 记忆保存失败 | 沿用现有「记忆保存失败」确认弹窗；用户选「不保存记忆，继续开启」时，**评估结果随重试请求一起提交**，不能丢 |
| 撤销 | 5 秒内可撤销**评估**（段落变回「未评估」）；上下文重置本身不可撤销，提示文案要说清楚：「撤销只取消评估，新上下文保持开启」 |
| 事后修改 | 鼠标悬停在分隔线上出现「修改评估」，可以改成另一种结果或补原因，7 天内有效 |
| 群聊 | 评估针对整段群聊，由当前用户提交一次；所有参与员工共享这个结果（每个员工的解决率都会计入） |
| 已下架、暂停的员工 | 沿用现有 `unavailable`：状态栏不显示，按钮不出现 |
| 键盘 | 分段按钮是一个 `role="group"`，两个按钮可以用 Tab 和方向键切换；浮层用 Esc 关闭 |

## 1.6 视觉规范

- 位置、高度不变：吸附在消息列表右上角，高 28px，全圆角。
- 左段：`--brand-gradient` 背景，`--text-on-brand` 文字，图标 `CircleCheck`。
- 右段：`--surface-glass-subtle` 背景，`--glass-gold-border` 描边，`--text-secondary` 文字，图标 `RotateCcw`。
- 两段之间用 1px `--border` 分隔。
- 窗口宽度 < 900px：只显示图标，文字放进悬停提示。
- 分隔线上的结果：已解决用 `--success` 文字，未解决用 `--warning`，其余部分维持现有金色。
- 浮层：宽 320px，`--surface-2-glass` + 毛玻璃，从按钮下方弹出，标签用药丸样式，选中态 `--brand-bg-soft`。

## 1.7 数据与接口

### 请求（向后兼容地扩展现有接口）

```
POST /api/agent/conversations/:id/context/reset
{
  "on_memory_failure": "proceed",          // 现有字段
  "outcome": "resolved" | "unresolved",    // 新增；缺省时等于「未评估」，保持旧客户端行为不变
  "outcome_reasons": ["missing_info"],     // 新增，可选；枚举见下
  "outcome_note": "……",                    // 新增，可选，≤500 字
  "follow_up": true                        // 新增，可选；保留为待跟进事项
}
```

原因枚举：`off_topic` 答非所问、`missing_info` 信息不够、`execution_failed` 执行失败、`wrong_result` 结果不对、`too_slow` 太慢、`other` 其他。

### 响应

现有 `ContextResetResult` 增加 `segment_id` 和 `outcome`。

### 新增读取与修改

```
GET   /api/agent/conversations/:id/segments            每段的起止消息、结果、原因、关联工作记录与产物
PATCH /api/agent/conversations/:id/segments/:segment_id  修改或撤销评估（outcome: null 表示撤销），带 revision 防并发
GET   /api/agent/usage/outcomes?employee_id=&window_start=&window_end=   解决率统计（供议题 3、7 使用）
```

### 记忆

重置时提交给 Manager 的记忆 `metadata` 增加 `outcome`、`outcome_reasons`、`segment_id`。这样员工以后能区分「成功经验」和「失败教训」，议题 4 的记忆列表也能按它筛选。

### 同步到企业侧（第二阶段）

段落评估汇总（员工 ID、结果、原因、时间，**不含对话内容**）随现有的用量发件箱（`/api/agent/usage/outbox`）上报 Manager，用于人才市场的全企业解决率。

## 1.8 验收标准

1. 单聊、群聊都能用两个按钮结束本段；分隔线显示结果和记忆状态。
2. 记忆保存失败的确认流程里，评估不丢。
3. 撤销后分隔线去掉结果标记，统计里该段变回未评估。
4. 旧版内嵌 Agent 不认识 `outcome` 字段时：按钮仍能重置，提示「当前版本暂不记录评估」，不能报错。
5. 窄窗口只显示图标，悬停提示完整。
6. 生成中、空段、员工不可用这三种禁用态都有明确提示。

## 1.9 待定事项
