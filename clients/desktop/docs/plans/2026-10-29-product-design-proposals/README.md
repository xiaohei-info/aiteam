## 议题之间的关联

几个议题共用同一份数据，建议一起定：

```
           ┌──────────── 1. 问题已解决 / 未解决 ────────────┐
           │  每段上下文一条「结果评估」记录                  │
           ▼                    ▼                            ▼
 3. 员工详情：解决率     7. 人才市场：解决率指标     8. 工作台：已解决 + 有文档 → 一键存为解决方案
                                                               │
 4. 员工记忆：重置时保存的记忆带上「已解决 / 未解决」标签 ◄──────┘

 3. 员工用量 ──┐
               ├── 共用「今日窗口」和用量卡片组件（同一套口径、同一套空态）
 5. 群聊用量 ──┘

 2. 权限 ── 6. 知识来源：「本机目录」在两处出现，命名和说明要一致
```

## 需要你拍板的决策点

每项的推荐方案写在前面，括号内是备选。

| # | 决策 | 推荐 |
|---|---|---|
| 1-a | 交互形态 | **A 分段双按钮**（B 回复结束后的提示条 / C 保留单按钮 + 弹窗选择） |
| 1-b | 「未解决」要不要填原因 | **可选**：原因标签 + 备注，可以直接跳过 |
| 1-c | 评估能否撤销 | **5 秒内可撤销评估**；上下文重置本身不可撤销 |
| 2-a | 是否合并 | **A：入口合并为一个「权限」按钮，内部仍是两个设置**（B 彻底合并：完全访问只在授权目录内生效 / C 不合并，只改文案） |
| 3-a | 时间范围 | **今日 / 近 7 天 / 全部** 三档切换 |
| 3-b | 费用币种 | **按服务端原样显示 USD**，不做汇率换算 |
| 4-a | 普通成员能看到什么 | **只看由自己对话产生的记忆**；企业管理员看全部并可编辑、删除 |
| 4-b | 入口形态 | **员工详情内的二级视图**（备选：独立的员工记忆页） |
| 5-a | 群聊用量来源 | **Agent 统计接口增加 `conversation_id` 过滤和按员工分组**（备选：前端翻页汇总工作记录，作为过渡） |
| 6-a | 知识来源怎么划分 | **A 按归属划分：企业知识库 / 个人知识库 / 本机目录**；部署位置（Manager 托管或企业内网 NAS）变成企业知识库的属性 |
| 6-b | 是否保留「团队」级 | **待定**：确认组织是否需要部门级知识库 |
| 7-a | 卡片指标 | **最多 3 项：招募数、解决率、计价**；没有数据的字段隐藏 |
| 8-a | 解决方案存在哪里 | **第一版存本机**（工作台本身也只读本机），第二版再同步到 Agent 或 Manager |
| 8-b | 标记时是否保存文件快照 | **文本类文件保存快照**（≤2 MB），Office/PDF 只记录路径和哈希 |
| 8-c | 命名 | 产品界面用「解决方案」，代码里用 `solution_record`，避免和现有的群聊编排方案 `SolutionProjection` 冲突 |
| 9-a | 坐姿怎么实现 | **A 沿用工位椅做法：用家具遮挡下半身表现坐下**（B 新增 Spine 坐姿动画，需要美术排期） |
| 9-b | 门的默认行为 | **自动门**：有人靠近时打开，开会和有人使用时关闭 |

## 排查中顺带发现的问题

这些不在 9 项范围内，但会影响方案落地：

1. 员工详情里「记忆摘要 → 查看详情」跳到 `/memory?employee=…`，但 `src/App.tsx` 里没有这个路由，会被兜底规则重定向到 `/chat`。点了等于没反应。议题 4 会修掉。
2. Manager 记忆列表（`GET /api/manager/memories`）和统计（`/analytics`）走 `management=True`，只有企业 owner 和企业管理员能读。普通成员当前读不到任何记忆条目。
3. 记忆按「租户 + 员工」存储，同一个员工被多个成员使用时，记忆是共享的。如果直接放开列表权限，成员 A 能看到成员 B 对话里沉淀的内容。这是议题 4 推荐「只看自己对话产生的记忆」的原因。
4. 本机用量统计接口只支持 `employee_id` 和时间窗过滤，口径是「当前成员 + 当前设备」，币种固定 USD。企业级账单接口（`/api/manager/billing/usage/*`）只对 owner 和财务管理员开放。
5. NAS 协议里每个知识库有 `level: private | team | enterprise`，和 Manager 的企业知识库重叠，这是议题 6 定义模糊的根源。
6. 办公室角色资源只有站立和走路两类动作（各 4 个方向）加表情，没有坐姿；门只有三张「已打开」贴图。编辑器素材里的 `07-closed-door.png` 是正视角，不能直接用于俯视地图。
7. 代码里已经有一个「方案」概念：群聊编排方案 `SolutionProjection`（`/api/agent/grants/solutions`）。工作台的「解决方案」如果也叫 solution，会和它冲突。
