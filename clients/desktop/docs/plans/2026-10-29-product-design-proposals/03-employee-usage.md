# 3. 员工详情增加用量展示

## 3.1 现状

| 项 | 现状 | 依据 |
|---|---|---|
| 员工详情 | 依次显示：身份、岗位描述、擅长技能、记忆摘要、模型和可操作系统、关联资源。**没有用量** | `src/components/Chat/AgentDetailPanel.tsx` |
| 预留字段 | 代码里有 `usage: employee.usage`，但注释写明「当前 ExpertProjection 未承诺时保持缺失」，没有渲染 | 同上 |
| 可用接口 | `GET /api/agent/usage/statistics?employee_id=&window_start=&window_end=` | `src/api/agent/observations.ts` |
| 接口口径 | `scope: member_local`：**当前成员 + 当前设备**；按 UTC 小时聚合；时间窗必须对齐 UTC 整点，否则 422；币种固定 USD | `observations.types.ts`、`TodayUsagePanel.tsx` |
| 返回字段 | 执行次数、成功/失败次数、输入/输出/缓存 Token、总 Token、耗时、费用（`cost_total` 可能为 null）、已知费用小计、定价状态 `known/partial/unknown`、未定价执行次数 | 同上 |
| 已有组件 | 办公室「今日消耗」面板（全员工）、`LocalUsage`（单员工全量） | `TodayUsagePanel.tsx`、`components/Work/LocalUsage.tsx` |

结论：**第一版只靠前端就能完成**。接口已支持按员工和时间窗过滤，「今日」窗口的计算逻辑在 `TodayUsagePanel` 里已经有了，抽到 `src/lib` 复用即可。

## 3.2 展示内容

在员工详情「身份」卡片下面新增一张「用量」卡片：

```
┌ 用量 ─────────────────────── [今日 | 近 7 天 | 全部] ┐
│  Token          费用              执行        成功率      │
│  128.4K         $0.42            23 次       91%          │
│  输入 96K · 输出 30K · 缓存 2.4K                          │
│  ▁▂▅▃▇▆█  近 7 天 Token 趋势（第二阶段）                  │
│  解决率 82%（17 段已评估）← 来自议题 1                     │
│  ⓘ 仅统计你在这台设备上的使用 · 按小时汇总                 │
└──────────────────────────────────────────────────────────┘
```

| 指标 | 来源字段 | 显示规则 |
|---|---|---|
| Token | `token_total` | ≥1000 用 K/M 缩写；悬停显示精确值和输入/输出/缓存拆分 |
| 费用 | `cost_total` | `pricing_status = known`：直接显示 `$0.42`；`partial`：显示「≥ $0.40」，下面小字「3 次执行未定价」；`unknown`：显示「—」并说明「模型未定价」 |
| 执行 | `execution_count` | 整数 |
| 成功率 | `succeeded_count / execution_count` | 执行为 0 时显示「—」 |
| 今日最后一次执行 | 工作记录第一条的 `ended_at` | 仅「今日」时显示，例如「最近 14:32」（可选） |
| 解决率 | 议题 1 的 `/usage/outcomes` | 已评估段 < 10 时显示「样本不足」 |

## 3.3 方案

### 方案 A（推荐）：详情卡片 + 三档时间切换

即上面的卡片。今日、近 7 天、全部各请求一次统计接口（切换时才请求，结果缓存 60 秒）。

### 方案 B：只显示今日 + 「查看更多」

卡片只显示今日四个数，点「查看更多」进入二级视图（与「自动化任务」二级视图同一形态），二级视图里有时间切换和按天趋势。

优点：详情面板更简洁。缺点：多一次点击，「近 7 天」这种常用信息被藏起来。

### 方案 C：企业口径（给管理员）

owner 和财务管理员额外显示一个「企业 / 我」切换，企业口径走 Manager 的 `/api/manager/billing/usage/records`，展示所有成员、所有设备的合计。

适合在 A 或 B 基础上叠加，作为第二阶段。

### 推荐

**A，第二阶段叠加 C 和趋势图。**

## 3.4 交互与状态

| 状态 | 显示 |
|---|---|
| 加载中 | 四个数字位置显示骨架条，不显示 0 |
| 没有使用记录 | 「今天还没有使用这位员工」，数字区隐藏 |
| 接口失败 | 「用量暂不可用 · 重试」，不影响其他卡片 |
| 旧版 Agent 不支持该接口 | 整张卡片隐藏 |
| 刷新 | 详情打开期间 60 秒轮询；本员工回复结束（`agent_settled`）时立即刷新一次，复用 `useOfficeMilestoneStore.usageVersion` |
| 跨天 | 每次刷新重新计算「今日」窗口，沿用 `todayUsageWindow()` 的处理 |

口径说明必须常驻显示一行小字，避免用户把它当成企业账单。

## 3.5 视觉规范

- 卡片沿用 `.adp-card`；时间切换用 3 段小型分段控件（高 22px，选中 `--brand-bg-soft` + 金色文字）。
- 四个数字：`font-number`、18px、`--text-gold`；标签 12px、`--text-muted`。
- 四列网格；面板宽度不足 320px 时变成 2×2。
- 趋势图（第二阶段）：7 根柱子，高 28px，`--brand` 透明度 0.35，今天的柱子不透明。

## 3.6 数据与接口

- 第一版：不改接口。新建 `src/lib/usageWindow.ts`，导出 `todayWindow()`、`lastDaysWindow(n)`，`TodayUsagePanel` 一起改用它。
- 新建 `src/components/Usage/UsageSummaryCard.tsx`，议题 5 的群聊用量复用同一组件。
- 第二阶段趋势图：统计接口加 `bucket=local_day&tz_offset_minutes=480`，返回按天数组；或者前端发 7 次请求（不推荐，7 倍请求量）。
- 时区注意：现在「今日」按本地午夜向下取整到 UTC 整点。中国（UTC+8）没有误差；UTC+5:30 这类非整点时区会多算半小时，属于已知局限，界面不显示。

## 3.7 验收标准

1. 三档切换的数字与 `LocalUsage` 在同一时间窗下一致。
2. 定价状态 partial 和 unknown 的显示符合 3.2。
3. 员工回复结束后 2 秒内数字刷新。
4. 无记录、失败、旧版 Agent 三种状态正确。

## 3.8 待定事项

- 费用是否需要换算人民币：推荐不换算，原样显示 USD；如果要换算，需要服务端提供汇率和换算时间，前端不自己定汇率。
