# 8. 工作台：有文档输出的对话 → 确认是否为解决方案

## 8.1 现状

| 项 | 现状 | 依据 |
|---|---|---|
| 展示内容 | 所有**生成过文档**的对话（Fred 会话产物 + Claude Code、Codex、TRAE、Qoder、WorkBuddy 等本机会话记录），每份文件只展示最终版本 | `docs/workbench-agent-solutions.md`、`src/pages/Workbench/` |
| 判定规则 | 只看文件类型和路径：md、txt、html、csv、svg、Office、PDF 等；排除代码、隐藏目录、说明类文件、像凭据的文件 | 同上 §2 |
| 已知问题 | 误报多：测试用 SVG、`/tmp` 下的提交说明草稿、`docs/todo.md` 更新都被算作「方案」 | 同上 §8 |
| 存储 | 只读，不保存任何用户标记 | — |
| 命名冲突 | 代码里已有「方案」：群聊编排方案 `SolutionProjection`（`/api/agent/grants/solutions`，存在 store 的 `groupSolutions`） | `src/api/agent/types.ts` |

问题：自动判定只能回答「有没有写文档」，回答不了「这是不是一个解决了问题的成果」。你提的做法是把判断交给用户：列出所有有文档的对话，用户确认哪些是解决方案。

## 8.2 概念

| 概念 | 定义 |
|---|---|
| 候选 | 有文档输出、但用户还没确认的对话。即现在工作台里的所有条目 |
| 解决方案 | 用户确认过的对话 + 选中的交付文件 + 一句话说明。确认后进入「解决方案」库 |
| 普通对话 | 用户点了「不是方案」的候选。从候选里移走，可以在「已忽略」里找回 |

产品界面用「解决方案」。代码和接口用 `solution_record`，避免和 `SolutionProjection` 混淆。

## 8.3 页面结构

工作台顶部增加三个标签：

```
[ 待确认 12 ]  [ 解决方案 34 ]  [ 已忽略 ]
```

### 待确认（默认标签）

保留现有的「左列表 + 右预览」布局。每张候选卡片底部增加两个按钮：

```
┌──────────────────────────────────────────────────────┐
│ 📄 Q4 渠道复盘方案                    Fred · 小策 · 今天 │
│ 2 份文件：复盘报告.md、渠道数据.csv                       │
│ 需求：帮我把 Q4 各渠道的投放数据复盘一下……               │
│                          [不是方案]   [✓ 设为解决方案]    │
└──────────────────────────────────────────────────────┘
```

- 「设为解决方案」打开一个小表单（见 8.4），确认后卡片从「待确认」移到「解决方案」，同时显示提示「已加入解决方案 · 撤销」。
- 「不是方案」直接移到「已忽略」，同样可以撤销。
- 列表顶部有批量操作：多选后「全部不是方案」，方便清理测试类误报。
- 不操作的候选一直留在「待确认」，按时间倒序；**超过 30 天未处理的自动折叠**到列表底部的「更早的候选」，不自动删除，也不自动判定。

### 解决方案

改成库视图（卡片网格），支持搜索、按员工 / 来源 / 标签筛选：

```
┌───────────────────────┐ ┌───────────────────────┐
│ Q4 渠道复盘方案          │ │ 采购审批流程梳理        │
│ 复盘各渠道 ROI，给出 Q1  │ │ ……                     │
│ 预算建议                 │ │                        │
│ #复盘 #渠道             │ │ #流程                  │
│ 小策 · 2 份文件 · 10/29  │ │ 小李 · 1 份文件 · 10/21 │
│ ✓ 对话中已标记为已解决    │ │                        │
└───────────────────────┘ └───────────────────────┘
```

点开后右侧预览，与现在的详情一样，多一个「编辑信息」和「移出解决方案」。

## 8.4 「设为解决方案」表单

```
设为解决方案
名称      [ Q4 渠道复盘方案              ]   ← 默认取对话标题
一句话说明 [ 复盘各渠道 ROI，给出 Q1 预算建议 ]   ← 可选；可点「让员工概括」自动填
交付文件  ☑ 复盘报告.md   ☑ 渠道数据.csv   ☐ 草稿.md   ← 默认全选
标签      [#复盘] [#渠道] [+]                       ← 可选，带历史标签联想
                                   [取消]  [加入解决方案]
```

## 8.5 与议题 1 的衔接（两个入口，一份数据）

| 入口 | 时机 | 行为 |
|---|---|---|
| 对话里点「问题已解决」 | 本段生成过文档 | 提示条里出现「存为解决方案」，点了直接打开 8.4 的表单，交付文件默认是本段生成的文件 |
| 工作台「设为解决方案」 | 任何时候 | 同一个表单 |

同一对话的同一组文件只能有一条解决方案记录。两个入口都能看到对方的结果：对话分隔线上显示「已存为解决方案」，工作台卡片上显示「对话中已标记为已解决」。

对于 Claude Code、Codex 等本机来源的会话，没有议题 1 的按钮，只能从工作台确认。

## 8.6 判定规则收紧（建议一起做）

用户确认机制能兜住误报，但候选太多会让人不想处理。建议先收紧两条（即 `workbench-agent-solutions.md` §9.2 的前两条）：

1. 排除 `/tmp`、`/private/tmp` 下的文件。
2. 只算在该轮最终回复中被提到的文件。

## 8.7 存储

### 第一版：存本机（推荐）

工作台本身只读本机数据（本机会话 + 本机 Agent），标记也存在本机应用数据目录 `workbench-solutions.json`：

```json
{
  "version": 1,
  "records": [{
    "record_id": "sr_…",
    "source": "fred",
    "session_id": "…",
    "file_ids": ["a1b2…"],
    "status": "solution",
    "title": "Q4 渠道复盘方案",
    "summary": "…",
    "tags": ["复盘"],
    "segment_id": "…",
    "snapshots": { "a1b2…": { "sha256": "…", "path": "snapshots/a1b2….md" } },
    "created_at": "…", "updated_at": "…"
  }]
}
```

`status`：`solution` 解决方案 / `dismissed` 已忽略。没有记录的就是待确认。

### 文件快照（需要决定）

确认后文件可能被继续修改或删除。推荐：
- 文本类文件（md、txt、html、csv、svg）≤ 2 MB 时，**确认时保存一份快照**，解决方案永远展示确认时的内容；如果原文件后来变了，显示「原文件已更新 · 查看最新版本」。
- Office、PDF 只记录路径和哈希；原文件变化或删除时提示，不保存副本（避免占用空间）。

### 第二版：同步

Fred 来源的解决方案写回本机 Agent（会话元数据），并可以「发布到企业知识库」（与议题 6 衔接），让同事也能看到。

## 8.8 视觉规范

- 标签栏沿用页面顶部的分段控件样式；数字用 `font-number`。
- 「设为解决方案」：金色描边按钮；「不是方案」：文字按钮，`--text-muted`。
- 解决方案卡片：`--glass-card-bg`，左上角 3px 金色竖条，表示「已确认」。
- 「对话中已标记为已解决」：12px，`--success`，前面一个 `CircleCheck` 图标。

## 8.9 验收标准

1. 三个标签的数量和列表一致；标记和撤销即时生效，重启后保留。
2. 同一对话从对话里和工作台两个入口确认，只会产生一条记录。
3. 原文件删除后，有快照的解决方案仍能预览；没有快照的提示文件已不存在。
4. 批量「不是方案」可以撤销。
